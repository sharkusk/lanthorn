## What is there now

`complete::room_words_from_text` (`crates/app/src/complete.rs:70`) pulls candidate
nouns out of transcript text with three hand-rolled English heuristics:

```rust
const STOP_WORDS: &[&str] = &["the","and","are","you","can","not","has","was", … ];  // ~40
for word in text.split(|c: char| !c.is_alphanumeric() && c != '\'') { … }
if lower.len() < 3 { continue }
```

It feeds **two** callers: `input::recompute_suggestions` (Tab completion ranking)
and `input::scraped_seen_nouns` (the command band's `here` fallback). A third
scraper, `inventory::parse_inventory_output` + `strip_article`, carries its own
article list for the carried fallback.

**The stop-word list is the tell.** It exists only because the tokeniser cannot
tell a real word from filler. Ask the story instead and the question dissolves:
`the` is not a word to suppress, it is simply a word this story's dictionary
does or does not hold — and if it holds it, the story genuinely knows it and we
were wrong to drop it.

## What is available now that was not when this was written

`zvm::dictionary` exposes `tokenise(&Memory, &[u8]) -> Vec<Token>` and
`lookup(&Memory, &str) -> u16` (0 = unknown). Feeding prose to `tokenise` is
**not an approximation** of the parser — it is the identical code path, so
separator characters, Z-encoding and the v1-3 six / v4+ nine character
truncation are handled exactly as the game will handle them. SQ-1041 proved this
route works and is cheap; SQ-1107 is built on the same insight.

So: no stop-word list, no bespoke splitter, no three-character floor. A token is
a candidate if the dictionary holds it, and that is the whole rule.

## Expected gains, beyond deleting code

- **Correct across engines and versions.** The 3-char floor silently drops `x`,
  `n`, `s`, `up`, `in` — real words in every story. A Scott game with 3-character
  dictionary words loses everything.
- **Truncation handled.** `lanter` in a v3 dictionary is currently invisible to a
  scraper matching whole prose words; SQ-1041 already showed this matters.
- **The stop list stops being wrong per story.** A game that implements `there`
  or `here` as real vocabulary is currently unreachable through completion.

## Scope, and what NOT to change

- **Leave the inventory tiering alone.** `command_band.rs:312` picks
  `session.introspect()` (object tree) when available and the scrape only
  otherwise, setting `here_is_seen` so the column labels itself "seen" rather
  than passing a scrape off as the room's contents. That design is honest and
  is not what this quest is about.
- Glulx and Scott have no `introspect()` object tree, so the scrape stays as a
  fallback for them — improve what it does, do not remove it.
- Small and separate: the "last 20 transcript lines, joined" block is
  copy-pasted verbatim in `input.rs` at both call sites. One helper.
