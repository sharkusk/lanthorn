## What works today, measured

Real launches of the shipped binary through the pty harness, a zip in each shape:

| zip holds | result |
|---|---|
| `zork1.z3` at the root | **plays** — r88/s840726 read from the header, parser takes `open mailbox` |
| `Zork I/zork1.z3` in a subdirectory | **plays** |
| `zork1.z3` + `readme.txt` + `cover.png` | **plays** — the non-story entries are ignored |
| `zork1.z3` + `beyondzork.z5` | **plays Zork I**, silently, with no way to ask for the other |
| `journey.z6` + `Journey.blb` | **refused**: `no .z3/.z5/.z8 entry found in zip` |

So the README's claim is true, and much narrower than it reads.

## Both limits are in one function

`crates/app/src/hints.rs:821-834`, the `ZIP_MAGIC` branch:

    let pred = |name: &str| {
        let lower = name.to_ascii_lowercase();
        lower.ends_with(".z3") || lower.ends_with(".z5") || lower.ends_with(".z8")
    };
    match read_zip_entry(path, pred)? {
        Some(bytes) => Ok((bytes, None)),

**One.** The predicate names three extensions. Not `.z4`, not `.z7`, and not
`.z6` — so the one format whose whole point is that it ships artwork is the one
format a zip cannot carry. Nor `.zblorb`/`.blorb`/`.gblorb`, nor `.ulx`, nor a
Scott Adams `.dat`, all of which lanthorn opens perfectly well as loose files.

**Two, and this is the one the title is about.** That `None` is the resource
handle. The disk-image branch twelve lines above returns `Some(image)` — the
thing every reader downstream uses to find pictures, sounds and hints beside the
story. The zip branch hardcodes `None`, so even a Blorb sitting in the same zip
is never opened. There is no "beside the story" inside an archive unless
something constructs one.

## What it should do

Treat a zip the way a disk image is already treated: it is a **volume**, not a
wrapper around one file. The disk path enumerates, picks or offers a choice, and
hands back an image resources resolve against; the zip path should reuse that
shape rather than grow a parallel one. That also gets `--story` working on a zip
for free — the four-shape table above shows a two-story zip silently taking the
first, which is exactly the defect SQ-1078 fixed for compilation discs.

Order that keeps each step falsifiable: widen the predicate (cheap, and makes v6
loadable), then give the zip a resource handle so a Blorb inside it is found,
then enumeration and `--story`.

## Do not let this quietly become a format

Pre-release, so no compatibility burden — but a zip is a *convenience for what
somebody downloaded*, not a lanthorn container. The `.lanthorn` archive is the
container and it is already a zip (`archive.rs`), so the two must stay clearly
apart: whatever this grows into must not start looking like a save file.
