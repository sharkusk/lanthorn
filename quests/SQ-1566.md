--- note 2026-09-25T05:00:18Z ---


**Why.** A host that composes v6 frames with `compose_v6_frame` and never calls
the terminal renderer gets the wrong default colours on the Amiga profile.
`V6FrameInputs::from_state` (`crates/app/src/render/screen.rs:2838`) calls
`v6_host_pair` (`screen.rs:2656`), whose top layer is `state.v6_page_pair`.
That cell is written only inside `render_story_pane_frame`
(`screen.rs:271-283`), from `ScreenModel::{fg,bg}`, on every terminal frame.
`v6_machine_page_rgba` (`screen.rs:2717`) and `v6_machine_page` read it the
same way. Without a terminal render, Journey under the Amiga profile (white on
medium grey, SQ-0740) composes in the host's pair instead.

**Change.** Extract the rule as
`pub fn v6_machine_pair(model: &ScreenModel, honor_game_colours: bool) -> Option<(u32, u32)>`
(Layered root, honoured, non-Default bg). `render_story_pane_frame` sets the
cell from it. Add a host entry point that needs no render cell, e.g.
`V6FrameInputs::for_model(state: &AppState, model: &ScreenModel, paint, prose) -> V6FrameInputs`
(or `v6_host_pair_with(state, pair: Option<(u32,u32)>)`), and keep `from_state`
for the TUI.

**Acceptance.**
- A unit test of `v6_machine_pair`: `None` for a Default bg, for declined colours
  and for a non-Layered root; `Some` otherwise.
- `v6_headless_compose` gains `Journey - The Quest Begins.adf` (release 30 /
  serial 890322, Amiga profile), with the inputs built from the model alone and
  no call into `render_story_pane`. The canvas matches the TUI's
  `build_v6_raster_canvas` pixel for pixel in both honour modes. Restore, then
  make a move, then assert (CLAUDE.md's rule that restore tests must perturb).
- Zork Zero r393 and Journey r83 are unchanged.
