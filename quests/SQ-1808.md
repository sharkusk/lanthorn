--- note 2026-10-23T16:39:57Z ---

Repro: Hitchhiker's Guide (Solid Gold, hitchhiker-invclues-r31-s871119.z5). Boot at 48 columns, play a turn, save the host state, restore/resume it in a session whose screen is 45 columns, enter one command. The upper window grows to 2 rows: row 1 ends with the score in col 45; row 2 col 1 holds one reverse-video space (cursor (2,2)). It stays for the rest of the session and goes into every later save. A fresh game at 45-48 never wraps, and a live narrowing (boot 48, shrink to 45) keeps the 48 floor and is fine.

Chain:
1. settle_width_floor (crates/app/src/session.rs:~2104-2132, SQ-1778) replays the turn at the narrow width and counts only set_cursor columns past $21 as overreach (crates/zvm/src/cpu/exec.rs:~3845-3849, upper_cursor_overreach). HHG's layout is fixed from its boot width: set_cursor(1,43) is legal at 45 but the following print runs one cell past the right edge. Verdict Adapts, the floor drops to 45, and the grid is refitted under a 48-column layout.
2. Window-1 printing wraps at the right edge (exec.rs:~6124-6129, print_text: if cursor_col >= cols { cursor_row += 1; cursor_col = 1 }), and the next write grow_rows the grid (exec.rs:~6119-6121). Frotz gives window 1 no wrapping attribute and drops characters past the right margin; the upper window does not scroll.
3. The SQ-1806 decode trim (crates/zvm/src/screen_snapshot.rs:~233-238 via last_painted_row, crates/zvm/src/screen.rs:~323) and split_window (exec.rs:~3416-3424) count that reverse-video space as paint, so the stray row survives restore and every re-split.

Asks:
1. v4/v5 window 1: a character past the last column is not drawn and the cursor stays at the right margin; never a new row, never a grown grid. Newline and set_cursor move rows as now.
2. In the SQ-1778 shadow turn, also count a window-1 print running past the right edge as overreach (a baked layout), so HHG keeps its saved width as the floor and shows its full status as a live narrowing does.
3. Tests with HHG r31 (or a synthetic story printing its status from a width saved at boot): boot wide, save, restore narrow, one command -> one row, no wrap, floor at the saved width.
4. Saves already on disk (players have them now): the decode trim recognises wrap residue -- rows below the split holding only whitespace, the snapshot's cursor on such a row just after a single leading painted cell -- and drops it, keeping quote boxes and menus whose rows below the split carry text.
The owner would like this in the v0.9.8 tag if possible (The Golden Lanthorn 0.7.0 is waiting on it).
