## A lead from SQ-1047's face reporting, before anyone re-derives it

`/dump-windows` now names the face, and the two presses disagree exactly where this defect does.

**Macintosh** (`dump-windows.log`, 2026-08-24T20:16:17Z) — the press that clips:

```
    body: 15x15px from MacOS_6.0.8_System_Startup.img · FONT 396 · fit Metric
    fixed: 7x15px from the release's own medium
    declared cell 7x15px · text scale 1x1 native px per face px
    pen: proportional 3–11px over printable ASCII · bold +0px (smear 0)
```

**Amiga** (same log, 20:37:04Z) — the press that does not:

```
    body: 8x8px from Kick12.rom · topaz/8 · fit Cell
    declared cell 8x16px · text scale 1x2 native px per face px
    pen: steps the cell — 8px for every character
```

So the clipping press has a **proportional** pen (3–11 px against a declared 7) and the clean one steps its cell exactly. That makes "font mismatch" unlikely and puts the first half of this report in the same family as **SQ-1051** (a raster prose row capped by CHARACTER count against a pixel-measured wrap) and **SQ-1050** (a wrap measured roman while the draw measured bold): a bound or a measure expressed in CELLS while the pen advances something else.

Where to look first — the hint menu does not take the ordinary prose path. Its topics are chrome runs packed onto the viewport (SQ-0892), and SQ-0937 already fixed one rounding defect in that packing on this exact press. `chrome_text_rects` and the ring's in-box packing were both written when every v6 pen WAS the declared cell.

**The two halves are probably not one bug.** The stuck reversed spaces reproduce on Arthur as well as Zork Zero, so that half is about a reverse-video run's ground outliving the attribute rather than about the pen — check where the menu's selection highlight is retired, and note SQ-1052 has just changed how a reversed run's block is resolved (per glyph now, not per run). Confirm this half against `machine-screenshots/` before assuming which behaviour is correct: a reversed space between words IS filled on the real machines in some bands, which is the whole of SQ-0504.

## Two defects, both reproduced, both fixed

Specimen for both: `stories/Zork Zero Disk.image`, **r296 / serial 881019**, Macintosh, raster, drawn with **Geneva 12** off the user's `MacOS_6.0.8_System_Startup.img` (advances **3–11 px** against a declared **7**). Route: taps to the first line prompt → `hint` → `y` → N `n` presses. The user's screenshot and `/dump-windows` 2026-08-24T20:39:35Z are the report.

### 1. Clipped mid-glyph — a spare rect measured in CELLS

`chrome_text_rects` names the pixels `fill_story_page_under_chrome_text` must **not** paint over. It measured each run as `chars * cell.w` while the glyph loop in `build_chrome_canvas` steps `advance_styled`. Where the face is wider than the cell, the page fill lands on the tail of the run and slices whichever glyph straddles the boundary.

Ink stopped at exactly `x + chars * 7` on every topic:

| topic | pen ends | ink stopped (before) | declared end | ink now |
|---|---|---|---|---|
| `GREAT HALL AREA` | 203 | 195 | 196 | 201 |
| `EAST WING` | 159 | 153 | 154 | 157 |
| `BAILEY/VILLAGE AREA` | 230 | 223 | 224 | 228 |
| `AS A LAST RESORT` | 425 | 419 | 420 | 423 |
| `FOR YOUR AMUSEMENT` | 443 | 433 | 434 | 441 |

Not a font mismatch — the same family as SQ-1050 and SQ-1051.

`buffer_line_rects` had the identical split and is fixed with it. Its own doc comment already named the hazard — *"whose caller must spare exactly the pixels the draw claims; measuring them twice is how Shogun's menu got erased once already"* — and the two were being measured twice, in two different units. Both now take the `TextFace` rather than a bare `V6Cell`, which is CLAUDE.md's "facts that must be considered together travel as a value".

### 2. Stuck reversed blocks — a space that could not clear a blank

`zvm::screen::paint_run` lets a SPACE with inherited colours pass over whatever is beneath it, because it deposits no pixels and a text-run model cannot overstrike. Right for Shogun, which pads its status fields with spaces reaching a neighbouring label. Wrong when the thing beneath is a cell whose only content IS a background.

The menu highlights a topic in reverse video — `GREAT HALL AREA` plus a trailing reversed space — and deselects it by re-printing the same characters in normal video. The letters overwrote their own cells; the two INTER-WORD spaces did not. Measured after two `n` presses:

```
y=106 x=132 st=1 " "     <- the deselected row's leftovers
y=106 x=167 st=1 " "
y=121 x=92  st=1 "EAST WING"   <- the live selection
y=121 x=160 st=1 " "
```

The rule added: a transparent segment erases only the BLANK cells under it. A letter cannot be overstruck by a space and that approximation stays; a blank has no letter to preserve, and two spaces cannot both own one pixel span, so the later one wins. **This separates the two frames with no threshold** — Shogun's neighbours are letters, Zork Zero's leftovers are not.

The covered-glyph arithmetic is now one function (`covered_glyphs`) shared by `trim_run_against_rect` and the new erase, rather than a second hand-maintained copy.

### Verification

* `zvm::screen::tests::a_printed_space_clears_a_blank_cell_but_not_a_letter` — both halves in one case: the reversed blank goes, the letter stays. Falsified by dropping the new arm.
* `render::v6_layout::tests::a_chrome_runs_spare_rect_is_the_pens_span_not_the_declared_one` — falsified at 105 (declared) against 130 (pen).

Both are unit cases with a synthetic pen, deliberately: the press that reports this draws with Geneva, which ships with the MACHINE and with no game (SQ-1036), so a case resolving the real cascade would answer out of whatever the person running it keeps in `~/.lanthorn/` — the trap SQ-1052's first case fell into.

### Found and NOT fixed — a third defect, same root

`native_extent` measures a grid run's reach as `(x - 1) + n * font_w`, the declared cell again. On this frame `"Hit Return to see hints."` at x=491 measures 168 declared against **145** by the pen, so the canvas comes out **658x400 instead of 640x400** — 18 px of dead space that then drives the letterbox scale and every band crop. Left alone because it changes canvas geometry globally and many suites pin `(640, 400)`; it wants its own quest and its own gate.
