--- note 2026-09-25T05:00:21Z ---


**Why.** A host that renders v6 text with its own font machinery (for example by
turning the bitmaps into an outline font) needs the pixels the raster path would
draw. Those are decided by a chain inside `render::bitfont::blit_glyph_styled`
(`render/bitfont.rs:446-680`): release or system face, `misc7x14` for a 7-wide
cell, Uni-VGA, the 8×8 masters, synthesized bold and italic, the emphasis rule
on machines that underline (SQ-1028), and the tiling source columns (SQ-1027).
A caller can blit into a scratch canvas today, but has to choose the cell width
itself and cannot enumerate what the chain can draw (the glyph tables in
`vga16.rs`, `misc7x14.rs` and `bitfont.rs` are private statics).

**Change.**
`TextFace::glyph_image(&self, ch: char, style: u8) -> Option<GlyphImage { advance: u32, height: u32, width: u32, bits: Vec<u8> /* 1 bit per px, MSB-left, row-major */ }>`,
implemented by calling `blit_glyph_styled` so there is one copy. Add
`TextFace::repertoire(&self) -> Vec<char>` (the face's codes ∪ `misc7x14` ∪
`vga16` ∪ the 8×8 extras).

**Acceptance.**
- For each face (Arthur Amiga `char.data`, Mac `FONT 524` 7×15 with and without
  a synthetic system face, topaz 8×8 at scale 1×2 via a fixture,
  `TextFace::cell_only` at 8×16 and 7×15) and all 8 style combinations,
  stamping `glyph_image` at pen positions reproduces `blit_glyph_styled`'s
  canvas for a sample string with box drawing, pixel for pixel.
- `advance == advance_styled(ch, style)`.
- `repertoire` contains every char for which `glyph_image` is `Some`, and
  nothing else.
