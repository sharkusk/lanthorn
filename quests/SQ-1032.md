## Design settled by discussion (user, 2026-08-27)

**The mode is: hybrid's behaviour, with the game's own bitmap face instead of terminal
glyphs.** Everything is pixels — so text is drawn in the release's own typeface
(topaz, Geneva, the medium's face, via `native_font::TextFace` / `V6FaceSpace`) — but
the FRAME extends vertically the way hybrid's border already does, instead of
letterboxing a fixed-aspect image.

### The payoff that is not in the title

An extending mode lets the magnification be pinned to a WHOLE number and spends the
surplus pane on CONTENT rather than on magnification. That sidesteps fractional
scaling entirely — which SQ-1099 established has no artifact-free answer — and gets
the bitmap face at 1:1 or 2x where it is sharpest. Today a tall pane forces a choice
between letterboxing and a fractional scale; this removes the choice.

### Where the extra rows come from: NOT from telling the game

`v6_screen_px` is passed only at construction and no resize path updates it —
`session.rs` is explicit: *"Ignored for v6, whose screen is the native pixel frame
seeded from `v6_screen_px`, never the host cell pane."* So hybrid does not give a game
more rows either, and there is no existing behaviour to port for that.

Telling the game a taller screen WAS considered and is **not** the design. It would
fabricate a screen no machine ever had (the SQ-0901 trap, and `machine-screenshots/`
goes blind exactly there), and it would likely be per-title: Zork Zero and Arthur
compute border positions and might follow, while Journey's fixed menu panels and
Shogun's full-screen compositions probably would not.

### The extra region holds lanthorn's OWN scrollback, and that machinery exists

`render/v6_layout.rs:1149` — lanthorn already rasterises the app's scrollback into a
v6 raster frame in the game's face. SQ-0695 shipped it; it was then gated by
`plate_free_box` after the first version painted the previous screen's prose across
Arthur's intro plate.

**The extended region is the EASY case for that code.** Today `plate_free_box` must
DISCOVER whether a gap is genuinely free, which is the half that went wrong. In an
extended frame the region is one lanthorn created — the game never drew a pixel there
— so "is this free?" is answered by construction rather than measured.

Consequences: no fabricated screen size, no game-behaviour risk, no probe needed, and
**no per-title breakage** — Journey and Shogun keep their native layout exactly and
simply gain a taller border with scrollback beneath it.

### The `[MORE]` pager follows for free

Initially thought to be a limit this design could not fix. It is not. The pager is
**lanthorn's** (`crates/app/src/pager.rs`) and it pages when *added rows > viewport*,
where the viewport is the prose area the RENDERER reports (`screen.rs:368`,
`viewport_rows: area.height`). The only game-side input is the §8.8.3.2.6 veto — a
line count of -999, "never print [MORE]", Zork Zero's demonstration mode — which is an
on/off, not a row count.

The user's argument is the decisive one: *"otherwise hybrid mode wouldn't work
properly either"* — if the pager counted against the game's window, hybrid would page
constantly while showing a full-pane transcript. It does not, so it cannot.

So enlarging the prose viewport reduces paging automatically. **Both wants — see more
at once, and be interrupted less — fall out of the same change**, with no pager work
at all.

### Open, for whoever builds it

- Where the created region sits relative to the game's own window, and whether the
  extended flanks run beside it (the SQ-1094/SQ-1097 machinery is now trustworthy for
  this).
- Whether the region is sized to whole text rows of the face, so the type lands on its
  own grid rather than being letterboxed within the region.
- What happens on a title whose art already reaches the pane bottom — presumably no
  region and today's behaviour, but say so rather than letting it fall out.
