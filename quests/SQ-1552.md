Citations crates/app/src/, as of af51457d.

1. Structured assists. `AppState::push_assist` (state.rs:5334) stores assist lines as text only. A host that makes the offered words clickable must parse them back out: match `vocab::LEAD_VETTED` / `LEAD_DICTIONARY` and `assist::preamble`, then find the unknown word by repeating the `knows` check (vocab.rs:1597) with a whitespace split because `vocab::words_of` (vocab.rs:1181) is private. Keep the text as it is, and also attach structured data to the transcript line (or return it from the offer path): the kind (intro / vocabulary offer / vetted offer / caution / other), the unknown word, the offered words, and for each offered word the command with the unknown word replaced (what a click should put in the input). Make `words_of` pub, or expose the tokenisation the offer uses.
2. Per-game quick words. `[command_panel] quick` is global config. A host that lets the player edit quick words per story has nowhere to keep them: `PerGameConfig::write` (styles.rs) rewrites only the keys it knows, so an added key is lost on the next write. Add a per-game `quick` override (read by `resolve`/`command_band` the same way the global one is) that `PerGameConfig::write` preserves; the TUI can keep editing the global list.

Acceptance
- TUI unchanged; existing suites pass.
- Tests: a rejected command yields an assist line carrying the structured offer (vetted and dictionary cases, the fill command correct); a per-game quick list round-trips through PerGameConfig::write alongside other per-game keys and takes effect in the band data for that game only.
