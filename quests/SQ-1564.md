Current code (rev c68d48cf):
- crates/app/src/session.rs:4731 `strip_read_prompt` removes the prompt only when a `>` stands alone on its line; the unit test `strip_prompt_does_not_remove_gt_mid_line` (~l.9400) keeps inline prompts on purpose — right for the default inline-prompt mode, where the typed command joins the game's `>` line.
- In command-bar mode (`command_bar: true`) the input lives in a separate bar, the host echoes `> cmd` as its own transcript line, and a game's inline prompt stays behind: a doubled prompt. Found at startup across ~120 stories: Bureaucracy (`>>` alone on its line — a run of `>`, which the lone-`>` rule misses), Beyond Zork (`[Please type YES or NO.] >`), Bronze (`…before? >`), Border Zone (`…(R)estore? >`), Counterfeit Monkey (`Can you hear me? >>`), Fairest / What Heart Heard (`…game?>`), Nameless (`…Q>>`). The TUI in command-bar mode shows the same.

Change (command-bar mode only; inline mode unchanged):
- Also strip a line that is only a run of `>` (`>>`, `>>>`), and
- a trailing `>`/`>>` (with optional preceding space) that ends the output immediately before a line read — leaving the rest of that line's text (`…(R)estore?`).
- Never strip `>` elsewhere (mid-line, or output not followed by a read).

Acceptance:
- Unit tests for each shape above in command-bar mode, and the existing inline-mode tests unchanged.
- An integration check that Bureaucracy's and Border Zone's opening output in command-bar mode ends without a `>`.
