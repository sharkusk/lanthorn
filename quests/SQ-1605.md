  A host laying out Glk windows from the engine's window tree can't place a proportional split's leftover cell, so it hands it to the wrong child

--- note 2026-09-26T19:14:58Z ---

gvm's layout_window (crates/gvm/src/glk.rs) rounds each child of a proportional split down on its own, and the cell left over belongs to neither child: split_rect places it between them. engine::Split (and so WinNode::Pair) reports only fixed, the first child's cells. A host that lays the tree out itself therefore gives the rest, slack included, to the second child, so that child's graphics canvas is drawn one cell larger than the game drew it. Kerkerkruip's centre-column rules (windows 39, 43, 45) come out 60 cells drawn over 61, and its right edge (window 9) 1 cell over 2. Wanted: carry the second child's own size too (e.g. rest: u16, so slack = extent - fixed - border - rest, placed as split_rect does), or give each leaf its Rect.
