## Why this is the one worth building

Infocom's "walking dead" states — the game continues for hours after becoming
unwinnable — exist **because the hardware of the day could not check**. You cannot
fork a 1980s Z-machine. We can, cheaply, and we already do: host Save States are
engine-neutral snapshots and `session.rs` can run a second silent session.

That makes this the clearest case of spending 2026 compute on something period
hardware structurally could not do, rather than on decoration.

## The mechanism already exists, filed for another purpose

**SQ-0785** — "re-land the return probe: snapshot the live game into a silent
second session after each move to discover the way back" — is exactly this
machinery, currently aimed at automapping. Generalising it:

1. snapshot after each move
2. in a forked, silent session, try to get BACK — the inverse direction, or a
   short search
3. if nothing returns, the move was irreversible

Build the two on one probe rather than two. Two forked-session probes would be the
parallel-path shape CLAUDE.md's refactoring policy warns about, and the automap
half is already specified.

## Keep the warning COARSE, and opt-in

    lanthorn: that looked irreversible.

and nothing more. Not *why*, not *you needed the lamp*, not *you can no longer
win*. The moment it explains, it is a walkthrough. A coarse flag lets a player
decide to rewind; a specific one decides the puzzle for them.

Off by default. Some players want the 1982 experience exactly as it was, and a
game that warns you is a different game.

## Honest limits — state them rather than overselling

* **Irreversible is not the same as unwinnable.** Plenty of one-way moves are
  fine, and some fatal mistakes are perfectly reversible in the movement graph
  (smashing an object, using up a limited resource). This detects a
  ONE-WAY-ROOM-TRANSITION, which is a proxy and will both miss and false-positive.
  Say so in the UI wording, or it will be trusted past what it can support.
* **Cost.** A probe per move, per candidate direction. Measure it —
  `examples/scroll_bench` (SQ-1033) is the precedent for building the instrument
  before claiming a cost — and put the work off the main thread, which is the
  standing direction: only the story interpreter belongs there.
* **Determinism.** A forked session must not consume the RNG the live one will
  use, or the probe changes the game it is probing. `random_seed` is already
  threaded through `GameSession::new_for_machine`; make sure the fork is sealed.

Related: SQ-0785 (the probe), and the persistence rules in CLAUDE.md — a snapshot
carries the recipe, not the result.

## Landed as a READING of SQ-0785's search, not a second probe (Lane C, wave 5)

Commit `6c8d27b1`, branch `worktree-agent-a4654c111323c6094`. The quest's own
instruction settled the shape: "one probe, not two — whichever of the two is
implemented first owns the seam, the second consumes it." SQ-0785 landed first,
so this consumes it. Net new probes: **zero**. A `ReturnSearch` that walks its
whole candidate list without reaching the origin has already established the
thing; `return_probe::one_way_caution` reads that and says one line.

### The three design questions, answered

**1. When it probes — AFTER the crossing, not before, and that is a decision.**

Warning *before* needs one of two things and neither is affordable:

* **Hold the player's command** while the worker walks the move plus twelve ways
  back. Measured through `examples/return_probe_cost` (debug, 12 candidates —
  which is exactly the case that produces a caution):

  | story | worker, 12 candidates | main thread (one snapshot) |
  |---|---|---|
  | Zork I r88 | **8.9 ms** (0.74 ms/cmd) | 1.1 ms |
  | Coloratura | **54.6 ms** (4.6 ms/cmd) | 6.9 ms |
  | Counterfeit Monkey 11 | **4.2 s** (352 ms/cmd) | 105 ms |

  4.2 s between Enter and the game's reply is not a stutter, it is a hang; and
  even Zork I's 8.9 ms is main-thread time bought for an optional feature, which
  is the precise thing SQ-1124 removed from this seam.
* **Scout ahead** — probe every exit of every room speculatively so the verdict
  is cached by the time the player types. Twelve searches per room for exits
  they will mostly never take, monopolising a shadow that `vocab` and the return
  search both share. Rejected on cost, and it would be the second fork path the
  quest forbids.

What is shipped costs nothing and still lands in time: `arm_return_search`
abandons the search the moment the player moves, so the caution either arrives
while they are **still standing in the room** or is never spoken. On Zork I the
whole twelve-candidate walk is ~9 ms — under the room description, in the same
beat. (`zork1_calls_the_trap_door…` reports 20 commands / 20.7 ms of worker time
for the *entire eleven-turn walk*, the Cellar's twelve included.)

**2. Threshold — three legs, and the third is the one that matters.**

1. the search armed at all (a real crossing, on a passage the map holds, no way
   back already known — SQ-0785's existing gate);
2. it ran its whole candidate list without landing on the origin;
3. **and the shadow got OUT of the room at least once** (`ReturnSearch::left`,
   set in `deliver` when a landing is `Some` and not `here`).

Leg 3 is the anti-wolf clause. Without it, "nothing led back" is
indistinguishable from "nothing led anywhere", which is what a **dark room**, a
locked cell, a cutscene, a story that ended and an unreadable location all look
like from here — and the caution would fire on every one of them. Falsified:
stubbing the guard out fails `a_shadow_that_never_got_out_of_the_room_says_nothing`.

**False positives it still has, and the wording absorbs them.** A way back that
needs a door opened, a key, a turn to pass, or two moves instead of one is
invisible to a one-step search. So the line states the test rather than its
implication:

    looks one-way — no direction leads back to Living Room

Twelve directions, one step, from here. Not "you cannot win", not "there is no
way back", not what to do about it. `looks` is the hedge; naming the origin is
what makes it checkable by the player. It also **cannot nag**: exhausting the
list marks all twelve on `Room::probed`, so the next arrival has an empty
candidate list, arms no search, and the line is said once per room, ever.

**3. Cost — zero marginal.** The twelve commands are typed for the map either
way; this is the map work saying what it found. The table above is the cost of
the *search*, which SQ-0785 already pays, on the worker.

### Surface

Per SQ-1125: inline in the transcript, through `AppState::push_assist`, so it
takes the `guidance` switch, `AssistTone::Caution`'s style, the once-per-session
introduction and `export-transcript`'s `Lanthorn: ` marker. No new config key —
it needs `return_probe` on (inherits its off-by-default) **and** `guidance` on.
`Assist::caution` had no production caller before this; it does now.

### Tests

Four unit cases in `return_probe.rs` (the line and its register; the third leg's
silence; the guidance switch silencing the line and not the map work; an unnamed
origin dropping the clause rather than trailing `back to `), and two real-game
cases in `tests/suites/return_probe.rs`:

* `zork1_calls_the_trap_door_one_way_and_names_the_room_it_shut_behind` —
  `zork1-r88-s840726.z3`, eleven turns in, the canonical Infocom one-way. The
  lamp is taken and lit first *deliberately*: the Cellar is dark, and a dark room
  is exactly the false positive leg 3 refuses (it would also grue-roll the shadow
  at random). Asserts the exact line, that the ten reversible moves before it
  were silent, and that the map took no invented edge.
* `a_crossing_with_a_way_back_says_nothing` — the cries-wolf assertion, on the
  ordinary case.

Both falsified by stubbing the guard and the `push_assist` respectively.

### Not done, and worth knowing

The verdict is not durable, so a *later* traversal of the same passage is not
cautioned before it happens. Making it so means a field on `mapper::graph::Room`
(persisted) or a session-lived set in `AppState` plus a pre-submit check in
`turn.rs` — genuinely "before the consequence", ~10 lines, and it only ever helps
a player crossing a passage they have already been warned about once. Left out as
speculative; this is the natural extension if the caution reads well.

`Confirm:` rather than `Completes:` because whether the line reads right, and
whether it fires at the right moments in real play, is the user's eye to settle.

## USER JUDGEMENT AND TWO REQUIREMENTS, 2026-08-30 — after the feature shipped

The user's objection to what landed: **"i don't see the point of this feature since
it is too late to do anything about it. i think our undo levels is a better feature
in general."**

That is a fair hit on the shipped design, and the design did not answer it: a
caution that arrives AFTER the crossing tells you something you cannot act on
merely by hearing it. `undo_levels` (default 16, `0` disables — `config.rs:1551`,
applied at `startup.rs:1445`) already lets a player back out of anything.

The counter-argument, which is why the feature is not simply wrong: **undo only
helps a player who NOTICES.** The caution's value is the noticing, and it arrives
while the player is still standing in the room, when `undo` is one word away. The
noticing and the escape are different problems.

Presented with revert / point-at-undo / keep-as-is, the user chose none and gave two
requirements instead:

> "if undo is disabled, this feature should also be automatically disabled. this
> also need a global setting to turn on/off."

## Requirement 1 — suppress the caution when undo is off

**When `undo_levels == 0`, the caution must not fire.** This turns the user's
objection into a rule, and it is the right rule: a warning is worth saying only if
the player can act on it, and with undo disabled there is nothing to do about a
one-way passage but read about it.

`0` is the documented off value, so the test is exact. Note it must read the LIVE
value, not a boot snapshot — SQ-1161 has just made Save apply settings at runtime,
and `undo_levels` is one of the three rows that can only land at boot, so check what
the running session actually has rather than what `config.toml` says.

## Requirement 2 — its own global setting

It currently has NO key of its own: it inherits `return_probe` (off by default) and
`guidance` (on). The user wants a dedicated global on/off.

That setting must obey the contract SQ-1161 just established, because it is a
settings-screen row like any other:

- a GLOBAL config key, written to the global `config.toml`;
- a value row in the settings screen — no actions;
- applied on Save at runtime if it can be (this one can — it is read per crossing);
- NOT a per-game sidecar key.

So the caution ends up with three gates and that is fine, but state the order and
the reason in the code: its own key (the player's wish), `guidance` (it is an
assist), `return_probe` (it is mechanically a reading of that search and cannot run
without it), plus the new undo suppression. Default the new key ON — a player who
has deliberately enabled the probe has opted into this class of help already, and
the key exists so they can decline this one line without losing the map work.

## Not chosen

Reverting, and adding "undo if you did not mean it" to the line. The wording may
still want that clause, but it is a separate question from the two requirements and
was not asked for.
