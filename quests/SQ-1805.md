  Found on Android 13 (Retroid Flip 2) in The Golden Lanthorn: downloading a game's document failed with 'could not save file: Function not implemented (os error 38)'. documents.rs:520 lock_dir() calls File::lock() (flock) on <dir>/.import.lock; Android's shared storage (/storage/emulated/0/..., a FUSE mount by MediaProvider) doesn't implement flock and returns ENOSYS, so every document import/index write fails there; only the empty .import.lock is left. Suggested: when lock() fails with Unsupported/ENOSYS/EOPNOTSUPP, carry on unlocked (or use an O_CREAT|O_EXCL lock file with stale handling), so embedding hosts on storage without advisory locks still work; a test with an injected lock failure. Same check for any future File::lock use.
