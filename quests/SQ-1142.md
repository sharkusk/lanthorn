--- note 2026-08-30T21:39:45Z ---

DECIDED by the user, 2026-08-30: **"unbind them and leave as / commands"**.

So the fix is a deletion, not a remapping. The three default bindings go:

    keymap.rs:300  bind!(plain(F(2)), "open-command-band", Context::Global);
    keymap.rs:311  bind!(plain(F(3)), "resize-panes",      Context::Global);
    keymap.rs:322  bind!(plain(F(4)), "reveal-words",      Context::Global);

Those are the ONLY default F-key bindings — the title's "F1-F10" overstated it.
`keymap.rs` continues to PARSE `"f1"`..`"f12"` as key specs, and that stays: a
player who wants an F-key binding may still write one in their own config. What
lanthorn stops doing is claiming them out of the box.

The three commands remain reachable exactly as before through `slash::COMMANDS` —
`open-command-band`, `resize-panes`, `reveal-words` — so nothing is lost from the
registry, only from the default keymap.

WHY, and it is worth keeping: a v4+ story may declare a terminating-characters
table at header `$2E`, and Infocom's V6 titles use it — Arthur lists F1-F6, so
pressing F2 for its map is a read the STORY handles. A host that intercepts the key
is eating input the game explicitly asked for. Rejected alternatives, for the
record: (a) let the story win only while it is READING, keying off `$2E` — the
highest-fidelity answer and the most machinery, and it makes the same keystroke mean
different things in different stories; (b) rebind the three commands to other keys —
keeps a default shortcut but spends three more keys on it.

CONSEQUENCE TO ACCEPT DELIBERATELY: three commands lose their only default key, and
discoverability has bitten this project before (see [[SQ-1125]]'s notes — a feature
the user could not see was reasonably read as broken). The mitigations that already
exist are the command palette and SQ-1123's clickable pane-border controls. Whoever
takes this should CHECK whether the command band in particular still has a
discoverable route in after F2 goes, and say so — if it does not, that is worth
raising before shipping the unbind rather than after.

The three `bind!` lines at `keymap.rs:300/311/322` are gone, replaced by a comment

Tests: `keymap::tests::f3_enters_resize_mode_by_default` is replaced by
`no_function_key_carries_a_default_binding`, which walks F1-F12 across all four
`Context` variants plus the real `key_to_command` path, so the next person reaching
for a "free" F-key finds none; `f_key_specs_still_parse_so_a_player_can_bind_one_by_hand`
pins the parser half. `input::tests::f2_opens_the_command_band_by_default` is inverted
to `f2_no_longer_opens_the_command_band_by_default` and also asserts
`primary_key("open-command-band") == None`.

ANSWER TO THE DISCOVERABILITY QUESTION — **yes, the command band keeps a visible
route in, and it is a good one.** `render::controls::controls_for` pushes
`BorderControl::VerbPanel` UNCONDITIONALLY into the story pane's border (it is not
config-gated and not hidden in either state); its glyph is `≡`/`band_show`, a click
runs `open-command-band`, and hovering it shows a tooltip. That is a permanently
visible on-screen affordance, which is more than SQ-1125's failure mode had. Behind
it the band also keeps the leader panel's `v` under "Map · View" and the `/` palette.
`resize-panes` keeps the mouse boundary drag plus the palette; `reveal-words` keeps
its own `◈` border control. So the unbind costs a default shortcut, not a route.

ONE CONSEQUENCE I COULD NOT FIX HERE — the border controls' HINTS now name keys that
do not exist. `crates/app/src/render/controls.rs` line ~281 gives the verb-panel
control the hint line `"F2"`, and line ~311 gives the reveal `"F4 · /reveal-words"`.
Both are false as of this commit. That file is Lane B's territory in this wave (the
map pane's border controls), so I did not touch it — it needs a one-line fix in each
hint (`"/open-command-band"`, and `"/reveal-words"` without the `F4 · ` prefix).
Note the existing `border_controls` suite CANNOT catch this: its assertion is
`text.contains("/reveal-words")`, which the stale `"F4 · /reveal-words"` still
satisfies, and the verb panel's hint is not checked for a command at all.

Docs/README stop naming the keys: `interface.md` (resize mode, the reveal control,
the command band's own bullet, the band's Esc/toggle paragraph),
`customization.md` (the reveal), `v6-graphics.md` (the reveal), and README's
"coming next release" line, which now points at the `◈` control. The README caveat
itself is left standing — removing it is a release task.
