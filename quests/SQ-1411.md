INVESTIGATION (lane, no code changed; reproduced headlessly on the .adf)

CAUSE — lanthorn's own [more] pager, not the game and not the VM.
The story is NOT re-running: the restored machine sits at the read_char on the
rebus picture (pc=0x20224, pending_read_pc=Some(131616)) vs pc=0xec52 at the `>`
prompt one turn earlier. What replays is the app's SCROLLBACK VIEW: the pager
parks the view at the TOP of the restored transcript and pages down through the
whole thing.

The chain:
1. startup.rs:1713 (auto_load, default true) installs the archive's transcript.
   `state.last_transcript_total_rows` is still 0 (state.rs:3663) — nothing seeds it.
2. The first frame drawn is Zork Zero's FULL-SCREEN picture, so
   render_story_pane reports `transcript_surface=false, total_rows=0`
   (render/screen.rs:389), and pager::apply_frame (pager.rs:262) returns early by
   design (SQ-0578) — the baseline stays 0.
3. The key that dismisses the splash finishes a turn; turn.rs:947-951 arms with
   `baseline_before(last_transcript_total_rows=0)` → arm(0).
4. The next frame has a real transcript surface with the WHOLE backlog, so
   activation_target(0, N, viewport, prompt) engages and parks at the top.

320x200, art_scale (2,2)). Turns: the archive's 11 command_history lines

WHY THE CONTROLS ARE CLEAN
- `>`-prompt save: the first frame HAS a transcript surface, so apply_frame
  calibrates last_transcript_total_rows before the player acts.
- in-game @restore off a bare .qzl: engine_helpers::restore_from_file returns
  DescriptorCompleted(None) and NEVER calls apply_archive_state — state.transcript
  is untouched, the baseline stays live.
So the discriminator is not read_char vs read; it is "the frame the resume lands
on is a v6 full-screen picture takeover".

SAME DEFECT, other sites (stale rather than zero baseline, so milder):
engine_helpers::apply_archive_state (engine_helpers.rs:290-297),
turn::apply_launch_resume (turn.rs:790-796), and the rewind/replay rebuild
(main.rs:4383-4389).

PROPOSED FIX (smallest, at the real cause)
`reset_transcript_sidecars` (state.rs:5585) already documents itself as "the one
place that invalidation lives, because it is already called at every site that
replaces the transcript" — the pager baseline is exactly such a sidecar.
1. `Pager { baseline_stale: bool }` (derive(Default) → false = valid).
2. `reset_transcript_sidecars` sets `baseline_stale = true` and disarms.
3. `pager::apply_frame`, on the first frame with `transcript_surface == true`
   while stale: drop the arm, clear `active`, clamp scroll, set
   `last_transcript_total_rows = total_rows`, clear the flag — CALIBRATE instead
   of measuring. Consistent with startup.rs:2076-2082, which already skips the
   opening-banner arm for a resumed transcript.
Simulated in the probe: splash save → pager.active=false, scroll=0, baseline
calibrated to 400; control unchanged.
