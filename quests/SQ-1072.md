## Measured against the machine's own capture

`machine-screenshots/mac-shogun-hintshown.png` — Macintosh Shogun r292/890314,
the InvisiClues clue page — against lanthorn on the same fixture and turn:

```
machine    6> You have to do everything you can to keep your ship from sinking before you
           get to Japan.

lanthorn   6> You have to do everything you can to keep your ship from sinking
           before you get to Japan.
```

**One word early, and the pen is not the reason.** Calibrating the capture (the
frame spans image x 7..646 = 640 px at 1:1, so `native = image − 7`), its first
line is **486 native px for 78 characters**; lanthorn's is 419 px for 67. Both
are **~6.25 px per character**, so the Geneva advance table agrees with the
machine to better than a pixel per glyph.

What ends the line early is the **COLUMN** measure. `screen::wrap_text` breaks at
whichever of the pixel and column limits fills first — SQ-1009 made that
deliberate, so a run's grid cell and its pixel origin agree character for
character — and `cpu::exec` sets them as

```rust
let (limit_px, limit_cols) = if wrapping {
    (u32::from(cols) * u32::from(fw), u32::from(cols))
} else { … };
```

with `cols = w.grid.cols`, itself `x_size / cell.w` from `window_size`. For this
window that is `500 / 7 = 71`. A 6.25-px pen fits about **80** characters in 500
px, so the column limit binds **nine characters before** the pixel limit does, and
the line is short by a word.

SQ-1009's own doc predicted the opposite: *"a line ends at whichever limit is
reached first, which on a proportional face is nearly always the pixel one — so
hybrid wraps where the machine wrapped, and its lines are honestly shorter than
the window rather than filled to a column count the game never used."* On this
press it is nearly always the COLUMN one, because the declared cell (7) is WIDER
than the pen's mean advance (6.25). The Amiga is immune — its pen steps the cell
exactly, so the two measures are the same number.

## Pre-existing, and wider than the frame that revealed it

Not introduced by SQ-1071. A window with attribute 0 set wrapped before that
change and wraps after it, through the same two limits — so **every wrapping
window on the Macintosh press has this**, including ordinary gameplay prose in
window 0. SQ-1071 only made it visible, by making the clue window wrap at all.

## The design question, which is why this is its own quest

The column measure exists so a CELL backend has a grid cell per run (SQ-1009). If
the pixel limit alone governs, a proportional line fits more characters than
`x_size / cell.w`, and `Grid::put` silently drops anything past `grid.cols` —
`idx` returns `None`. So the fix is not simply `limit_cols = u32::MAX`; it has to
answer what the grid does with a line the declared column count cannot hold.

Two candidates, neither yet measured:

1. **Size the grid by the PEN, not the cell.** `grid.cols` becomes what actually
   fits — for a proportional pen, more than `x_size / cell.w`. Keeps one break
   list and one grid cell per glyph; changes what `grid.cols` means on one machine.
2. **Let the pixel limit govern and grow the grid on demand**, the way rows
   already grow (`w.grid.grow_rows` under the newline handler). Smaller blast
   radius, but leaves `grid.cols` disagreeing with the row it holds.

Whichever is chosen, the falsifier is in hand: the Macintosh capture above must
break after `you`, and `v6_hint_clue_wrap::mac_clue_wraps_inside_its_window`
(which today asserts only the RULE, and says in its doc why) should be tightened
to the capture's exact break the way the Amiga case already is.

## Watch for

`v6_shogun_declared_columns` and anything else pinning a column count on the
Macintosh press; SQ-1009's own cases in `zvm`; and the app-side dump line
`usable 500px = 71 cols`, which states the same number.

## Fixed in the same effort as SQ-1071, because it stopped being optional

Filed as "one word short in a hint", which understated it. The moment SQ-1071
gave Macintosh windows a wrap regime, the column limit started binding on frames
that matter: **Arthur's Macintosh status ribbon lost the `e` of `Compline`** —
`v6_arthur_status::mac_arthur_raster_score_bar_is_one_ribbon_not_the_location_alone`
went red on `" Churchyard … St Anne's Day, Complin   e "`. So it is fixed here.

## The fix

`limit_cols` is only a limit on a FIXED pen:

```rust
let (limit_px, limit_cols) = if wrapping {
    (
        u32::from(cols_now) * u32::from(fw),
        if metric.is_proportional() { u32::MAX } else { u32::from(cols_now) },
    )
} else { (u32::MAX, u32::MAX) };
```

The machine has only pixels. The column count is OUR bookkeeping — the grid cell
a run carries, SQ-1009 — so the grid grows to hold the line rather than the line
shrinking to fit the grid: `UpperWindow::grow_cols`, the column counterpart of
`grow_rows`, called beside it in the print path. Row-major, so it re-lays through
`resize_preserving` instead of appending in place.

**Every fixed-pen machine is byte-identical**: their column limit is unchanged,
and it stops the line at exactly `cols_now`, so `grow_cols` never fires. The two
proportional presses are the whole blast radius — the Macintosh, and Arthur's
Amiga floppy, whose pen is WIDER than its declared cell (~9.4 against 8) so the
pixel limit already bound first there and nothing moves.

## Verified against the capture

`machine-screenshots/mac-shogun-hintshown.png`, and now exact:

```
6> You have to do everything you can to keep your ship from sinking before you
get to Japan.
5>
```

The machine's first line measures native 72..557; lanthorn now draws 71..559.
`v6_hint_clue_wrap::mac_clue_wraps_where_the_machine_wrapped` pins the frame run
for run — it was written asserting only the RULE, with a note saying why, and
that note is now the record of what this quest was.

## Note on the sibling defect this uncovered

While chasing it, the gate also caught **`grid.cols` going stale against
`x_size`** on Arthur's Amiga hint menu — `grid.cols` is only rewritten by
`window_size` (EXT:0x11), and a game that moves property 3 through
`put_wind_prop` leaves it behind. That is fixed alongside, in SQ-1071: the wrap
limit now comes from `x_size / cell.w` rather than from `grid.cols`, so the same
field bounds the wrap and the clip.
