--- note 2026-09-25T02:02:21Z ---

Current code (rev c68d48cf):
- crates/mapper/src/route/mod.rs `select_shared_paths` (~l.70-128, SQ-0225/SQ-0522): when a room pair is joined by both a compass passage and an Up/Down (or other portal) passage, the compass one is the pair's single drawn connector and the portal direction is folded into that connector's `secondary_exit` / `secondary_entry` (~l.1471-1486).
- crates/app/src/export_svg.rs `render_svg_body` (~l.1565-1620, SQ-1368) draws that folded direction as a "U"/"D" badge on the surviving connector's end — so the SVG export shows the passage.
- But `layer_layout` (SQ-1540, ~l.1194-1345) and `LayoutConnector` (~l.1099-1136: origin, dest, points, exit_dir, entry_dir, reciprocal, distorted, weight, is_portal, exit_kind, entry_kind, merge) have no field for it: `layer_layout` reads `secondary_exit`/`secondary_entry` only to suppress a redundant portal marker (~l.1251-1262). A host rendering from `layer_layout` therefore has no trace of the passage at all.
- Real occurrences in Zork I's fully explored map: Rocky Ledge↔Canyon View, Atlantis Room↔Cave, several Maze rooms (8 in total).

Change: add to `LayoutConnector` the folded directions per end, e.g. `pub secondary_exit: Vec<Direction>` and `pub secondary_entry: Vec<Direction>` (with their `PortalKind`s if the badge rendering needs them), filled from the routed connector, plus — if the SVG badge placement is computed in render_svg_body — the badge anchor point(s), so a host can draw the same badge in the same place without redoing the geometry.

Acceptance:
- Test: a two-room map with A north→B and A up→B (and B down→A): `layer_layout` yields one connector whose secondary directions include Up at A's end and Down at B's end; the portal marker suppression is unchanged.
- Test: a Zork I pregenerated map (`mapgen::generate`) where Rocky Ledge↔Canyon View carries its Up/Down in the layout data.
- SVG export output unchanged.
