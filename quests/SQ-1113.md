## The gap

SQ-1041's `vocab::stems()` handles regular endings — `opening` → `open`,
`lighting` → `light`. English irregulars are unreachable by any suffix rule:

| typed | wanted |
|---|---|
| `lit` | `light` |
| `took` | `take` |
| `went` | `go` |
| `caught` | `catch` |
| `broke` | `break` |

The lane did the right thing rather than papering over it: a test asserts
`stems("lit")` is **empty**, so the limitation is pinned rather than hidden
behind a rule that half-works.

## Why it matters more than it looks

A player who types `lit lamp` is not making a typo — they are speaking English.
The one-keystroke near-miss rule cannot help (`lit` to `light` is two edits and
the rule stops at one, deliberately, because distance two is what turns `marcus`
into `march`). So this is a silent miss with no fallback.

## The fix, and where it belongs

An irregular verb table — a few hundred pairs, closed-class and stable since
Middle English, so it does not rot. Map inflection to lemma, consult it when
`stems()` returns nothing.

**Do this alongside or after [[SQ-1110]]**, not before. That quest is already
establishing lemma handling (its table is lemmas-only and its consumer must
lemmatize before lookup), and it is acquiring a licensed lexical source that may
carry the irregular forms already — WordNet ships an exception list
(`verb.exc`) that is exactly this data. Building a hand-written table here first
would duplicate it and then have to be reconciled.

So the shape is likely: SQ-1110 extracts the exception list as a by-product of
work it is doing anyway, and this quest wires it into `vocab::stems()`.

## Do not widen the near-miss distance instead

Raising the edit-distance threshold to two would catch `lit` and would also
catch a great deal of nonsense — SQ-1041 chose one keystroke deliberately and
its silence cases depend on it. Fix the morphology, not the tolerance.
