--- note 2026-08-27T06:22:58Z ---

Reported by the user while the 0.3 --help wrapping work was still fresh: "we are still not consistent. some help items wrap on their own (~83 cols), while other wrap at the end of the terminal line. we need to be consistent."

Two wrapping authorities are in play and the output shows both. ~83 columns is a hardcoded or clap-default width being applied to some entries; the terminal edge is the emulator wrapping a line nothing measured. Either is defensible on its own — the defect is that one --help shows both, so the right column is ragged in a way that reads as a rendering fault rather than a layout choice.

Likely lands on the same surface as SQ-1082 (the one-flag-surface rework), which rewrites every flag's help text across app, zvm-cli, gvm-cli and scott-cli. Worth doing WITH that quest rather than before it — otherwise the wrap fix is applied to text that is about to be replaced. Note the four front-ends do not share a help renderer: `app` is clap derive, `zvm-cli` uses the `cli_host::args` scanner, so "consistent" has to mean consistent across two mechanisms, not one setting.

Decide the authority deliberately: a fixed width (and which), or the terminal's, or the terminal's clamped to a maximum. A hard 80/83 is friendlier to narrow terminals and to piping into a pager; the terminal's own width is friendlier on wide screens. Whichever, it must be the same answer for every entry in every front-end.
