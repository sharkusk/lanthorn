  The CLIs' screen-reader rules treat a one-row grid as status chrome and taller grids as content; a v6 Layered screen (Zork Zero's two-row Moves/Score band, its hint menu drawn as graphics/text, Arthur, Shogun, Journey) fits neither, so an embedding host has no rule for what a listener should hear or for finding the score.

--- note 2026-10-11T06:29:46Z ---

Design settled with user 2026-10-11: (1) classify v6 Layered windows by a generic rule (short top window repainted each turn = chrome) with per-RELEASE overrides for the Infocom v6 titles (Zork Zero, Shogun, Arthur; keyed by release, not title). (2) Menus: Zork Zero's hint menu through cli_host MenuBlock if its text has the marker column; Journey (parserless, permanent command columns) DEFERRED to its own quest. (3) Score: read the game's own score variable, verified per release from the routine that paints its status band, surfaced via Engine::score(); parsing the band text only as a fallback for an unknown v6 release. (4) API: renderer-neutral screen_reader::regions(screen, profile) -> Vec<Region{role: Chrome|Content|Menu, rect, text}>, same pattern as typed_input_colours; PositionedWindow gains its v6 window number. Scope: embedding hosts (the TUI is not switched over in this quest).
