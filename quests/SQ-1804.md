  A non-terminal embedding host builds the lanthorn library for Android (aarch64-linux-android, NDK); two terminal-only kitty shared-memory graphics paths stop it compiling: crates/app/Cargo.toml:128 ratatui-image 12.0.0-rc.0 uses rustix::shm (src/picker.rs:621, src/protocol/kitty.rs:16-18,276), which rustix 0.38 lacks on Android (rc.3 too); and crates/app/src/render/graphics.rs:3883 kitty_shm_write is cfg(all(unix, not(target_os = "linux"))), so it includes Android, and calls libc::shm_open/shm_unlink (3893, 3919), which libc lacks for Android. Leave the kitty shm path out on Android (or put it and ratatui-image behind a terminal feature); ideally CI runs cargo check --target aarch64-linux-android with the NDK.
