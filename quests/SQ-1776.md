  An empty ~/.lanthorn (only an empty saves/ folder, created by something unknown) appeared on a Mac whose real settings live in ~/.config/lanthorn; because legacy wins whenever ~/.lanthorn exists (user_dirs.rs rule 2), every setting silently looked lost until the empty folder was removed.

--- note 2026-10-12T16:22:18Z ---

Proposal: (1) UserDirs::resolve treats ~/.lanthorn as legacy only when it holds real content (config.toml, style.toml, saves with files, users/), so an empty or near-empty folder no longer hides the platform-default config; (2) when both locations hold real content, don't pick silently: the TUI asks once at startup which set to use (showing each path and its config.toml's modified time), remembers the answer, and offers to move/merge the other; (3) expose the detection (e.g. a UserDirs::conflict() -> Option<(legacy, platform)>, or a resolve result that says both are present) so an embedding host can ask its own way instead of re-implementing the check. Repro: settings in ~/.config/lanthorn/config.toml, then mkdir -p ~/.lanthorn/saves and launch: all settings appear reset.
