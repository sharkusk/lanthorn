--- note 2026-10-12T16:22:18Z ---

Proposal: (1) UserDirs::resolve treats ~/.lanthorn as legacy only when it holds real content (config.toml, style.toml, saves with files, users/), so an empty or near-empty folder no longer hides the platform-default config; (2) when both locations hold real content, don't pick silently: the TUI asks once at startup which set to use (showing each path and its config.toml's modified time), remembers the answer, and offers to move/merge the other; (3) expose the detection (e.g. a UserDirs::conflict() -> Option<(legacy, platform)>, or a resolve result that says both are present) so an embedding host can ask its own way instead of re-implementing the check. Repro: settings in ~/.config/lanthorn/config.toml, then mkdir -p ~/.lanthorn/saves and launch: all settings appear reset.

--- note 2026-10-12T16:27:00Z ---

Settled design (user 2026-10-12): (1) ~/.lanthorn counts as legacy only with real content (config.toml, style.toml, saves holding files, users/). (2) When both locations hold real content: plain-terminal prompt BEFORE the TUI starts (style of --migrate-user-dir), showing both paths, each config.toml mtime and save count; user picks one; then offer to rename the other set to <name>.unused-YYYY-MM-DD (each platform dir separately, same suffix; never delete). Declining the rename: use the pick this launch, ask again next launch. Non-interactive (stdin/stdout not a tty): never block — use platform default + one-line warning naming both paths. (3) Expose detection (e.g. UserDirs::conflict()) for embedding hosts. Also: find what creates an empty ~/.lanthorn/saves. Finishing trailer: Confirm.
