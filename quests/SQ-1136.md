## What actually runs, and what does not

Read out of the turn path; **not yet measured**, and the magnitude wants numbers
before anyone claims it matters.

**A turn that does not change the graph already costs nothing.** `should_bg_tidy`
returns early on `!changed`, and its comment says why: `overlap` is a STATE
predicate, true whenever the layout currently has any overlap, so without that
gate a persistent overlap re-triggered a tidy every turn and the map border pulsed
on a bare `look`. So `look`, `examine`, inventory and refused moves are free
today.

**A turn that adds a room or an edge runs all of this, and none of it consults
`show_map`** — `grep show_map crates/app/src/turn.rs` returns nothing:

| work | thread |
|---|---|
| `mark_distorted` — whole-graph connection pass, inside `observe_inner` (`mapper.rs:141`) and `record_probed_passage` (`mapper.rs:198`) | **main** |
| `occupied_cells_in_layer` + `rooms_in_layer` + a full connection scan for `distorted`, in `schedule_map_maintenance` | **main** |
| `mapper.graph.clone()` — the whole graph | **main** |
| the tidy job: full relayout or overlap cleanup | background |

This became marginally more frequent on 2026-08-29: SQ-0785 now records an edge
for a probe landing in ANY room already on the map, so edges arrive on turns where
the player did not move.

## The decision (user, 2026-08-29)

> "I think a delay seeing the map when opening the map panel is preferred to
> overhead incurred with each turn. There are many people who do not want or like
> the auto map, but may want the other features, so I think this is worth the
> optimization."

The assist set is meant to stand on its own. A player who never opens the map
should not pay for it on every move.

## What must NOT be deferred

**Observation.** Rooms and edges keep being recorded with the pane closed — that
is SQ-0785's standing decision, and the reason is that hiding a view must not
degrade the data behind it, or the player opens the map later and finds gaps they
can never account for. Only LAYOUT is deferrable, because coordinates exist to be
drawn.

`mark_distorted` counts as layout, not observation: it reads room positions and
marks connections against them.

## Key the deferral on a CONSUMER, not on the pane

The obvious implementation — recompute when the pane opens — is wrong, because
layout has more consumers than the pane: `export_dot`, click-to-route, room info,
and the map dump commands all read coordinates. A pane-open trigger leaves each of
those reading stale or unplaced rooms, which is a fresh class of bug rather than
an optimisation.

**Lazy-on-demand** — a dirty flag, and the first consumer to ask for coordinates
pays — covers the pane and every other reader with one rule. That is the design to
build.

## Three things to settle while building it

1. **The archive.** A session played with the map hidden and saved without ever
   opening it would archive rooms whose placement was never computed. Either the
   archive tolerates unplaced rooms and the restore places them lazily too, or the
   save forces a settle first. The former is consistent with "persist the recipe,
   not the result"; the latter is simpler. Decide deliberately rather than
   discovering it.
2. **The delay wants a progress indication.** `replay_build_and_placement` already
   threads `progress: Option<&Arc<AtomicUsize>>`, and a tidy progress bar exists —
   reuse it rather than blocking the UI silently on a large graph.
3. **Measure first, and measure the right thing.** The main-thread cost is the
   clone plus the scans, and both scale with graph size, so a ten-room map proves
   nothing. Take numbers from a long session — a deep Zork I, or Counterfeit
   Monkey — with the pane hidden, and report cost per graph-changing turn against
   room count. If the number turns out to be negligible at realistic sizes, say so
   and close this; the decision above is about a cost whose size is still unknown.

Related: the standing direction that only the story interpreter runs on the main
thread and all map work moves off it — a full graph clone per move is exactly the
shape that direction exists to remove.
