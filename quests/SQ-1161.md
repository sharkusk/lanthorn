## The `font_check` row, raised by the user — and it needs a distinction the quest title does not yet draw

User: "we have a `font_check` setting with only run... as the option. not sure what's going on with that one."

MEASURED: `crates/app/src/render/config_screen.rs:54`. It is `ConfigRowKind::Action`
— **the only one of the 32 rows** — added deliberately under SQ-1104, and the enum
variant's own doc explains it fully: "A row that DOES something rather than holding
a value. Enter runs it; ← / → do nothing, because there is nothing to cycle. Its
value column says what the key does instead of what the setting is, and its effect
lands outside the working copy the Save button writes — which the row's own
description has to say, or Cancel looks like it would undo it."

So "only run… as the option" is the Action row kind showing through, not a defect.

**IT ALSO PASSES THIS QUEST'S STATED RULE.** The rule as filed is "anything in the
settings screen should be GLOBAL, not per-game", and the font check is global — its
answers land in `style.toml`, which is global, and the row says so.

**But it fails a DIFFERENT rule the quest's other half implies**, and this is the
distinction worth settling before anyone edits rows: "remove settings that have UI
buttons". `font_check` is not a setting at all, and it is reachable two other ways
already — the `/run-font-check` slash command, and `--font-check on` at launch. So
by the duplication half of the rule it is a candidate for removal; by the
global-vs-per-game half it is fine.

## What this quest actually needs decided first

Two rules were filed as one sentence and they select different rows:

1. **No PER-GAME settings in the settings screen** — they belong in the per-game
   sidecar and on the pane borders. This is the rule as titled.
2. **No DUPLICATES of things reachable from a border control or a slash command** —
   which is a different set, and is what catches `font_check`.

Rule 2 is much broader and needs care: nearly every setting is reachable from
`/`-commands by construction, since `slash::COMMANDS` is the one registry and the
border controls dispatch through it. Applied literally it would empty the screen.
So rule 2 probably means "has a BORDER CONTROL" rather than "has any slash
command" — worth confirming with the user rather than inferring, because the two
readings differ by roughly the whole screen.

`font_check` sits exactly on that seam: no border control, but two other routes.

## Recommendation to weigh, not a decision

Keep `font_check`. It is the one row whose action a player cannot discover any
other way at the moment they need it — a first-run player who does not know
`/run-font-check` exists is precisely who the row is for, and SQ-1104 put it there
for that reason. If it goes, check first that a first-run player still meets the
font check some other way; the dialog already offers itself on a first run when
there is no `config.toml`, so the row may genuinely be redundant — but that is a
measurement, not an assumption.
