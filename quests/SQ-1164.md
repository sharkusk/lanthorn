## A — `zork0-mac-tall` becomes EXTENDED mode (user, restated 2026-08-31)

The user asked for this during SQ-1152's planning — "let's update the long mac b/w
to use raster extended to show off that capability" — and it was never done. That
lane built the tall Shogun, left `zork0-mac-tall` alone, and wrote manifest prose
framing the two as complements ("hybrid extends the border, extended grows the
frame"). The request stood; it was simply not carried out. The user has now restated
it: **"let's make the zork0-mac-tall raster-extended since we aren't showing that
anywhere."**

Note what makes it worth having beside `shogun-amiga-extended` rather than
duplicating it: the Macintosh declares a **7x15** Version 6 cell where every other
machine is 8x16, and draws its text at one native pixel per face pixel. So Mac
extended and Amiga extended fill their surplus rows differently. Two extended shots
earn their places only if the caption says which fact each one shows.

**Three things change together, and none can be left behind:**

1. `v6_render = "extended"` on the entry (the key SQ-1152 introduced, so a typo is
   an error rather than a silent fall-through to hybrid).
2. **The caption is now false and must be rewritten.** Every word of it is about
   hybrid: "hybrid mode fills the difference by extending the border out of its own
   artwork", "The pillars are the tell: the Macintosh's monochrome plates band
   theirs with a ring, and a taller pane gets more rings at the same spacing". None
   of that describes extended, which grows the FRAME and spends the surplus on the
   game's own bitmap face.
3. **`expect_art_cells = 1200` must be recalibrated.** Its own comment says the
   number is "the extension itself, not the artwork", measured against hybrid's
   flank tiling — 1731 art cells measured, guard at 1200. Extended produces a
   different cell count entirely. Re-measure and re-justify the floor the way
   SQ-1152 did for Shogun (extended frame 3280 cells against an unextended
   letterbox's 2000, floor set at 2400 so the guard is the extension).

## B — every Journey shot halts before the game says anything

All FIVE — `journey-blorb`, `journey-amiga`, `journey-wide`, `journey-huge`,
`journey-halfblocks` — share one recipe:

    keys = "wait:2500,n,wait:1500,cr,wait:1500,cr,wait:1500,cr,wait:1800"

`n` and three blank returns. The captured frame is Journey's OPENING MENU — the
illustration on the left, an empty text pane on the right, and *Start · Background ·
Change Name · Help · Game* along the bottom. The narration begins only once **Start**
is selected, and the recipe never selects it.

This is CLAUDE.md's documented trap word for word: "Real-game harnesses drive blank
lines and single keys, which reaches an intro card and often nothing else." Compare
`zork0-blorb`, which types `look` and shows a page of prose.

**Journey is MENU-DRIVEN, so `text:look` is not the answer** — it has no typed
parser prompt in the ordinary sense. The recipe has to drive its menus to Start and
into play. Work out the sequence against the real game rather than guessing, and put
the turn count in the entry the way the convention requires.

**Every one of the five needs it**, not just the three the user noticed — the other
two are the same frame at a different size and backend.

**And give the shots a non-vacuity guard on PROSE.** `expect` currently names things
visible on the menu screen, so it passes on the empty frame. A shot whose subject is
the story pane should fail when the story pane is empty; that guard is what would
have caught this instead of a human eye on a proof sheet.

## Done on branch `agent-ae0f307766b8e784f` (commit 5d82b67b, `Confirm: SQ-1164`)

### A — `zork0-mac-tall` is extended

`v6_render = "extended"`, caption rewritten (every sentence of the old one was
about hybrid's border extension), and `expect_art_cells` re-measured the way
SQ-1152 did Shogun's: **3300 cells** in extended (60x55, the whole pane content)
against **1140** for a frame that letterboxed 480x300 at the same 2x (60x19).
Floor set at **2400**, between the two.

**A fourth thing had to move: `size`, 92x58 -> 62x58.** `RasterFrame::extended`
takes `v6_upscale_cap`, which is `MAX_V6_UPSCALE = 2` on any backend that ships
pixels (a PNG-encode budget, `graphics.rs`). So a 480-wide press can never be
wider than 960 device px = 60 cells, and at 92 columns the composite came out 60
cells wide with thirty columns of empty pane beside it. `(62-2)*16 / 480` is
exactly 2 — the same arithmetic that puts Shogun's row at 82. Verified by
capture, not by argument.

`expect` had to change too: raster puts the whole screen in one image, so there
is no text to search but the pane title, and 62 columns clip the header at
`Zork Zero Disk.ima` — so it names the GAME (`Zork Zero: The Revenge of
Megaboz`) rather than a string whose truth depends on where a title bar elides.

**And the opening `cr` became `esc`.** A blank line typed at Zork Zero's parser
answers `[I beg your pardon?]`, which the small hybrid panes elsewhere scroll
away and an extended pane keeps on screen for the whole transcript. It was in
the middle of the first extended capture.

The two extended shots' captions now each name their fact: the Macintosh
declares a **7x15** cell and draws text at one native pixel per face pixel
(thirty-eight 15-pixel rows of surplus), the Amiga 8x16 with a release face in
the picture space (sixteen 16-pixel rows). The manifest's section headers were
rewritten to match — the old ones framed mac-tall as "the HYBRID answer" and
shogun as "the RASTER answer", which is now false.

### B — the five Journey shots

Worked out against the real game with `pty_capture`, one keypress at a time.
Journey's opening is five keys and each does something different:

    n    answers the GAME's "Do you want to restore a saved game?"
    cr   dismisses the full-screen title splash
    cr   turns the credits card
    cr   turns the "It was a Golden Age" prologue -> lands on the OPENING MENU,
         Start · Background · Change Name · Help · Game, story pane still empty
    cr   takes Start (the item the menu opens on) and the game narrates

The fifth is the one all five shots never had. New recipe on all five:
`wait:2500,n,wait:1500,cr,wait:1500,cr,wait:1500,cr,wait:1500,cr,wait:2000`.
The frame they now reach is the party at Lavos in front of the provisioner, with
the in-play command menu (Proceed · Enter, the four characters, Get Advice ·
Cast · Examine · Drop · Inventory) under the prose — exactly what
`journey-blorb`'s caption has always claimed.

### The guard

New manifest key **`expect_prose_cells`**: the least number of cells INSIDE the
story pane (rows `1..=ROWS-3`, cols `1..=COLS-2`) carrying an alphanumeric the
game wrote, skipping any cell under a kitty placement. Inside the pane is the
whole point — lanthorn's header and help bar are ~100 letters that are there
whatever the game did, so a screen-wide count cannot fail.

Measured ladder on `journey-blorb` at 82x28: **menu 59**, title splash 170,
intro card 350, **in play 517** (Amiga r30 wraps to 524). Floor **400** on all
five, which fails all three non-subjects.

**Falsified**: restoring the old recipe against the new manifest fails with
`writes 59 letter(s) into the story pane, wanted at least 400 — the frame
reached a menu or a card and the game has not narrated yet`.

Refused where it could only ever read zero, the same refusal `expect_art_cells`
gets on half-blocks: `raster`/`extended` (one image, no text cells), a `show_map`
shot (the pane is a ratatui percentage split this file does not restate), and a
`library` shot (no story opened). Two new cases in `gallery_manifest.rs` —
`a_prose_floor_is_refused_where_it_could_only_read_zero` and
`every_journey_shot_guards_its_prose` (keyed on the MEDIUM, not on shot ids, so
curating a Journey row out later does not fail it).
