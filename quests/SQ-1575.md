Current code (rev 5a31a353):
- Boot arms the opening: crates/app/src/host/boot.rs:1559-1563 — `if startup_transcript.is_none() && pager::should_arm(session.pending_input(), pager::more_suppressed(..)) { state.pager.arm(pager::opening_baseline(&state)) }` (SQ-1434's first-prose-row baseline).
- Reset doesn't: crates/app/src/host/reset.rs `reset_game` (l.38) clears the transcript fields by hand (~l.373-380), sets `transcript_scroll = 0`, and never touches `state.pager` — it neither arms nor calls `reset_transcript_sidecars` (state.rs:~5853, which sets `baseline_stale`). Callers add no arm: main.rs:2673 (ResetConfirm), main.rs:2688 (GameOverPlayAgain), slash_dispatch.rs:451 (`/reset-game map|data`). So after Reset / Play again the view sits at the bottom of the new banner: a long opening (Zork Zero r393's prologue) scrolls past unread, unlike a fresh launch of the same story.

Change: at the end of `reset_game` (after the new banner is in the transcript), arm the opening exactly as boot does — same `should_arm` guard, `state.pager.arm(opening_baseline(&state))` — ideally via one shared helper used by both boot and reset so the two can't drift. Make sure no stale `last_transcript_total_rows` from the old game leaks into the new baseline (reset it, or mark the baseline for recalibration consistently with boot).

Acceptance:
- Test: Zork Zero r393 — boot, play a move, `reset_game` → the pager is armed at the new banner's opening baseline, and the first frame after reset stops at the same row a fresh boot of the same story stops at (same pane).
- A story whose banner fits the pane does not pause after reset (same as boot).
- TUI: Reset / Play again on Zork Zero now shows [more] at the prologue.
