  crates/blorb/src/iso9660.rs walk() (~315-349) only bounds depth (MAX_DEPTH=8). A directory whose subdirectory records point back at its own extent makes the walk ~N^9 calls and entries: a 48 KB image with N=6 took 2.8 s and produced 2,015,539 entries; ~50 such records fit one block, so a single image in a library hangs the library index and grows memory until the process dies. Add a visited-extent set like prodos.rs (~403) and a per-mount record/entry cap. Any host that scans libraries or loads downloaded stories is affected.
