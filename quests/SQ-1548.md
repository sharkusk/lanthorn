Citations crates/app/src/, as of 5560bc25.

Current state
- `loop_tick::poll_shadow_answers` (loop_tick.rs:542, bin-only) routes answers from the shared shadow `state.probe` to their owners: `vocab::owns` / `deliver_answer` / `poll_vocabulary_offer` (vetted offer -> `push_assist` "try instead — …", vocab.rs:1742), `return_probe::owns` / `deliver` / `pump_return_search` (map edges), `random_exit_probe::owns` / `deliver`. The host arms the probes each turn (host/turn.rs:366-404) but nothing in the lib ever collects the answers.
- Consequence for a non-terminal host: with `guidance_probe` on (the default) a vocabulary offer is parked in `vocab_pending` and never delivered; return-probe and random-exit discoveries never land in the Mapper. The host silently diverges from the TUI.

Change
- Move the routing into the host (e.g. `host::probe::poll(&mut AppState, &mut dyn Engine, &mut Mapper, now)` returning whether anything changed), called by the TUI's loop exactly where it calls `poll_shadow_answers` today, and callable by any host on its own tick. Include whatever deadline the probes need in `host::clock::next_deadline` if they are time-driven, so a host that sleeps until the next deadline wakes for them.

Acceptance
- TUI behaviour unchanged; existing suites pass.
- Headless tests (skip when a story is absent): a mistyped word whose offer needs the probe yields the vetted `try instead` Assist line through the host alone; a walk that the TUI's return-probe tests already cover adds the same map edge through the host alone.
