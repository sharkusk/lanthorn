## The idea

Let a player drop an **Amiga Workbench floppy** or a **Mac OS boot disk** into
`~/.lanthorn/` (or beside the story) and read the machine's SYSTEM fonts out of it.

The games do not ship their body faces. `mac/xzip.lst` says
`ZSTD: TextFont (stdFont)` with `stdFont := geneva`, and Geneva lives in the
System file, on every Macintosh and on no game disk (SQ-1036). The Amiga's topaz
is in ROM and on Workbench, not on Arthur's floppy. So the authentic face is
reachable only from media the USER owns — which is precisely the arrangement
`stories/` already runs on.

## Why this beats a substitute

* **It is the real face at the real advances.** SQ-1036's route 1 — an
  open-source Helvetica bitmap standing in for Geneva — reproduces the SHAPE of
  the machine's behaviour (proportional text under a declared average) without its
  widths. This reproduces the widths, because it is the font.
* **We ship nothing.** No licence question at all. Same contract as `stories/`:
  read when present, skipped vacuously when absent, never committed.
* **It is mostly reuse.** `blorb` already mounts HFS, ADF, ProDOS, D64, FAT12,
  ISO9660, 2MG and the segmented `.D1`-`.D5`; `mac_font::from_volume` /
  `faces_in_fork` and `amiga_font::from_volume` / `faces_in_volume` already read
  faces off a mounted volume. This is those doors aimed at a different image.

**Evidence the Amiga half already works**: scanning the release floppies for
SQ-1009 turned up `fonts/garnet/16`, `fonts/garnet/9` and `fonts/gene/8` on Zork
III's `.adf` — AmigaDOS system faces in a `fonts/` drawer, found and parsed by
`amiga_font` with no special handling. A Workbench disk is that, with `topaz` in
it.

## The lookup

* **Macintosh** — a `FONT` id is family x 128 + size, so Geneva 12 is **FONT 396**
  (family 3), against the 524 (Monaco 12, family 4) the games ship. The System
  file's resource fork parses with the code already in hand.
* **Amiga** — `fonts/<name>/<size>`, a hunk file with `dfh_FileID` 0x0F80, which
  `amiga_font::parse` already signature-checks rather than matching on filename.

## Where it sits in the ranking

    the game's own media  ->  a user-supplied system disk  ->  an embedded
    substitute  ->  vga16

This is the existing "a release disk's own resources outrank a `.blb` beside the
story" rule extended one notch. Note it keeps SQ-1016's misc-fixed 7x14 USEFUL
rather than redundant: it is what CI and a player with no Workbench disk get.

## Open questions, none blocking

* **Where.** `~/.lanthorn/` is the better home than the game directory — one
  Workbench disk serves every Amiga game, and per-game sidecars are for a few keys
  (see the config rules in CLAUDE.md), not for media.
* **Which face for which request.** The game names a family; we resolve it against
  whatever the supplied disk carries. A missing family falls through the ranking
  rather than failing.
* **Version drift.** A System 7 disk's Geneva is not necessarily the 1988 one.
  Worth reporting which disk answered rather than silently using it.
* **Discovery.** The info panel already lists detected faces and marks which is in
  use (SQ-1019); it should say WHERE each came from once there is more than one
  source.

## Sequencing

Blocked behind SQ-1009's proportional pen — a proportional system face cannot be
DRAWN until the pen exists. Useful before then only for fixed faces, which is not
where the need is.

Related: SQ-1036 (the Macintosh's missing body face, which this would solve
outright), SQ-1016 (the embedded substitute, which becomes the fallback rung),
SQ-1009 (the pen).

## The disks are in place and verified (2026-08-23)

`~/.lanthorn/` now holds three, supplied by the user:

    MacOS_6.0.8_System_Startup.img
    Workbench v1.2 rev 33.56 (1987)(Commodore)(A500)(Disk 1 of 2)(Workbench).adf
    Workbench v1.3 rev 34.20 (1988)(Commodore)(A500-A2000)(DK)(Disk 1 of 2)(Workbench).adf

All three mount with the code already in the tree, and they carry exactly what
this quest wants — see SQ-1038 for the full inventory and for the one thing
stopping us reading it.

**Workbench 1.2 and 1.3 are IDENTICAL for fonts.** Same fourteen files, same
faces, same sizes, same parse outcome on both: ruby 8/12/15, opal 9/12, sapphire
14/19, diamond 12/20, garnet 9/16, emerald 17/20, topaz 11. The version choice is
therefore not a decision anyone needs to make. Worth recording so nobody re-runs
the comparison.

## *** Several disks should COMPOSE, not compete ***

The user put both Workbench disks in the directory deliberately, to exercise the
multiple-copies case, and it is a better test than it looks: every obvious
pick-one rule is bad.

* **first found** — filesystem-order dependent, so the answer changes for no
  reason the player can see;
* **newest version** — needs version parsing off a filename a player may have
  renamed;
* **most fonts** — arbitrary, and wrong the moment one disk has more faces but not
  the one being asked for.

So do not pick a disk. **Collect the faces from every disk of the right kind, then
resolve by what is actually being requested — family and size.** Several disks
compose into one pool rather than one of them winning.

That is not merely tidier, it is materially better here: the user has "Disk 1 of
2" for both Workbench sets, and the Extras disk of each pair carries further faces.
A compose rule picks those up as soon as they are dropped in; a pick-one rule
would discard whichever disk lost.

The machine still gates the KIND — an Amiga story consults ADFs, a Macintosh story
HFS volumes — and the source of the face that answered must be reported, because a
System 7 Geneva must not quietly stand in for a System 6 one.

Precedent for the shape: `mac_font::from_volume` already chooses among several
parsed faces on one volume rather than taking the first, and `PictSource` already
resolves an archive through a ranked cascade. This is the same idea across
volumes.

## Still blocked

SQ-1038: `Glyph::rows` is one `u8` per row, so every proportional face on both
disks is refused. 13 of 14 Amiga faces, and all seven Geneva sizes. Nothing here
can be built until that is widened.
