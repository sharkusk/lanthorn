  IFDB search's chooser marks a download option as already held only when a same-name file sits in the download folder itself (ifdb_search_modal.rs probe_present). A library that keeps games in subfolders (e.g. glulx/, infocom/, scott/) gets no mark, so the game is downloaded again as a second copy. Detection should not depend on the library's details having been fetched from IFDB first. Wanted, for the TUI and any embedding host: a lib call that says whether the library already holds the game an IFDB search resolved, searching every folder under the library root (as the library scan does) and matching by IFID, using the IFIDs in the resolved iFiction record (and the TUID where a story is already linked), with the same-name check kept as a fallback. Public so an embedding host can show the same mark in its own chooser.
