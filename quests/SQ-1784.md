--- note 2026-10-13T21:16:58Z ---

Problem. ifdb_documents::classify lists any non-isGame link with an unknown extension (or none, with format text/document) as LinkKind::Text and keeps it if the bytes sniff as text. HTML pages therefore get saved as documents even when they are a website or a dead online game. Hitchhiker's Guide (ifdb ouv80gvsl32xlion) shows every case: https://www.bbc.co.uk/radio4/hitchhikers/game.shtml (format html; IFDB desc: "Requires Flash, so in effect no longer playable"), https://tvtropes.org/pmwiki/pmwiki.php/... (format html), https://www.douglasadams.com/creations/infocomjava.html ("online Java version"), https://github.com/historicalsource/hitchhikersguide (no extension, format text). Meanwhile a real HTML manual or map is often exactly what a user wants, so HTML must not simply be dropped.

Proposal: give each link a kind decided from cheap signals already in the record, and let the host offer Open (in a browser) or Save with a default per kind, never removing the other choice except for dead games.

1. Before any download (record only):
   - Host: IF Archive and mirrors, eblong.com, a game's own docs path → document. General sites (github.com, tvtropes.org, wikipedia, bbc.co.uk, etc., or simply "not a known archive host") lean web page.
   - URL shape: plain file name (.html/.htm/.txt/.pdf …) → file; server-side page (.shtml .php .asp .aspx .jsp .cgi), query string, trailing '/', or no file name → web page.
   - IFDB title/desc wording: "Flash", "Java", "applet", "play online", "no longer playable", "formerly hosted" → obsolete online game. Always expose title/desc on the option (already parsed).
2. When the user previews or saves (the preview already fetches 16 KB, so no extra request): <embed>/<object> with .swf, or <applet> → obsolete game; little prose, mostly script and off-site links → web page; long prose or a TOC with relative links to its own images → document.

Suggested API: a new LinkKind::WebPage plus a flag (or kind) for an obsolete online game, and a per-option default action (Save | Open). Document → Save (Open also offered); WebPage → Open (Save also offered); obsolete game → Open only, labelled e.g. "needs Flash — no longer plays". The TUI chooser could open via its existing open-URL path.

Keep IFDB's terms: no prefetch; any sniff only on the user's own preview/save request.
