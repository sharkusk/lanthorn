Current code (rev 5a31a353, after SQ-1567):
- crates/app/src/render/v6_layout.rs:1762 `GlyphSink::caret(&mut self, canvas, x, y, w, h, ink: Rgba<u8>, panel)` paints `fill_cell(canvas, x, y, w, h, ink)` in every mode but RecordOnly, and records `V6Caret { x, y, h, panel }` (struct at v6_layout.rs:1694).
- So under RecordOnly — exactly when the host must paint the caret — the caret's `ink` (the composite's story ink from draw_story_text_into, or the panel's fg) and its `w` are thrown away. A host has to guess the colour (e.g. the fg of the last run of the same source on that row) and the width (a cell width), which can miss.

Change: add `w: u32` and `ink: image::Rgba<u8>` to `V6Caret`, filled from the arguments `caret` already receives. Nothing else changes; Rasterise output is untouched.

Acceptance:
- In `v6_headless_compose` with `awaiting: true` under RecordOnly: `caret.ink` equals the pixel colour the same frame's caret has under Rasterise, and `caret.w` × `caret.h` covers exactly the Rasterise caret's pixels — for Zork Zero r393's story caret and for a panel caret (a game reading through a secondary window).
- Existing pixel-for-pixel cases stay green.
