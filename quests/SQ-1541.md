--- note 2026-09-24T04:26:10Z ---

Citations are crates/app/src/ unless stated, as of ca723e44. Goal of this series: an embedding host that is not a terminal (a GUI, a network server, a mobile FFI binding) can boot and play a story through the `app` lib with the same rules the TUI uses, instead of re-implementing them. The TUI must run on the same code, so there is one copy of the rules.

Current state
- crates/audio/src/lib.rs: `decode_aiff` (:67) and `synth_tone` (:31) are private; `mod_stream::ModSource` is an `Iterator<Item=i16>` of interleaved stereo at 44100 Hz (:166-207) but the module is private and needs `mod-music`; Ogg decodes only inside the private `build_sample_sink` (:342) via rodio. The only public API is `AudioBackend` (:259).
- crates/audio/Cargo.toml: `default = ["playback","mod-music"]`, `playback = ["dep:rodio"]`. crates/app/Cargo.toml depends on audio without `default-features = false`, so every consumer builds rodio -> cpal -> alsa-sys (needs libasound2-dev, pkg-config).
- Infocom disk sounds: `native_sound::from_medium` (native_sound.rs:51) already yields AIFF via `InfocomSound::to_aiff` (blorb/src/infocom_sound.rs:410).

Change
- Public decode API that needs no device and no rodio: AIFF -> PCM (channels, rate, i16 samples), synthesized tone -> PCM (the Z-machine's high/low bleeps), MOD -> PCM (render ModSource to completion or for a duration), and a small WAV (RIFF PCM) encoder so a caller can hand PCM to anything that plays WAV. Ogg can stay as raw bytes (callers that cannot decode it themselves are out of scope).
- In app: a `playback` feature, default on, forwarding to `audio/playback` (and `mod-music` as today); cfg-gate the AudioBackend-using code in AppState/turn so `cargo build -p lanthorn --no-default-features` builds without rodio/cpal/ALSA. The TUI keeps default features.

Acceptance
- Unit tests: synth_tone PCM length/rate; AIFF decode of a committed or generated AIFF round-trips through the WAV encoder; MOD render of a committed tiny module (or skip if none is committable) yields the expected frame count.
- CI builds `-p lanthorn --no-default-features` on Linux without libasound2-dev in that job (or asserts alsa-sys is absent from its dependency tree).
