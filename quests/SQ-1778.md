--- note 2026-10-12T20:16:58Z ---

Cause (at a5cb7fe): crates/app/src/session.rs:2129-2133 (drain_turn, SQ-1604) gives back the restored-width floor (pre_restore_screen_cols -> boot_screen_cols) after any turn in which the game reads header byte $21; the doc comment at session.rs:1122-1128 assumes r52 never reads $21 again, but it reads it every turn while keeping the score/moves columns it laid out for 80 (set_cursor to 52/65). On the next poll host::screen::sync_zvm_screen_dims narrows the header to the pane (the TUI too, via loop_tick::poll_zvm_screen_dims), the set_cursor moves past it are dropped, and the moves wrap to row 2 (60 cols: ' Forest Path ... Score: 0' / ' 21') or garble the room name (40 cols: '0 28aring'). A fresh game at any width is fine. tests/suites/zork1_restore_status_width.rs misses it because it checks after one move, before the next poll narrows the screen. Suggested: don't release the floor on a $21 read alone for a story whose field columns are fixed; extend the test to a second turn after re-declaring the pane, at 60 and 40 columns. A host whose status line is then two rows also reads it aloud each turn (a two-row grid counts as content).

--- note 2026-10-12T20:22:52Z ---
