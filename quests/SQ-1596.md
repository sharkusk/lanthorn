--- note 2026-09-26T14:44:36Z ---

Some v4+ Z-machine stories read header bytes $20/$21 only at boot and refuse to start below a minimum. Bureaucracy (r86 and r116) needs 40 columns by 19 rows as the game sees them, and prints "[Screen too small.]" otherwise. A later resize to a larger size doesn't help: a 38-column or 80x18 boot refuses even after resizing to 80x30, while a 41x30 or 80x19 boot starts.

A host that can draw the game's grid windows at a smaller cell size wants such stories to boot at a minimum size even when its measured pane is smaller. It can't do that today. boot_story computes host_screen with the private pre_boot_host_screen (host/boot.rs:243, called at :706-707). The public story_screen_in (host/boot.rs:280) needs the resolved AppState (theme borders, garglk overlay, layout), which exists only after boot. So before boot a host can't find which pane size gives the game N×M.

Wanted, either of:
(a) TerminalFacts::min_story_screen: Option<(cols, rows)>, so the pre-boot seeded screen of a v4+ Z-machine story is raised to at least that size as the game sees it; or
(b) a public pre-boot query answering, from (cfg, story, pane size), the screen the game would see, or the smallest pane that gives the game N×M.

A pinned virtual_screen_cols/rows keeps precedence. Test story: Bureaucracy. Booting a 38x36 pane with a floor of (40, 19) should start the game instead of printing "[Screen too small.]".
