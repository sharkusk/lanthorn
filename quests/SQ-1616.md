Follow-up to SQ-1613.
(1) crates/gvm/src/glk.rs:3873: Model deserialize rebuilds each Window with terminators: Vec::new(), and serialize doesn't write them. GlulxSession::silent_look save_state/restore_state (crates/app/src/glulx_session.rs:1887, :1912) runs this round trip, so by the time a host asks GlulxSession::line_key_terminator the list is empty. Repro with gvm alone: a game calls glk_set_terminators_line_event (e.g. unit_tests/inputfeaturetest.ulx); is_line_terminator(F1) is true; after one serialize/deserialize it is false. A player's own save/restore loses them the same way. Fix: carry terminators (and probably echo_line) through the snapshot, with a format version bump if needed, or have silent_look preserve them.
(2) crates/app/src/main.rs:3303: the TUI's key gate only considers zvm_session_opt(...).pending_input() == Line, so Glulx terminators aren't delivered by the TUI either even when the list is intact. Route it through deliver_line_key_terminator for Glulx too.
Test: a Glulx story that sets F1 as a terminator ends the line on F1 after a look and after a save/restore.
