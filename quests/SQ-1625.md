Today mapper::graph::Room (crates/mapper/src/graph.rs:21) stores name, label_override, notes, pos, layer, loc_method and tried directions, but not what the room looked like. A player returning to a room they visited long ago, or browsing the map, often wants to reread its description without walking back or scrolling the transcript.
Ask:
- Capture the room's description when the player arrives or LOOKs: the text the game printed under the room's heading for that turn (the lib already knows the heading, e.g. the Glk heading+description detection in glk_backend, and the Z-machine location change). Keep only the most recent one per room, with the turn number, overwriting older ones, so a room that changes (a door opened, an object gone) shows its latest state.
- Store it on the Room (e.g. description: Option<String>, description_turn: Option<u32>), persisted with the map (serde default for old maps), plain text with paragraph breaks kept.
- Leave out the heading line itself, the status line, and lines that belong to the command's other output where the lib can tell (e.g. object listings are fine; an 'I don't know that word' reply isn't a description).
- Publish it for any embedding host (the room details a host shows, and the map export if useful). The terminal's own room panel could show it too.
- Works for Z-machine, Glulx and Scott Adams where the lib can tell a room's text apart; say which it can't.
Tests: arrive in a room, check its description; LOOK after a change, check it's replaced; reload the map, check it survives; an old map without the field loads.
