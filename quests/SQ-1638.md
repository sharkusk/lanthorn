--- note 2026-09-29T01:04:22Z ---

Observed per story (any host using the mapper and item tracker would see these):
1. Anchorhead (full game): no room is detected and no inventory is detected.
2. Anchorhead Special Edition Demo: inventory IS detected, but each item carries a lot of extra description instead of its noun name. Examples: 'umbrella my green handle'; 'clothes my tasteful muted brown green ensemble clothing pants trousers shirt' (adjectives, possessives and synonym lists from the parser/dictionary run together into one item name).
3. Counterfeit Monkey: the same kind of extra wording on detected items (also many one-character items, single letters and digits, which the host now hides in its own list).
4. Superluminal Vagrant Twin: rooms are detected when the player issues the 'map' and 'prospects' commands, i.e. the output of these meta commands is being mistaken for a room description/header, creating bogus rooms.
Expected: a detected room only from a real location change; item names reduced to the noun the game prints in inventory/room lists (no possessives/adjective/synonym tails); Anchorhead's status/inventory formats recognised. Repro with each story from the host's story folders.

--- note 2026-09-30T06:39:37Z ---

Triaged via a read-only investigation against real fixtures (stories/Anchorhead.gblorb, AnchorheadDemo.gblorb, CounterfeitMonkey-11.gblorb, Superluminal_Vagrant_Twin.gblorb.blorb):

#1 (Anchorhead full game: no room/inventory detected) — NOT reproducible on current main. Room detection works correctly across movement + look. This report's context head (ea95e22d) predates SQ-1639 ("harden Glulx description/item coverage"), which almost certainly already fixed this. No action needed.

#2 (Anchorhead SE demo: verbose item names) — MOSTLY fixed by SQ-1648 (names are clean at boot/look/inventory now), but a real NARROWER residual bug was found: `x umbrella` corrupts both "umbrella" and "clothes" to "green" simultaneously; `x clothes` afterward turns "clothes" into "tasteful". Root cause: item_tracker_display_name's tier-1 rule (session.rs, SQ-1648) picks the first of an item's own vocabulary words that appears in THIS TURN'S prose — but an `examine`'s prose is the object's own adjective-heavy description, so it readily cross-matches another object's shared adjective before reaching a real noun. Splitting this off as its own quest (see linked note) since it's a distinct, more precise bug than what was originally reported.

#3 (Counterfeit Monkey verbose/single-char items) — INCONCLUSIVE. look/inventory at the boot room returned zero tracked items in the probe; needs a deeper drive (take, movement) before this can be confirmed or ruled out. Left open below.

#4 (Superluminal Vagrant Twin: map/prospects create bogus rooms) — CONFIRMED, clean root cause. `map` sets TurnResult.location to a bogus "Other Worlds"/"Boony (not yet landed)"; `prospects` does the same; a subsequent real `look` snaps back correctly. Root cause: StoryScan::capture_heading/take_room_heading (glk_backend.rs ~869-1010) treats ANY own-line Subheader-styled text as a room-heading candidate, with no signal distinguishing a real movement heading from an unrelated meta-command's title printed in the same style. Splitting this off as its own quest too.

Narrowing this quest's remaining scope to #3 (CM item detection) pending a deeper probe.
