  User report: "after the intro screen, a new command jumps the scroll back to the intro quote, then scrolls quickly to complete the command." Traced precisely: pager.rs's arm_after_turn/apply_frame compute added/before_rows/after_rows against the FULL wrapped transcript's row count (window_wrapped_rows's n), with no awareness of AppState::top_anchor. Right after a clear, transcript_scroll==0 so at_bottom reads true; an ordinary command's own small output makes activation_target return None (fits in one screen), so arm_transcript_follow_ease(added, 0) fires, where added is this turn's own row delta against the FULL transcript, not against the anchor. window_wrapped_rows only takes the top-anchor path at scroll==0 exactly; any non-zero intermediate scroll value during the ease falls through to plain bottom-stick-from-the-whole-transcript, which reaches into the intro/quote text still sitting (unremoved) above the anchor in state.transcript. The animation settles back at scroll=0 where top-anchoring re-engages and hides it again — the visible "jump back then scroll forward." Root cause is the follow-ease operating in the wrong coordinate space (full-transcript-relative) while top-anchoring is active (anchor-relative), not a repeat of SQ-1656/1658/1660.
