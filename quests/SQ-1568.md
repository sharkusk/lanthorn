--- note 2026-09-25T05:00:20Z ---


**Why.** The rule for a v6 click lives in the terminal binary
(`crates/app/src/main.rs:3740-3820`). It covers which read takes a click
(`input::v6_click_read`, `input.rs:1338`; a Journey line read takes none),
`set_mouse(y, x)` (`session.rs:5384`), ZSCII 254 for a char read or
`submit_line_with_terminator` with `mouse_click_terminator()` for a line read
(`session.rs:1703`, `5248`), adopting the echoed direction as the turn's
command (`session::echoed_direction_command`, `session.rs:4078`), and running
`host::turn::finish_command_turn` or `apply_game_driven_result`. Mapping a
canvas pixel to a game pixel (where the rows an extended frame added are not the
game) lives in the terminal's `V6ClickMap` (`render/graphics.rs:714-900`).

**Change.**
- `app::host::input::deliver_v6_click(state, mapper, session, ctx: &TurnCtx, game_px: (u16, u16)) -> Option<TurnOutcome>`
  (`None`: the pending read takes no click). `TurnCtx` bundles `game_dir`,
  `ifid`, `arc_file`, `map_view`, `bg_tidy_counter`, the arguments
  `finish_command_turn` already takes.
- `RasterFrame::game_px(self, canvas_px: (u32, u32)) -> Option<(u16, u16)>`:
  1-based, `None` outside `native`.
- The TUI calls both and keeps its press/drag/release gesture.

**Acceptance.**
- Zork Zero r393 at its `>` prompt: a click on the banner compass's north spoke
  produces a turn whose command is `north`, maps an edge, and counts a turn.
- The same click during a char read delivers 254 with the coordinates visible
  to `read_mouse`.
- Journey r83 at a line read: `None`, and nothing changes.
- `game_px` returns `None` for a y inside an extended frame's added rows and for
  x ≥ native width, and `(1, 1)` for canvas (0, 0).
- The TUI's `v6_mouse_outcome` tests still pass.
