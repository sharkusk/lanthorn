## Why now

`crates/zvm` is to be usable outside this project as the standard Rust Z-machine
implementation. That changes what `pub` means: it is a promise to strangers, not
a convenience for `app`. Nobody has yet read the surface as an outside consumer
would, and the crate grew under the assumption that `app` was its only caller.

## The three questions to ask of it

**1. What is `pub` that should not be?**
Things exposed because `app` happened to need them, which an embedder would
reasonably take for API and which would then be painful to change. `V6Cell`'s
methods, `write_screen_dims` / `write_screen_dims_px`, `Machine::set_v6_cell` /
`set_v6_screen_px` and the `ScreenState` internals are all recent and worth a
deliberate look — several were made `pub` this week for lanthorn's benefit.

**2. What is missing that an embedder needs?**
The known case is SQ-1013 (the Version 6 cell lives in `app`), but there will be
others. Useful test: could someone write a working v6 host against `zvm` alone,
without reading `crates/app`? Where they cannot, either the knowledge is
misplaced or the seam is missing.

**3. Do the docs read as written for a stranger?**
`zvm`'s comments are unusually good but frequently addressed to US — they cite
quest numbers, name lanthorn's own defects, and assume the reader knows what the
ring or the hybrid path is. A `SQ-0917` reference is meaningless to an embedder;
the ZMSD section number beside it is not. Prefer the spec citation first and the
quest as provenance.

## The seam question, which is the interesting one

The engine must not decide I/O, fonts or rendering — but it should DEFINE the
interfaces a host plugs into, because that is what makes it embeddable rather
than merely readable. Existing seams: `Output`, the picture/sound event queues,
`InterpreterProfile`-supplied colours.

The one SQ-0917 identified and did not build is `FontMetrics` — a host-supplied
answer to "how wide is this string, in the face I am actually painting". Under
the standard-implementation goal this stops being speculative: a GUI drawing
proportional text is the second consumer the goal anticipates. `V6Cell` already
documents the boundary it sits on (declared metric versus drawn), so the shape is
half-designed already.

**Do not build it as part of this review.** Decide whether it belongs, and file
it if so.

## Also worth deciding

- **Versioning and stability.** Pre-release today with no back-compat obligation
  (a standing project rule). At what point does `zvm` start owing semver to
  people who are not us?
- **Whether `gvm` and `scott` carry the same ambition.** The goal as stated names
  `zvm`; Glulx and Scott Adams may or may not follow, and the answer changes how
  much of this review generalises.
- **A doctest or example.** Every crate here sets `doctest = false`, which is free
  while nothing is public-facing and looks different for a crate meant to be
  embedded — a compiled example is the cheapest proof the API is usable.
