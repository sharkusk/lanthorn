--- note 2026-09-16T15:53:12Z ---

Design settled 2026-09-16, ready to implement. Picture index 99 is already a documented convention in the scott crate (saga_us.rs's PictureFile::index doc, apple_pictures.rs's module doc: "R0199 the Adventure International globe-and-ai logo... §8.6's reserved 99") but has no named constant yet, unlike DARKNESS_PICTURE (0) and INVENTORY_PICTURE (98) which both live in saga_us.rs.

Mechanism: ScottSession::refresh_picture() (crates/app/src/scott_session.rs) is the single place that decides which picture the band shows, called at boot (new_with_options) and after every turn (submit). Add a `showing_title_card: bool` field, true only at boot when this release both (a) has US S.A.G.A. (family-C) artwork — `picts.scott_saga_platform().is_some()`, which is exactly "US S.A.G.A." and correctly excludes the MS-DOS/Apple/other dialects this quest is not scoped to — and (b) actually carries picture 99 — `picts.image(u32::from(TITLE_PICTURE)).is_some()`, the same defensive check `submit()` already applies to picture-show sequences (SQ-1482's `shows.retain`). While the flag is set, refresh_picture() shows TITLE_PICTURE instead of the room; the flag is cleared as the first line of `submit()`, so the player's first command of any kind dismisses it and every refresh_picture() call from then on is unaffected.

Restore is the one place this needs explicit handling: ScottSession::restore_state already clears `self.showing` (SQ-1487's picture-show sequence) with the comment "transient host state, not part of the scott::Vm snapshot" — showing_title_card is the same category and must be cleared there too (and in restore_game_save), or a restore into a session already past the title would incorrectly re-show it.

Scope: US S.A.G.A. (family-C: C64, Apple II, Atari 8-bit) only, per this quest's title. NOT the MS-DOS Questprobe release (family-E) even though its own doc block also mentions a title picture — no ground truth for its real boot sequence, don't extend without evidence. NOT the restore-question/Demo-mode prompt — deliberately out of scope per this quest's own context note.
