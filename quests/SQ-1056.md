## What the capture already narrows

* **The story window is present and correct** — `win0` is a primary `Buffer`, 548x370 at native (46,30), marked current+input. So this is NOT SQ-1026's shape: there is a real `Buffer` in the story slot, and the guard added there (a `Grid` contributes its rect and nothing else) returns early only when the slot holds something other than a `Buffer`. **Check that first anyway**, since the frame one screen earlier — the hint menu — is exactly the frame that guard fires on, and this is the frame after leaving it.
* **`0 prose line(s)` and `0 paint run(s)` on win0.** The story window carries nothing of its own; in raster the prose comes from the HOST transcript through `build_main_text`, so the question is whether that path ran at all.
* **Only two bands, both flanks.** `band uploads since launch: 2` and both are `[Art, tiled]` side columns. Nothing was uploaded for the middle.
* **Hybrid on the same frame is fine**, per the report — and the path history shows `hybrid-ring x3` before the switch, so both were exercised on this screen.

## Where to look

`build_v6_raster_canvas`'s early returns are the obvious suspects, and there are now several: the plate arm (`story_prose_box` returning `None`), the canvas arm (`story_window_is_a_canvas`), the degenerate-interior arm (`story_clear_native` filtered on `w >= 8 && h >= 16`), and SQ-1026's new `Buffer` guard. Each of them ships the frame with no prose and no scroll metrics, which is exactly what a blank screen looks like. Print which one this frame takes before theorising.

`win7` is a full-screen 640x400 Graphics window. If the hint screen left it holding opaque pixels, `story_clear_native` insets past frame art and could return a degenerate interior — that would take the `w >= 8 && h >= 16` arm and blank the screen. That is a guess and the frame should settle it.

### Hypotheses tested and eliminated

* **SQ-1026's guard firing.** No — the story slot holds a `Buffer`, and the guard returns early only when it does not. (Worth checking anyway because the frame one screen earlier IS the hint menu, which is exactly what that guard fires on. It does not carry over.)
* **The post-clear top-anchor** (`build_main_text`'s `anchor_row`, SQ-0748 — "an anchor at the very end of the transcript reads as an EMPTY screen"). No: Shogun sets **no `erase_lower`** on this route, so no clear anchor is ever recorded. Verified by mirroring `turn.rs`'s anchor handling in the harness and watching it never fire.
* **The magnification ladder.** No: `FrameGeometry::step()` is 1 on the Macintosh (`gcd(7,15) = 1`), so every whole magnification is a valid rung; at 1376x1224 device px the lock picks **2.000** cleanly, `degraded=false`.
* **White-on-white.** No: the game sets an explicit pair after the hint screen (`pair=(16777218, 16777225)`, white page / black ink) and both reach the canvas.

### Where that leaves it

This is the case CLAUDE.md describes for escalating a layer: *"reach for it when the model looks right and the screen doesn't"*. The cell-buffer layer says the frame is right, so the next honest instrument is `crates/app/tests/pty_stream/` (or `cargo run -p app --example pty_capture`) — the only layer that tells an image PLACEMENT apart from a background painted into cells.

**Leading hypothesis, untested**, from reading `render::graphics`:

`encode_v6` ends in `picker.new_protocol(...).ok()?` and `spawn_v6_encode` stores its `Option` straight into `self.v6`. If that encode returns `None`, `self.v6` stays `None`, so `v6_wants_build` answers true again next frame and the same encode is retried — forever, with nothing placed. That is exactly the shape of the reporter's dump: **`raster x21` against `band uploads since launch: 2`**, the two bands being leftovers from the hybrid frames before it. It would also explain why hybrid is unaffected: bands take a different encoder.

The session history matters here in a way a fresh `AppState` cannot reproduce — the reporter's path is `hybrid-ring x3 → modal overlay (hotkey_dialog) → modal overlay (palette x4) → raster x21`, and the hybrid ring calls `invalidate_v6()` on every frame it draws.

### Two cheap observations that would halve the search

1. **Does the frame ART vanish too** (the side columns and border), or only the story text? Art gone = nothing is being placed at all, which points at the encode; art present = a content question.
2. **Does anything bring it back** — resizing the pane by one column, toggling `/set-v6-render` away and back, or a keypress? A resize changes `area`, which is in `v6_wants_build`'s key; if that restores the screen, the cache/area path is implicated rather than the encode.

## Hypotheses tested against the reproduction and ELIMINATED

The frame reproduces exactly off `stories/Shogun.toast` (r292/890314) with Geneva; in that reproduction raster draws the prose correctly (13,584 ink px in the story box). So each of these was tested by forcing the state and comparing both paths:

Raster and the cell path move **together** — at `Some(n)` raster gives 0 non-blank rows and the cell pane gives 2. No asymmetry, so this cannot produce "raster blank, hybrid fine". Also: Shogun sets no `erase_lower` on this route, so no anchor is recorded at all.
* **A parked scroll / the pager.** Swept `transcript_scroll` over 0, 5, 12, 23, 24, 30, 47, 60, 200. Raster stays at 18–19 non-blank rows throughout and the cell pane at 40; `max_scroll` is 24 and the clamp behaves. Never blanks.
* **SQ-1026's `Buffer` guard.** The reporter's own dump has `win0 … attrs=1111 … model: Buffer — the story window`, so the guard passes. (Worth re-checking only if a frame ever comes back with win0 as a `Grid`.)
* **The early-return arms.** `story_clear_native` and `story_prose_box` both answer `Some((46,30,548,370))`; neither the plate arm nor the degenerate-interior arm fires.
* **The magnification ladder.** `step()` is 1 on the Macintosh; the lock picks 2.000 at the reporter's pane, `degraded=false`.
* **White-on-white.** The game sets white page / black ink and both reach the canvas.

## What is left

The difference has to be **session history** that a fresh `AppState` cannot reproduce — the reporter's path is `hybrid-ring x8 → modal (palette x4) → raster → modal (palette x4) → hybrid-ring x187`, i.e. the pane has been through hybrid frames and modal overlays before raster is asked for. `state.raster_wrap` is the one product that survives all of that, is keyed by `WrapKey`, and is **not** invalidated by a resize on the raster path — because raster's wrap width comes from `story_prose_box` over the NATIVE screen and so is constant for the session, which is exactly why a resize moves the art and not the text. `restart` clears the transcript, which changes `WrapContent` and forces a rebuild — which is exactly what recovers it.

That is a hypothesis with the right shape but it is **not confirmed**: `WrapShape` looks thorough (width, filter, images, char_px, clear_anchor, machine_pair, story_page, period_look, hybrid_ring, face fingerprint) and I could not make it go stale by hand.

**Next instrument: the pty capture** (`crates/app/tests/pty_stream/`, or `cargo run -p app --example pty_capture`), driving the REAL binary through the reporter's own sequence — boot, hybrid frames, a modal, hint, `y`, `q`, switch to raster. ## What this rules in and out

* The window model is a proper primary `Buffer` — SQ-1026's guard is not involved,
  as the earlier notes already found.
* The headless harness with this same model builds a canvas WITH prose (13,584 ink
  px, measured in this quest's second note), so the model and the canvas builder
  are both sound in isolation.
* Therefore the difference is the live session's own state across the
  ring→raster transition. The stream backs that up: the composite is re-transmitted
  several times after the menu, and the LAST upload of the run is the smallest
  payload of all of them (21,156 B against 26–50 KB earlier), which is what a
  chrome-only canvas compresses to.

## Next

Bisect inside that transition rather than around it. The two candidates, both now
cheap to test because the route is scripted:

1. `state.raster_wrap` across the ring frames — the ring never calls
   `build_main_text`, so the cache is not refreshed while the menu is up.
2. The encode/placement path after `invalidate_v6()` — `spawn_v6_encode` runs
   synchronously when `self.v6` is `None`, and the payload sizes say the final
   canvas really is chrome-only, so the canvas handed to it is already blank.

(2) is the stronger lead: a blank canvas at encode time means `build_v6_raster_canvas`
took an early-return arm on THAT frame, in the live session, where the harness does
not. Print which arm on the `q` frame under the pty and the quest is answered.
