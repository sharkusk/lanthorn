## What the capture already narrows

* **The story window is present and correct** — `win0` is a primary `Buffer`, 548x370 at native (46,30), marked current+input. So this is NOT SQ-1026's shape: there is a real `Buffer` in the story slot, and the guard added there (a `Grid` contributes its rect and nothing else) returns early only when the slot holds something other than a `Buffer`. **Check that first anyway**, since the frame one screen earlier — the hint menu — is exactly the frame that guard fires on, and this is the frame after leaving it.
* **`0 prose line(s)` and `0 paint run(s)` on win0.** The story window carries nothing of its own; in raster the prose comes from the HOST transcript through `build_main_text`, so the question is whether that path ran at all.
* **Only two bands, both flanks.** `band uploads since launch: 2` and both are `[Art, tiled]` side columns. Nothing was uploaded for the middle.
* **Hybrid on the same frame is fine**, per the report — and the path history shows `hybrid-ring x3` before the switch, so both were exercised on this screen.

## Where to look

`build_v6_raster_canvas`'s early returns are the obvious suspects, and there are now several: the plate arm (`story_prose_box` returning `None`), the canvas arm (`story_window_is_a_canvas`), the degenerate-interior arm (`story_clear_native` filtered on `w >= 8 && h >= 16`), and SQ-1026's new `Buffer` guard. Each of them ships the frame with no prose and no scroll metrics, which is exactly what a blank screen looks like. Print which one this frame takes before theorising.

`win7` is a full-screen 640x400 Graphics window. If the hint screen left it holding opaque pixels, `story_clear_native` insets past frame art and could return a degenerate interior — that would take the `w >= 8 && h >= 16` arm and blank the screen. That is a guess and the frame should settle it.
