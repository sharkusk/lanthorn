  Design settled with the owner 2026-10-23 after a run of resize/restore status-bar bugs (SQ-1806, SQ-1808, SQ-1778): games that lay their status out once from the boot width break whenever the width changes or a save moves between screen sizes. DECISIONS: (1) fixed width = 80 columns (Infocom v4+ target; verify against machine-screenshots before pinning, and take it from the InterpreterProfile so a medium that differed can say so). (2) Which games: DETECT, don't list -- the engine observes whether the game reads header byte $21 again after its first status draw/split; a game that does adapts and stays dynamic (Inform libraries), one that doesn't is told 80 for the session and never sees a width change. Reconcile with SQ-1778's existing shadow-turn overreach detection (settle_width_floor) -- this likely replaces it for these games. (3) Pane wider than 80: centre the grid (already done in render/upper_window.rs) and extend each row's reverse/bg styling into the side margins. (4) Pane narrower: display-only column dropping, never touching the game's grid -- first drop columns that are blank on EVERY row, nearest the centre first alternating left/right; only then drop content columns middle-out the same way; the same column set applies to every row of the upper window (multi-row status areas, Bureaucracy forms, quote boxes, Beyond Zork panels stay aligned). (5) Anything mapping screen column -> game column needs the inverse mapping (upper-window mouse clicks, e.g. Beyond Zork; cursor if drawn); a click on a dropped column lands on the nearest kept neighbour. Scope v4/v5/v7/v8 only; v3 status is interpreter-drawn, v6 is its own path. Saves become terminal-width neutral for these games. Not to be dispatched until the owner says so; SQ-1808 is being fixed separately first.

--- note 2026-10-23T16:47:31Z ---

Feedback from The Golden Lanthorn (2026-10-23), with proposed resolutions (owner to confirm):
1. In-place forms (Bureaucracy): today's viewport follows the cursor so the field being typed stays visible; column dropping could drop a mid-form field at 45 cols. RESOLUTION: never drop the cursor's column, and protect the field around it (the contiguous styled/non-blank run containing the cursor) whenever the game is reading input with the cursor in window 1.
2. Quote boxes / Beyond Zork panels at narrow widths: blank-column dropping handles margins, but middle-out CONTENT dropping makes prose unreadable. RESOLUTION: content dropping applies only to the status band (the rows of a plain status line). When the grid holds anything else (a quote box, a menu, a form, panels) and still doesn't fit after blank-column dropping, fall back to today's horizontal viewport (follows the cursor) rather than dropping content. The host follows whatever the TUI does.
3. Lower window: $21 is one value for the whole screen, so a game told 80 may centre/pad story text for 80; we reflow lower-window text, so leading centring spaces could look off on a narrow screen (same exposure SQ-1778's floor already has today). Add to the test plan: a lower-window centring check on several Infocom v5 titles (e.g. AMFV, Trinity, Bureaucracy, Beyond Zork, Sherlock, HHG Solid Gold) at ~45 cols once the feature exists; if it's bad, consider trimming leading padding on lower-window lines that the 80-column assumption would have centred.

--- note 2026-10-23T16:50:16Z ---

Detection mechanism (proposed 2026-10-23, owner to confirm): classify by OBSERVED behaviour, not by compiler/type (Infocom vs Inform only says who compiled it; AMFV re-splits and adapts, some Inform games cache in a custom status routine). The catch: a game caches whatever it is told at boot, so the verdict must exist BEFORE the real boot. Proposal: probe in a shadow machine (the SQ-1778 settle_width_floor shadow-turn machinery is the precedent) — boot + first turn with header reads of $21 watched (byte read of 0x21 AND any word read covering it, i.e. loadw at 0x20; v5 also word $22 width-in-units), then a second turn: reads after the first input => ADAPTS (told the pane width), none => CACHES (told 80 for the session). Persist the verdict in the host save (a game property, not terminal state, so the archive stays terminal-neutral) so a restore never re-probes; optionally cache it per story identity (release/serial/checksum). Keep a per-game override (config sidecar key) as the escape hatch for a misjudged title. Alternative considered: boot every v4+ game at 80 and release adapters to the pane width once they re-read — simpler, but an adapting game's first screen would be laid out at 80.

--- note 2026-10-23T17:17:14Z ---

Embedding-host needs (The Golden Lanthorn's web page, which draws grids itself from data and cannot reuse render/upper_window.rs):
1. The column-dropping rule as a library function beside grid_viewport, not inside the TUI renderer: given the upper grid and the pane's width, return the kept game columns (a sorted list or ranges). A host sends that to its page in place of today's contiguous first/width viewport and draws only those columns, so the TUI and every host drop exactly the same columns.
2. The inverse mapping from the same function (screen column -> game column, a dropped column landing on its nearest kept neighbour), for a drawn cursor and for upper-window mouse clicks.
3. In-place forms (Bureaucracy etc.): today's viewport follows the cursor (SQ-0122-style), so the field being typed stays on screen. Middle-out dropping must never drop the cursor's column, and ideally not the run/field around it.
4. Quote boxes and multi-row panels (Beyond Zork) at a narrow pane (the Retroid Flip 2 is about 45 columns): dropping blank columns trims a box's margins well, but dropping content columns middle-out leaves quote text unreadable. Consider a different fallback for rows that are text rather than a status line (e.g. the existing contiguous viewport), and expose which one applies so a host follows the same choice.
5. Centring a wider pane and extending each row's reverse/background styling into the side margins is presentation; a host can do it from each row's first and last cell style, so nothing extra is needed from the library unless the TUI's rule is more than that.
6. Lower window: a game told 80 columns may pad or centre story text for 80; hosts that reflow proportional text may show that padding oddly on narrow panes. Worth a check with a few v5 titles when this lands.
Screen readers and narration read the game's full grid, not the kept columns, so dropped columns never hide text from someone listening.

--- note 2026-10-23T18:07:21Z ---

MEASUREMENT (2026-10-23), header_width_read (SQ-1604 flag) drained per input, 80x25 boot, 32 v4+ games in stories/ (15 *inv.z5 hint programs excluded). Tool saved at <session scratchpad>/width_probe/width_probe.rs (+ dbg_w22_counter.patch); run as `cargo run --release -q -p lanthorn-zvm --example width_probe -- [--width N --cmd look|z|empty --inputs N --resize --rwidth W --key N --layout --dump] stories`.
- ADAPTS (17): every Inform game tested — Bronze, Facility, ImpossibleStairs, LostPig, MakeItGood, Mulldoon, Savoir-Faire, Tangle, Wallpaper, WeirdCityInterloper, anchor, curses, frankenfingers, gostak, suvehnux, vespers — plus Infocom's Border Zone r9 (re-reads at chapter starts only: inputs 2 and 7). 15 re-read on input 1; anchor on input 2 (after keypress intro). Facility, frankenfingers, suvehnux do NOT read $21 at boot — so boot reads carry no signal either way.
- CACHES (11): every other Infocom v4/v5 — Trinity r12, AMFV r77, Bureaucracy r116 (provisional: stuck at "[Press any key to begin.]"), Nord and Bert r19, Sherlock r26, Beyond Zork r57, Solid Gold HHG r31 / LGOP r4 / Planetfall r10 / Wishbringer r23 / Zork I r52.
- UNCLEAR (4): no status line or never past the intro — photopia (reads only on keypress turns), solpoker and Bureaucracy-like stuck keypress screen, advent.z8, nameless.z8.
- Width-follow cross-check (boot 80, resize to 60/40, 2 more inputs) agreed with the read verdict for every game with a width-dependent status: no game re-reads and still has a baked layout. anchor adapts but overlaps location/right field at 40 cols (an adapting game misbehaving very narrow — the floor note's case).
- Command (`look` / `z` / empty line) changed no verdict. $22 reads: only Beyond Zork, once at boot — no $22 tracking needed.
PROBE RULES derived: (1) count only turns after the first real line-input prompt; a read in the keypress turn right after boot does NOT count (Trinity reads once there, then never). (2) ADAPTS = any $21 read within 4–6 line-input turns; else CACHES. (3) Command `look`. (4) Keypress prompts: Enter/space; Border Zone's chapter menu needs `1`; Beyond Zork's menu needs `begin` then a key; keep the yes/no heuristic narrow (it misfired on advent.z8). (5) A repeated identical prompt limit; on hitting it, or no status line at all, fall back to CACHES (the safe, clamping outcome). Open: why Bureaucracy/solpoker stick on "Press any key" in a bare harness (possibly a timed read_char the harness doesn't service) — investigate when building the probe.
