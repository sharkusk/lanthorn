  Design settled with the owner 2026-10-23 after a run of resize/restore status-bar bugs (SQ-1806, SQ-1808, SQ-1778): games that lay their status out once from the boot width break whenever the width changes or a save moves between screen sizes. DECISIONS: (1) fixed width = 80 columns (Infocom v4+ target; verify against machine-screenshots before pinning, and take it from the InterpreterProfile so a medium that differed can say so). (2) Which games: DETECT, don't list -- the engine observes whether the game reads header byte $21 again after its first status draw/split; a game that does adapts and stays dynamic (Inform libraries), one that doesn't is told 80 for the session and never sees a width change. Reconcile with SQ-1778's existing shadow-turn overreach detection (settle_width_floor) -- this likely replaces it for these games. (3) Pane wider than 80: centre the grid (already done in render/upper_window.rs) and extend each row's reverse/bg styling into the side margins. (4) Pane narrower: display-only column dropping, never touching the game's grid -- first drop columns that are blank on EVERY row, nearest the centre first alternating left/right; only then drop content columns middle-out the same way; the same column set applies to every row of the upper window (multi-row status areas, Bureaucracy forms, quote boxes, Beyond Zork panels stay aligned). (5) Anything mapping screen column -> game column needs the inverse mapping (upper-window mouse clicks, e.g. Beyond Zork; cursor if drawn); a click on a dropped column lands on the nearest kept neighbour. Scope v4/v5/v7/v8 only; v3 status is interpreter-drawn, v6 is its own path. Saves become terminal-width neutral for these games. Not to be dispatched until the owner says so; SQ-1808 is being fixed separately first.
