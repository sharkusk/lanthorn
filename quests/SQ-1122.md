## The decision (user, 2026-08-28)

Add `[command_band] hidden_verbs`, with a **default list containing only
R-rated cuss words** — the strong ones. Not mild profanity.

**This does not contradict the "faithful, we don't censor" ruling on
[[SQ-1115]].** That ruling governs the generated synonym data, where a word can
only ever surface because the player typed something that mapped to it AND the
story implements it. Here the words are **displayed unprompted** to anyone who
opens a panel. The user drew that line himself, and the two decisions are
consistent: the data stays faithful; the unbidden display gets a default.

## Scope — err toward under-filtering

`only include rated r cuss words`. Zork I's dictionary holds a spread, and the
default list is the strong end of it, not everything that would raise an
eyebrow. `damn` and `barf` are Infocom being Infocom and stay visible. The list
should be short enough to read at a glance.

**One question to put to the user before shipping the default:** Zork I also
holds `rape` and `molest`. Those are not cuss words, so the literal reading of
the instruction excludes them — but displaying them unprompted in a panel is
arguably worse than any expletive. Ask; do not decide it silently in either
direction.

## Design — the list must be VISIBLE, which is what keeps it a default and not censorship

- Ship it in `config_template.rs` as an **uncommented, readable line**, so a
  player can see exactly which words are hidden and delete or extend it. A
  filter nobody can inspect is censorship; a filter written in the player's own
  config file is a default.
- Setting `hidden_verbs = []` must restore the full column. Verify that works.
- It filters **display only**. A hidden verb is still a word the story knows —
  typing it must behave exactly as it does today, and SQ-1041's suggestion path
  must not consult this list. Pin that as a test: the same word hidden from the
  panel and still offered by the light, if the story holds it.

## Where it goes

`[command_band]` beside `verbs` and `extra_verbs` (`crates/app/src/config.rs`),
applied after the `VerbTable` is assembled so it filters the story's grammar,
a configured `verbs` list and the `BUILTIN_VERBS` fallback alike. Document in
`docs/features/customization.md` next to the other two keys, and say plainly
what the default holds and how to empty it.

## Sequencing

**Do not dispatch while SQ-1116 or SQ-1121 are live** — 1116 owns
`command_band.rs` and 1121 owns `config.rs`, and this needs both.

## The switch, and the list is top-level not band-local (user, 2026-08-28)

`rape` and `molest` go **on** the list — the user's call, resolving the question
left open above. He calls it "the adult list", which is a better name than
`hidden_verbs` because it says what it is; use that vocabulary.

**Two keys, not one:**

```toml
hide_adult_words = true          # the switch
adult_words = ["…", "…"]         # the content, visible and editable
```

A bare list cannot be turned off without destroying it — emptying it means
retyping the words to get it back — and a list is not something a settings-screen
row can toggle. Splitting them gives three controls, each doing what its shape
implies: the settings row flips the boolean, `hide_adult_words = false` turns it
off while keeping the list, and editing `adult_words` changes what counts.

**Top level, NOT under `[command_band]`.** The principle is not about the band:
*unprompted enumeration gets a default; what the player reached for does not.*
SQ-1107's momentary reveal is another unprompted enumeration, and so is whatever
comes next. One setting they all read answers the question once instead of each
surface growing its own key and drifting apart — the same argument as
[[SQ-1117]].

A CLI flag is optional and probably unnecessary — this is a display preference,
not a launch mode. Say what you decided.

## Unchanged by this

The list is still shipped **uncommented and readable** in `config_template.rs`,
so a player can see exactly what is hidden. It still filters **display only** —
typing a hidden word behaves exactly as today, and SQ-1041's suggestion path must
not consult it, pinned as a test. And [[SQ-1115]]'s "faithful, we don't censor"
still governs the generated synonym data, which this does not touch.
