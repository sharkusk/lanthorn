--- note 2026-10-03T16:58:51Z ---

Add a lib decision (e.g. glk_cfg::design_readable(fit, char_px, primary_rect) -> bool, plus a MIN_DESIGN_TEXT-style constant or config key, e.g. 20x4) saying whether a design-size story's primary text window, at the text cell GlkFit::design_screen implies, gets too few columns/rows, so any host (and the TUI on a small terminal) can fall back to cell layout on a small pane instead of each inventing its own threshold. Decide it only from pane / cell / design / fit changes, never from the game's transient layout (Photopia's chapter cards squeeze the text window to 0 on purpose and must not flip it). Stretch mode doesn't remove the need: on a 390x640 pane Narcolepsy's 240px text box still gets ~11 columns in either mode, since stretch adds height, not width.
