--- note 2026-10-03T04:29:47Z ---

The picker's download-hints handler (picker_ui.rs ~3050-3085, drained ~1980-1995) lives in the binary: busy check, has-hint check, hints::hint_download_for, documents::locate, HintDest::for_story, HintDownloader::start, plus its status lines ("Downloading hints for {title}…", "{title} already has a hint file", "No InvisiClues found for {title}", "Downloaded hints for {title}", "Hint download failed: {msg}"). A host that offers the same action outside a running game has to repeat all of it.

Proposed: e.g. host::hints::start_story_download(&mut HintDownloader, &StoryEntry, &DataRoots, &HintIndex) -> String (the status line) and host::hints::download_result_line(&HintDlResult) -> String, used by both the picker and hints_tab::start_download_in / poll_download, so the logic and wording live in one place.

Related:
- hints_tab::start_download_in (hints_tab.rs ~241) names the story by its file stem, so the in-game result reads "Downloaded hints for deadline-r27-s831005" while the story browser says "Downloaded hints for Deadline". Use the story's title (state.title).
- hint_download::HintDownloader has no way to inject a fetcher (fetch_bytes uses ureq directly), so a host cannot test its download wiring offline. A HintDownloader::with_fetcher(...) seam would help.
