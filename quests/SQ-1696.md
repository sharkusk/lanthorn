--- note 2026-10-03T04:29:47Z ---

The picker's download-hints handler (picker_ui.rs ~3050-3085, drained ~1980-1995) lives in the binary: busy check, has-hint check, hints::hint_download_for, documents::locate, HintDest::for_story, HintDownloader::start, plus its status lines ("Downloading hints for {title}…", "{title} already has a hint file", "No InvisiClues found for {title}", "Downloaded hints for {title}", "Hint download failed: {msg}"). A host that offers the same action outside a running game has to repeat all of it.

Proposed: e.g. host::hints::start_story_download(&mut HintDownloader, &StoryEntry, &DataRoots, &HintIndex) -> String (the status line) and host::hints::download_result_line(&HintDlResult) -> String, used by both the picker and hints_tab::start_download_in / poll_download, so the logic and wording live in one place.

Related:
- hints_tab::start_download_in (hints_tab.rs ~241) names the story by its file stem, so the in-game result reads "Downloaded hints for deadline-r27-s831005" while the story browser says "Downloaded hints for Deadline". Use the story's title (state.title).
- hint_download::HintDownloader has no way to inject a fetcher (fetch_bytes uses ureq directly), so a host cannot test its download wiring offline. A HintDownloader::with_fetcher(...) seam would help.

--- note 2026-10-03T04:55:21Z ---

Scope, revised: an embedding host wants to call the story browser's own hint code for a story row, not re-create it. Please expose, as host-neutral functions in the lib (used by picker_ui.rs too, so there is one copy):

1. The row's hint status: what the info panel shows (picker_ui.rs ~3905-3910): Some(hint file name) from entry.hint_sidecar, else "available to download" when hints::hint_download_for(ifid) is Some, else nothing. E.g. picker::hint_status(&StoryEntry) -> HintStatus { File(PathBuf) | Downloadable | None }.
2. Starting the download for a row (picker_ui.rs ~3050-3085): busy check, already-has check, hint_download_for, documents::locate, HintDest::for_story, HintDownloader::start, returning the status line. E.g. host::hints::start_story_download(&mut HintDownloader, &StoryEntry, &DataRoots) -> String.
3. Applying a finished download to the row list (picker_ui.rs ~1975-1992): find the entry by story + disk entry, set hint_sidecar = dest, recompute badges, and the result line. E.g. picker::apply_hint_download(&mut [StoryEntry], &HintDlResult) -> (Option<usize>, String).

Bug to fix along the way: for an IFDB-linked game, a download now lands in the documents folder (SQ-1690), but the scan's associate_hint_sidecars only looks beside the story. After a restart entry.hint_sidecar is None again, so the browser says "Hints: available to download" and Shift-H downloads again, although resolve_hint_source finds the file. The row's hint status (and the already-has check) should see a hint program in the game's documents folder too, e.g. via the same lookup resolve_hint_source step 0 uses.
