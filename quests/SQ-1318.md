REDESIGNED 2026-10-02 on top of SQ-1676 (lanthorn's --player / LANTHORN_PLAYER). Lanthorn never authenticates.

ttyd 1.7.7 facts (MIT, tag 1.7.7, commit 40e79c706be1):
- -H/--auth-header trusts the named header (src/protocol.c:184-185) and exports TTYD_USER=<value> to the child (src/protocol.c:137-141, max 29 chars).
- -c/--credential is a single user:pass and exposes no username.
- -a ?arg= is unauthenticated.

Two modes:
A) Proxy mode (real separation):
   - New env, e.g. LANTHORN_WEB_AUTH_HEADER=<header>, makes entrypoint.sh pass `--auth-header <header>` to ttyd.
   - serve-session.sh validates and exports LANTHORN_PLAYER="$TTYD_USER".
   - Document that ttyd's port must be reachable only via the proxy, and that the proxy must strip client-supplied copies of the header. Examples: Caddy forward_auth / Authelia / Authentik / Tailscale serve identity headers.
B) Household mode (no real auth): the single ttyd credential as the house password, plus a "who's playing?" picker that sets the player. Picker design still to be agreed; a URL ?arg player is acceptable only here.

Required in both modes: key every detached-session path (dtach socket, audio FIFO, stamp, serve-session.sh:76-80) by (player, session id), e.g. <dir>/<player>/<id>. Otherwise a player could reattach another's game by reusing a browser-supplied id.
Build A first; B after its picker is designed. Depends on SQ-1676.
