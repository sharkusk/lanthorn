Citations crates/app/src/, as of 3153804a. Found while driving the session host from a headless host (no terminal). Each item is small; together they remove the last places such a host must copy TUI rules.

1. Per-command bookkeeping lives only in the TUI. Before calling `host::turn::finish_command_turn`, main.rs (~3953) does `record_command`, `turns += 1` and `unsaved_progress = true`. A headless host has to repeat those three lines to get the same history, turn count and autosave behaviour. Move them into the host (inside `finish_command_turn`, or a documented `host::turn::begin_command` the TUI also calls) so there is one copy.
2. Boot does not report whether it resumed from the resume archive. `host::boot_story` returns `BootedStory` with no flag; a host has to infer it from the console hooks and by re-reading the archive. Add a field (e.g. `resumed: bool`, or the loaded archive's summary) to `BootedStory`.
3. `host::ingame_io::handle_save_as` (host/ingame_io.rs:78) returns `()`. A host that answers the game's own SAVE without drawing dialogs can only detect failure by scraping the notices it pushes. Return a Result (or an outcome enum: saved / exists / failed(reason)); keep pushing the notice for the TUI.
4. `render::resolve_zcolour` (render/mod.rs:233) is `pub(crate)`. A host that renders transcript StyleRuns itself needs exactly this mapping (packed zcolour + palette -> concrete colour) and currently restates its four arms. Make it pub (or move the pure part out of `render` into `colors`), returning a plain RGB rather than a ratatui Color if that is what forces it into render.

Acceptance
- TUI behaviour unchanged; existing suites pass.
- `tests/suites/host_turn.rs` / `host_boot.rs` / `host_session.rs` extended: a headless command turn updates history/turn count/unsaved state with no extra caller code; boot reports resumed true/false correctly; a SAVE answered to an existing name or an unwritable path yields the error outcome; resolve_zcolour is callable from an integration test.
