--- note 2026-09-25T13:07:59Z ---

Current code (rev 5a31a353):
1. Story ink: `compose_v6_frame_into` (crates/app/src/render/screen.rs ~l.3007-3011) resolves the prose ink (`game_ink` / `ink`, via `v6_layout::story_fg_rgba` with the host-ink fallback), but `V6Frame` (screen.rs ~l.2928) doesn't report it. A host that draws the prose, the input line or a matching command bar itself must restate that rule (currently: call `story_fg_rgba` and apply the same fallback).
2. Picture indent: `InlineImage::margin_px` — the gap the lib leaves between an inline picture (e.g. Zork Zero's drop caps and room icons) and the text flowing beside it — isn't carried to hosts that lay out the prose themselves, so their text sits at the picture's edge plus a guessed margin.

Change:
- `V6Frame` gains `ink: image::Rgba<u8>` (the resolved story ink, same value the Rasterise path paints prose in).
- Expose `margin_px` wherever an inline picture reaches a host (the InlineImage itself is pub; make the field pub / add an accessor if it isn't, and make sure it survives into whatever a host reads for transcript pictures).

Acceptance:
- Zork Zero r393: `frame.ink` equals the colour of the prose pixels under Rasterise; Amiga Journey r30 likewise (its machine pair).
- A drop-cap picture line reports the same `margin_px` the raster layout uses.
- TUI output unchanged.
