--- note 2026-09-24T04:26:09Z ---

Citations are crates/app/src/ unless stated, as of ca723e44. Goal of this series: an embedding host that is not a terminal (a GUI, a network server, a mobile FFI binding) can boot and play a story through the `app` lib with the same rules the TUI uses, instead of re-implementing them. The TUI must run on the same code, so there is one copy of the rules.

Current state
- bin-only `turn.rs`: `finish_command_turn` (turn.rs:68) echoes the command, pushes the transcript, calls `apply_turn_events` (turn.rs:857; sound + diagnostics), arms the pager (`Pager::arm_after_turn`, pager.rs:134), feeds the mapper, and runs `post_turn_bookkeeping` (turn.rs:446: history, inventory, autosave). `apply_game_driven_result` (turn.rs:902) does the same for char-mode, timer and notify results; `finish_resumed_turn` for resumed input.
- Neither calls crossterm, but both take `&mut AppState` and a `ratatui::layout::Rect` (map_area, used only to recenter the map).
- Map feeding around the pure `session::apply_turn(&mut Mapper, cmd, &TurnResult, &mut DeathWatch)` (session.rs:4103): `random_exit_probe::declared_exit_for_command` (turn.rs:~180), Glulx `take_room_remap` -> `rekey_room`, `rollback_tried_on_death`. The map-changed check compares room/connection counts (turn.rs:469) and bumps `AppState::graph_gen`.
- Sound: the engine reports data (`TurnResult.sounds: Vec<SoundEvent>` with number/effect/volume/repeats/routine, zvm/src/cpu/exec.rs:52; Glulx `glulx_sound_ops: Vec<SchannelOp>`, session.rs:605). Playback happens in `apply_turn_events` via `AppState::play_turn_sounds` / `play_glulx_sound_ops` (state.rs:3977/4049), which open `audio::AudioBackend` lazily. Sound-finished callbacks are polled in main.rs:1767-1824 (`audio.finished()` -> `run_sound_finish(routine)` session.rs:1776, Glulx `sound_notify`/`volume_notify` glulx_session.rs:2102/2113).

Change
- Move these functions into the lib host module from part 1. Replace the `Rect` parameter with an optional recenter hint (or return a "map wants recentering" flag the TUI acts on).
- Introduce a small sound-sink trait the per-turn apply calls instead of playing directly: play/loop/stop/volume of a resource id, plus a way for the host to report "sound N finished" back so the engine callbacks run. The TUI implements it with the existing AudioBackend code; a headless host can record or forward events. No change to what the TUI plays.
- Report per turn whether the pager would arm and whether more is suppressed (`Pager::arm_after_turn`, `should_arm`/`more_suppressed`, pager.rs:229/241), so a host that paginates by its own viewport knows where a pause belongs. `pager::apply_frame` stays render-driven in the TUI.

Acceptance
- TUI unchanged; existing suites pass.
- Headless test: boot Zork I through part 1, submit a scripted walk, and assert the transcript grows with StyleRuns, the Mapper gains the expected rooms, and DeathWatch/rollback behave as in the TUI. Model it on tests/suites/vocabulary_offer.rs:323-345 and declared_exit.rs:34.
- Sound test with a recording sink: a story that plays sounds (skip when absent) yields the same event sequence the TUI would play, and reporting "finished" runs the engine's routine.
