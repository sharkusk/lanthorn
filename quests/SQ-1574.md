Current code (rev 5a31a353), crates/app/src/render/screen.rs — all private:
- `enum BottomPlan { Letterbox, Extend, Menu, Frame }` (l.5678)
- `fn hybrid_bottom_plan(story, gfx, chrome, native, slack, cell) -> BottomPlan` (l.6036)
- `fn menu_strip_below_story(...) -> bool` (l.6122), `fn anchored_band_bottom(...) -> Option<u32>` (l.6192)
- `fn bottom_anchored_chrome(chrome, story, native) -> Option<Vec<usize>>` (l.7214) and `bottom_anchor` after it
- `fn menu_band_runs(runs, story)` (l.7276), `fn menu_band_rows(menu, cell) -> u16` (l.7297)
The TUI's Hybrid uses these to extend every v6 title: Arthur = Extend, Zork Zero/Shogun = Frame (flanks stretch), Journey = Menu (story + chrome top-anchored, the command strip bottom-anchored to the pane, the story filling between; band height = the menu's own rows, SQ-0765/SQ-0754). The only pub path, `compose_v6_frame(layout, want: RasterFrame, inputs)` (l.2970), declines Journey's extension at ~l.3088 via `menu_strip_below_story` — correct for Raster/Extended (one image in game coordinates), but it means a host whose Hybrid draws chrome text itself cannot extend Journey without re-implementing the plan and the flank tiling.

Change:
1. Expose the plan as data: `pub enum V6BottomPlan { Letterbox, Extend, Frame, Menu }` and
   `pub fn hybrid_bottom_plan_for(layout: &V6Layout, native: (u16,u16), cell: V6Cell, slack_native_rows: u32) -> V6HybridPlan { kind, stretch_flanks: bool, band_top_native: Option<u32>, band_rows: u16 }`, using the same art-only obstruction canvas compose builds internally (`build_graphics_canvas(&layout.chrome, native)`), so the host doesn't need it. The TUI's hybrid calls it.
2. A compose path for the Menu plan: e.g. `V6FrameInputs { bottom_anchor_menu: bool, .. }` (or a `RasterFrame` variant) so `compose_v6_frame` grows the canvas, moves the menu-strip windows (runs + their bg blocks + cell grid) down by the extension — as `bottom_anchor` already does for Arthur's window 3 (SQ-1132) — stretches the flanks, and reports `story` filling between. Raster/Extended keep declining as today.

Acceptance:
- `hybrid_bottom_plan_for` returns Menu for Journey r83 (and `Journey - The Quest Begins.adf`), Frame for Zork Zero r393 and Shogun r322, Extend for Arthur r74, Letterbox where the TUI letterboxes — the same answers the TUI's hybrid takes on those screens.
- With the Menu compose path on a tall pane: Journey's canvas grows, the menu runs sit `extension` rows lower at the same distance from the bottom as the game put them from the screen's bottom, `story` fills between, flanks are tiled (no bare page under them); the Raster/Extended compose of the same frame is unchanged.
- TUI hybrid output unchanged.
