  A host whose text cells aren't 8x16 px (proportional-font frontends, or any text size) gets Glk graphics canvases sized in the wrong pixels

--- note 2026-09-26T14:51:13Z ---

Glk graphics windows get a canvas of (window cells × cell px). With no terminal, the cell px is fixed at 8x16 at boot (host/boot.rs:505-518; glk_backend.rs:500 canvas_size), and a host can't change it on boot or on resize. A host whose text cells are another size (for example 10.2x22.95 px at a 17px text size) then gets canvases that don't match their windows. Kerkerkruip shows it: its 224px rule window sits in a 285.6px space, and its 8x672 edge windows sit in 10x963 columns. The host has to stretch every canvas unevenly (1.275x across, 1.43x down), or restate the terminal renderer's thin-window rule, to draw them.

Wanted: a host-facing way to set the cell pixel size Glk graphics windows are measured in, at boot (for example on TerminalFacts or the boot options) and on resize (with set_story_pane or resize_glulx). Changing it should re-size existing graphics canvases and send the game its usual rearrange/redraw events, as a terminal font-size change would. Then a host's canvases match its windows 1:1. Test story: Kerkerkruip (its section rules and panel edges).

--- note 2026-09-26T15:35:50Z ---

Another visible symptom in Kerkerkruip: each section's one-row rule window shows its canvas as a small white box, as wide as the rule, sitting inside the host's taller, wider window. That's the canvas's own background at 8x16-cell size.
