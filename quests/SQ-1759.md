  SQ-1758 marks the typed command with a GLK_STYLE_TYPED_INPUT run (bits, fg, bg, ink) and AppState decides the story's input opinion, which any host gets through finish_command_turn. But the final pick of how that run is drawn lives in render/transcript.rs typed_input_style (private, ratatui Style): theme transcript_input over the line's style unless the story states an input style; colour only under honor_game_colours; on a game-coloured page keep the game's background and fall back to the run's ink when contrast < MIN_INPUT_CONTRAST. A non-terminal host must reproduce that decision to draw the same thing. Wanted, for any embedding host: a public, renderer-neutral resolver, e.g. fn typed_input_colours(run: &StyleRun, theme_input: (Option<fg>, Option<bg>, modifiers), honor_game_colours: bool) -> resolved fg/bg/bits as packed colours or a plain struct, which the TUI's typed_input_style then calls, so both draw a typed command identically. Also the same for the live command line at the inline prompt before Enter, if the TUI styles that too, so the line doesn't change colour when the command is committed.
