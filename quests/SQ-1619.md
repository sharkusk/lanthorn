Today the resume lives in the TUI's event loop: Action::ReplayResume in crates/app/src/main.rs ~4078-4130. Given state.overlays.replay's idx it takes app::history::resume_plan, wraps plan.save in an EngineSave with the engine tag, calls session.restore_state, swaps in the map from plan.map_json, truncates state.history to idx+1, rebuilds the transcript and its kinds (rebuild_transcript), resets transcript_runs/para and sidecars, refreshes seen words, sets state.turns, clears unsaved_progress, invalidates the map render cache (SQ-1544), resets death_watch, re-observes the current location, and so on. A host that isn't the terminal has to copy all of that, and would drift from it.

Ask: move the body into the library as one host function (next to host::persist::load_save), taking the session, mapper, state and the history index, and returning what the caller must still do (e.g. a flag that the screen needs a full redraw). The TUI's arm then calls it. Keep the linear semantics (later turns discarded). Also say in its doc whether the resumed turn should be autosaved immediately, and do the same thing for every host.
Nice to have for a non-terminal viewer: a documented way to list the recorded turns (turn number, command, whether the map changed) and to get the map at a turn (history::map_at_turn exists) without touching AppState internals, e.g. a small read-only accessor over state.history.
