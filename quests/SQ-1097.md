## The mechanism, measured

`cargo run -p app --example flank_shape -- --story <shogun> --cols 60` gives the same
answer on every flavour that extends:

| medium | release | classification | sections |
|---|---|---|---|
| `shogun-r322-s890706.z6` (IBM PC) | 322 / 890706 | `ShogunSinglePiece` | banner 0 rows · **middle 0..400, period 400** · footer 0 rows |
| `James Clavell's Shogun.adf` (Amiga) | 295 / 890321 | `ShogunSinglePiece` | identical |
| `Shogun.toast` (Macintosh) | 292 / 890314 | `ShogunSinglePiece` | identical |
| `Shogun.po` (Apple IIgs) | 311 / 890510 | `None` | art already covers the pane — **unaffected** |

So the user's "all flavors" is right: three of four take one path, and the fourth never
extends.

**`period 400` on a 400-row middle means no sub-period was found** — the unit is the
whole drawing. With `footer_h == 0`, `extend_pillars` runs its bottom-anchored UPWARD
fill:

```rust
let mut y = fill_to;            // the bottom
while y > sec.middle_end {
    let top = y.saturating_sub(uh);
    if top < sec.middle_end {   // gap narrower than a whole copy
        let tail_h = y - sec.middle_end;
        let src_y = if flipped { 0 } else { uh - tail_h };
        stamp(dst, &snapshot(&unit, src_y, tail_h), sec.middle_end, flipped);
        break;
    }
    …
}
```

Extending 400 → 586: `uh = 400`, `y = 586`, `top = 186 < 400`, so the loop takes the
partial-tail branch on its FIRST iteration and never stamps a whole copy at all.
`tail_h = 186`, `src_y = 400 - 186 = 214` — it stamps **the art's own rows 214..400
directly beneath the art**. Art row 399 is followed by art row 214.

That is exactly the reported shape: a single fixed copy of the art at the top, the
extension taken from the bottom of the drawing and anchored to the bottom of the pane,
and a phase jump where the two meet.

## Why no sub-period is found — and it is not a tuning problem

The flank is a vine with `mon` medallions. Measured off a real 100x50 capture
(`shogun-r322-s890706.z6`, hybrid, kitty, 16x32 cell), the dominant vertical period of
the rendered flank is **524 device pixels at 56% row agreement** — 262 native rows at
2.0x. The art is 400 rows tall, so it holds about **1.5 copies of its own motif**.

`flank_sections` requires `len >= 2 * period` — two WHOLE copies — before it will call
a stretch periodic. Shogun's artwork cannot satisfy that at its true period, at any
rendition, ever. It is not that the search is mis-ranked (that was SQ-1094); it is
that the acceptance rule excludes this drawing by construction.

## Was it introduced by SQ-1094? No — SQ-1094 changed WHICH wrong answer it gets

`git diff 664a19f6 91865beb -- crates/app/src/render/v6_border.rs`:

```rust
-  if best.is_none_or(|b| (sect.middle_end - sect.middle_top) > (b.middle_end - b.middle_top)) {
+  let len = sect.middle_end - sect.middle_top;
+  if len >= 2 * period && len >= V6_TEXT_ROW && sect.middle_end + period >= foot
+     && best.is_none_or(|b| len > b.middle_end - b.middle_top) {
-  let periodic = best.filter(|b| b.middle_end - b.middle_top >= 2 * b.period);
+  let periodic = best;
```

The new `len >= V6_TEXT_ROW` clause is the one that reaches Shogun. Before it, Shogun
took an 8-row middle (its lacquer agrees with itself for eight rows in a few places).
SQ-1094's own report records what that produced: *"an 8-row middle leaves no unit at
all once `extend_with_sections` insets it by 4 at each end — `James Clavell's
Shogun.adf` plate 4 composed a 497-row band whose last painted row was 399."*

**So Shogun was already broken, differently**: a degenerate unit producing a band with
unpainted rows, rather than today's phase jump. SQ-1094 did not introduce the defect
and did not regress a working case; it moved the failure from one wrong arm to another.
Worth stating plainly in the fix so nobody reverts SQ-1094 hoping to get Shogun back.

## What a fix has to decide

The interesting question is what to do when **the art holds between one and two copies
of its motif** — enough to know the period, not enough to satisfy "two whole copies".
Options, none free:

1. **Accept a period with 1.5 copies** when the partial copy agrees over its whole
   overlap. Fixes Shogun; loosens a rule that exists to stop a coincidence being read
   as a repeat, so it needs the corpus sweep re-run (Arthur ×6, Zork Zero ×6, Shogun
   ×5, media + plates) to show nothing else changes arm.
2. **Fill downward from the art rather than upward from the bottom** in the
   footer-less case, so the join to the art is continuous and the discontinuity lands
   at the pane's bottom edge where a foot would be. Note `extend_pillars` already
   argues for exactly this in the WITH-footer case (SQ-1063: *"a flipped copy OPENS on
   the row the art CLOSED with, so the shading runs on unbroken"*), and the comment
   claims the footer-less case does not need it because *"a footer-less flank is a
   lattice, which does not mirror and has no join to smooth"* — Shogun is the
   counter-example to that claim and the comment should change with the code.
3. **Both** — (2) makes the seam invisible even when the period is wrong, (1) removes
   the wrong period. (2) alone is the smaller, safer change and probably the one to
   land first.

Check the reference capture before pinning what the extended flank should look like:
`machine-screenshots/amiga-shogun-game.png` is the real machine, and no real machine
had a pane taller than its screen — so it gives the motif and its spacing, not the
extension policy.

## Decided (user, 2026-08-27): option 2 — downward fill, and do not disturb the footer case

> "downward fill is fine. don't break the footer case used for zork-zero"

So the change is scoped to the **footer-less** arm only. The WITH-footer path is Zork
Zero's, it already fills downward for exactly this reason (SQ-1063 — *"a flipped copy
OPENS on the row the art CLOSED with, so the shading runs on unbroken"*), and it is
pinned by `no_tile_join_steps_harder_than_the_pillar_shaft_itself`, which measured a
10.54 step against the shaft's own 5.27 when that parity was wrong. Leave it alone.

Option 1 (accepting a period with only ~1.5 copies) is **not** being taken now. It
loosens a rule that exists to stop a coincidence being read as a repeat, and the
downward fill makes the visible defect go away without touching the acceptance rule.
Shogun will still be extended by a fragment of its own drawing rather than by its true
motif — that is a separate, smaller-value question and can stay filed here as the
remaining half.

What "downward" has to mean concretely: the copy adjacent to the ART is a whole copy
starting where the art's last row leaves off, so the join is continuous; the partial
copy — there will still be one, since 586 is not a multiple of 400 — lands at the
BOTTOM of the pane, where a foot would be and where the eye is least likely to read it
as a break. Today it is the other way round: the partial copy abuts the art and the
whole copies stack beneath it.

Do not "fix" this by making the footer-less arm call `extend_pillars`; that is the
footer path's primitive and routing Shogun through it is how SQ-1094's stray ornament
happened (`footer_h > 0` routing plus `mirror = !periodic` stamped a whole flank
upside down). Change the fill direction in place.
