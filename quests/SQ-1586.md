Current code (rev d7fd62b7). Everything that opens a hint session is bin-only, in crates/app/src/main.rs.

`open_hints` (l.4420-4523):
- loads the hint index;
- calls `hints::resolve_hint_source(story_path, ifid, &index)` (hints.rs:543);
- turns `File` / `ZipEntry` into story bytes (`hints::load_story_bytes` / `hints::read_zip_entry`);
- builds `session::GameSession::new(bytes, config.honor_game_colours, false, config.interpreter_number)`, sets `undo_cap = config.undo_levels`, and works out the label and `builtin_hint` (`hints::story_supports_hint`, hints.rs:445);
- assembles a `state::HintSession`;
- for `AskUser` / `None`, sets status text only ("no hint file found — place <story>.hints.z5 next to the story, or use /hints <path>").

`hint_opening` (l.4401-4410): skips the InvisiClues "your screen is only N characters wide" banner by sending a space when `hints::is_narrow_screen_warning` matches and the VM waits for a key. Gated on `config.hint_skip_screen_warning`.

Callers: main.rs:~4180 (`Action::OpenHints`), slash_dispatch.rs:~558 (`/hints`).

A non-terminal host that wants a hints panel would have to re-implement these ~110 lines.

Also, visibility and opening can disagree. The library scan pairs sidecars with `picker::associate_hint_sidecars` (picker.rs:~1891, `StoryEntry.hint_sidecar`), but opening uses `resolve_hint_source`, which also looks inside zips and the story's own container. So a host can't cheaply tell whether "open hints" will succeed.

Change:
- Add `host::hints::open(story_path, ifid, user_dir/index, &Config) -> Result<Option<HintSession>, HintOpenError>` next to `host/boot.rs`. It resolves, loads and boots the VM, applies the banner skip, and returns the label and `builtin_hint`. `Ok(None)` means there's no hint file; the error carries the TUI's reason text (including `AskUser`).
- Add a cheap `host::hints::available(story_path, ifid, index) -> HintAvailability` that uses the same resolution rule as `open`, without booting.
- The TUI's `open_hints` / `hint_opening` call these.
- Persistence stays as today (the hint VM isn't archived; state.rs:22-27).

Acceptance:
- `zork1-r88-s840726.z3` with `zork1izm.z5` (waitingforgo: the banner is skipped), and `zork2-r48-s840904.z3` with `zork2inv.z5` (SLAG): `available` says yes, `open` boots, and the first screen is the hint menu.
- A story with no hint file: `available` says no, and `open` returns `Ok(None)` with the TUI's message.
- `zork1-invclues-r52-s871125.z5` isn't treated as a hint sidecar (unchanged).
- The TUI's /hints and hint key behave exactly as before.
