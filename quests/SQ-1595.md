--- note 2026-09-26T06:06:37Z ---

When a turn adds text to the story pane, the view jumps straight to the new text, and it's easy to lose your place. The [animation] engine (config.rs:1323 AnimationConfig: enabled, easing, scroll_ms; state.rs:1676 ScrollAnim) already eases list and hint-panel scrolls, but the story pane doesn't ease when new output arrives.

Wanted:
1. The story pane eases its scroll from where it was to the new text over a configurable duration, so the reader sees it move.
2. A new [animation] key for this alone, e.g. follow_ms (0 = instant; pick a sensible default), separate from scroll_ms, so the user's own history scrolling (wheel, keys, drag) behaves exactly as today. It honours enabled = false and the easing key.
3. It works with the pager: the animation runs up to a [more] stop and pauses there, never past unread text. When one turn's output is longer than the pane, define the behaviour (ease to the first page, then [more] as now).
4. User input wins: any user scroll or keypress during the animation cancels it, jumping to the target or stopping where it is (choose one and document it).
5. Embedding hosts can read the setting's value and meaning through the library (the config field, plus a documented rule for when a follow animation applies), so every frontend eases new text the same way from the same config key.
