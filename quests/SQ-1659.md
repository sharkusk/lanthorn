Only now visible on Anchorhead because its "Carrying:" section was always empty before SQ-1655/1657 resolved the avatar. build_inventory_dock_rows already receives &mapper.graph directly (main.rs:763), and the registry record for a carried item already stores the CLEAN name item_tracker_display_name resolved when the item was first observed (via apply_item_observations) — so the likely fix is preferring graph.item(key).name over the live display_name()-derived name when a registry record exists, inside build_inventory_dock_rows/carried_line, rather than threading turn prose into the render path.
