Citations are crates/app/src/ unless stated, as of ca723e44. Goal of this series: an embedding host that is not a terminal (a GUI, a network server, a mobile FFI binding) can boot and play a story through the `app` lib with the same rules the TUI uses, instead of re-implementing them. The TUI must run on the same code, so there is one copy of the rules.

Current state
- `export_svg::render_svg_of(&RenderMap, Option<&MapGraph>)` (export_svg.rs:1952) and `render_svg_layered` (:1985, per layer via `mapper::render::render_layer(graph, l)` at :2017) emit SVG strings. Geometry comes from render/map.rs: `boxes_axes_sized` (:267), `plot_connector` (:1455) -> `ConnectorPlot` whose `path` is already the turning-point polyline for vector output (:1330-1337), plus `random_stub_cells`, `PosTable`, `BOX_W/H`. Those are `pub(crate)`. They take mapper types only, no ratatui Buffer at runtime.
- `export_json`/`mapgen::render_json_view` (mapgen.rs:2158) give grid positions and edges but no boxes or routed paths.
- No change signal on Mapper: the TUI compares room/connection counts (turn.rs:469) and bumps `AppState::graph_gen`, which misses rename, notes, relabel, delete, move_region and tidy. See SQ-0378 for why the current-room refresh must not force a re-route.

Change
- A pub fn (next to `render_svg_body`, export_svg.rs:888) returning, for one layer, the data the SVG is drawn from: room boxes (room id, label, rect in the SVG's own units, flags such as current, has-notes, maze/unvisited as the SVG marks them), connector polylines (endpoints, turning points, one-way/arrowhead ends, labels), up/down/in/out portal markers with destination room and layer, unexplored stubs, and the layer's overall extent. `render_svg_of` should be built on it, so the two cannot disagree.
- A structural generation counter on `Mapper` (or `MapGraph`) bumped by every mutation that changes what is drawn: rooms/connections added, rename_room, set_notes, delete_connection, relabel_edge, rekey_room, move_region, layer rename/view, tidy results applied. Current-room changes are reported separately (`current()`), so moving through known rooms does not force a re-route.

Acceptance
- Test: for a fixture map (e.g. a persisted Zork I walk), every connector and box in `render_svg_of`'s output corresponds exactly to the data fn's output.
- Test: each listed mutation bumps the counter; walking between already-mapped rooms does not.
- Existing SVG export output unchanged byte-for-byte on the export tests.
