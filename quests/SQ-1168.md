## The report, and what it is NOT

User: "are the disk and light bulb icons in the story list BOLD faced? they seem a
little big"

**They are not bold.** Checked: `registry.rs:203` —

    row("story_badge", Section::Elements, Kind::Style, Some("text"), Delta::EMPTY)

inherits `text` with an EMPTY delta, so no modifier is applied. `picker_ui.rs:2044`
reads that style and nothing adds to it.

**The weight is the glyph, not the style.** Material Design Icons are drawn to fill
the em box: `md-content_save` (U+F0193) and `md-lightbulb` (U+F0335) occupy the full
cell height, where the `S` and `H` they replaced under SQ-1159 filled roughly
x-height — about 60% of the same box. Identical cell, far more ink. That reads as
bigger and bolder while being neither.

So the fix is a different GLYPH FAMILY or variant, not a style change. Do not reach
for a lighter colour or a modifier — that treats a symptom and leaves the icon still
filling the cell.

## The constraint that rules most of them out

`HintBadge` has THREE states and two of them draw:

    None       nothing
    Available  a downloadable InvisiClues  -> md-lightbulb_outline  (hollow)
    Present    a hint file on disk         -> md-lightbulb          (filled)

So the bulb needs a **matched filled/hollow PAIR from one family**. That kills
`fa-lightbulb_o` (Font Awesome has exactly one bulb — established and recorded on
SQ-1159, where the user chose to keep the MD pair for precisely this reason), and it
means outlining the "present" bulb would collide with the "available" one.

**Codicons look like the only family that can lighten BOTH while keeping the
three-state distinction** — `cod-save` plus a `cod-` bulb pair, IF one exists. That
is the first thing to check: scan for a `cod-` outline/filled bulb pair the way
SQ-1159 scanned, and if there is none, say so, because it changes the answer.

The floppy has no such constraint — it is one state — so it may take a lighter mark
independently of the bulb if that reads better.

## Settle it by LOOKING

Render the candidates at the size the picker actually draws them and show the user a
comparison strip. SQ-1159 rejected `md-alpha_z_box_outline` **after** its cmap check
passed, because at 12px its stroke was one pixel and the letter inside vanished —
this needs the same judgement, and a name in a table cannot supply it.

Per SQ-1045 every codepoint comes from the font's own `post`/`cmap`, never a cheat
sheet — including the table above, which was scanned but should be re-verified
before shipping.
