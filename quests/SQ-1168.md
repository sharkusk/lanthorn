## The report, and what it is NOT

User: "are the disk and light bulb icons in the story list BOLD faced? they seem a
little big"

**They are not bold.** Checked: `registry.rs:203` —

    row("story_badge", Section::Elements, Kind::Style, Some("text"), Delta::EMPTY)

inherits `text` with an EMPTY delta, so no modifier is applied. `picker_ui.rs:2044`
reads that style and nothing adds to it.

**The weight is the glyph, not the style.** Material Design Icons are drawn to fill
the em box: `md-content_save` (U+F0193) and `md-lightbulb` (U+F0335) occupy the full
cell height, where the `S` and `H` they replaced under SQ-1159 filled roughly
x-height — about 60% of the same box. Identical cell, far more ink. That reads as
bigger and bolder while being neither.

So the fix is a different GLYPH FAMILY or variant, not a style change. Do not reach
for a lighter colour or a modifier — that treats a symptom and leaves the icon still
filling the cell.

## The constraint that rules most of them out

`HintBadge` has THREE states and two of them draw:

    None       nothing
    Available  a downloadable InvisiClues  -> md-lightbulb_outline  (hollow)
    Present    a hint file on disk         -> md-lightbulb          (filled)

So the bulb needs a **matched filled/hollow PAIR from one family**. That kills
`fa-lightbulb_o` (Font Awesome has exactly one bulb — established and recorded on
SQ-1159, where the user chose to keep the MD pair for precisely this reason), and it
means outlining the "present" bulb would collide with the "available" one.

**Codicons look like the only family that can lighten BOTH while keeping the
three-state distinction** — `cod-save` plus a `cod-` bulb pair, IF one exists. That
is the first thing to check: scan for a `cod-` outline/filled bulb pair the way
SQ-1159 scanned, and if there is none, say so, because it changes the answer.

The floppy has no such constraint — it is one state — so it may take a lighter mark
independently of the bulb if that reads better.

## Settle it by LOOKING

Render the candidates at the size the picker actually draws them and show the user a
comparison strip. SQ-1159 rejected `md-alpha_z_box_outline` **after** its cmap check
passed, because at 12px its stroke was one pixel and the letter inside vanished —
this needs the same judgement, and a name in a table cannot supply it.

Per SQ-1045 every codepoint comes from the font's own `post`/`cmap`, never a cheat
sheet — including the table above, which was scanned but should be re-verified
before shipping.

## Keep

Whatever is chosen goes in the `badge_icons` nerdfont preset (SQ-1159), with the
per-slot `badge_*` keys still overriding it — that structure is settled and the user
confirmed its purpose is per-state override. Do not restructure it.

Trailer `Confirm:` — a glyph weight is a look.

## Done on `worktree-agent-a01f1cf28ca8ffdca` (43305b29) — awaiting the user's eye

### The codicon question, answered first, and it changes the answer

**There is NO `cod-` filled/hollow bulb pair.** Codicons carry exactly two bulb
glyphs and neither is the other hollowed:

    cod-lightbulb            U+0EA61   a solid bulb
    cod-lightbulb_autofix    U+0EB13   the SAME solid bulb with a gear beside it

Read from the font's own `cmap` by enumerating every `cod-` glyph whose name
mentions a bulb or a light, in all nine patched families. So Material Design is
the only family in the patched font with a matched pair at all — Font Awesome has
one bulb (`fa-lightbulb_o` U+0F0EB, SQ-1159), Octicons one (`oct-light_bulb`
U+0F400), Codicons one. The hint slot keeps MDI by elimination, not by preference.

That is a pity, because `cod-lightbulb` is **the lightest bulb in the font** —
12x17px against MDI's 16x23 — and the closest of any to letter size. It is
unusable here anyway: `Available` would then differ from `Present` by COLOUR
alone, the SQ-1148 degradation accepted only where the font offers no off-shape,
and this font does offer one.

### What was actually wrong — measured, not guessed

Face and size are the gallery's own (Fira Code Nerd Font Mono at 26 px/em in a
16x32 cell — what `Face::outline` picks for the shots the report was made
against). Cap height there is 18.4px:

| mark | ink | vs cap |
|---|---|---|
| `S` `H` `h`, the letters these replaced | 13x19, 12x18, 11x20 | 1.00 |
| `md-lightbulb` / `_outline` (was) | **16x23** | **1.25** |
| `md-content_save` (was) | 16x16, solid | 0.87 |
| `md-content_save_outline` (now) | 16x16, hollow | 0.87 |
| `md-lightbulb_on` / `_on_outline` (now) | 16x16 | 0.87 |

Two different faults with one report. The **bulb** overshot the letters beside it
by a quarter — it is the only mark in the set taller than cap height. The
**floppy** is not tall at all; it is solid ink across the full advance width,
where an `S` has side bearings on both sides. "A little big" was both at once.

Nerd Fonts normalises each icon against its own artwork's bounds, so glyph size
here is a per-GLYPH fact and not a per-family one: every save candidate in every
family measures 16x16 (there is no lighter floppy to be had by changing family,
only a hollower one), while the `_on` bulbs come out smaller than the plain bulbs
precisely because their rays are counted into the box being normalised.
