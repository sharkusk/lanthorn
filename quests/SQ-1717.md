  An embedding host can load an Infocom game that is not a known release: a build compiled from the publicly released ZIL source (Zork I, II, III under MIT since 2025) gets ZCODE-0-<build date>, and a rare or beta release may simply be missing from known_titles.tsv. Today hint_download_for() and hint_matches_identity() (crates/app/src/hints.rs) resolve a game key only through crate::session::known_title(ifid), so such a story offers no InvisiClues download and a matching zork1inv.z5 in its documents folder is not recognised, even when the story is linked to the game's IFDB page (fetch_by_id / a user relink). Ask: when the IFID is unknown but the story carries an IFDB page id (tuid), resolve its canonical title from that tuid: e.g. a small tuid->title table beside known_titles.tsv for the Infocom games (Zork I = 0dbnusxunq7fw5ro), consulted by known_title-style lookup, and an entry point that takes the tuid alongside the IFID so hint download, hint-file matching and anything else keyed on identity work. Keep the existing rule: never fall back to a filename or a displayed title; an IFDB link is identity the user or host asserted, not a name match.
