## What the capture already settles

* **`win0`'s WRAP BIT IS CLEAR.** `attrs=1110` — bits 3, 2 and 1, with bit 0 (wrapping, ZMSD §8.8.3.2 property 14) **off** — and the flags line reads `[scroll transcript buffered]` with no `wrap`. That is very likely the whole of the "does not wrap" half: the game withdrew wrapping for the clue window and the text runs to the screen edge because nothing is bounding it. Check what the real machine does here before "fixing" the wrap — `machine-screenshots/` is the falsifier, and a clue that runs off the edge on the Amiga would be the game's own behaviour, not ours.
* **`model: Grid — 5 run(s)`, not a `Buffer`.** So on this frame the story slot holds a GRID, which is SQ-1026's promoted-middle shape — and the guard added there makes the RASTER path ship the frame with no prose at all. That is a concrete link to SQ-1056 and SQ-1069 and should be checked first.
* **The hybrid "narrow centre column" is the viewport**: `story viewport 102x53 at (16,8)` inside a 132x60 pane, with `cells: 104x31 at (15,7) as grid`. The clue is being drawn into window 0's own 500x330 box at native (70,70) — the hint menu's box — rather than across the screen.
* **The flanks are tiled from a 73x655 source on a 400-px-tall frame**, which is SQ-1063's defect on this same press. Expect the two to travel together; fix SQ-1063 first so its noise is out of the picture.

## The three symptoms, and which look separable

1. **raster: no wrap, text off the right edge** — likely the clear wrap bit above, plus whatever SQ-1026's guard does to a Grid story slot.
2. **hybrid: only a centre column used, not wrapped** — the viewport is that column; the question is whether the clue window's box is what the game asked for.
3. **a black box on the SECOND viewing** — a repaint/erase question, and the one most likely to be its own defect. SQ-1054's `erase_blank_cells_in_rect` ground rule is the neighbour to read.

## Root-caused: the wrap failure is ONE over-long paint run, and it is an ENGINE defect

Reproduced on the reported press, `stories/James Clavell's Shogun.adf` — Amiga,
**release 295 / serial 890321** — booted the way `startup.rs` boots and driven
`hint`, `y`, Return ×3 after 14 intro taps. The frame matches the reporter's dump
exactly (`w0 500x330 at (71,71)`, `attrs=1110`, 5 paint runs) and the runs are:

```
run @(  71,  71) w=   8  \"6\"
run @(  79,  71) w=  16  \"> \"
run @(  95,  71) w= 544  \"You have to do everything you can to keep your ship from sinking bef\"
run @(  71,  87) w=   8  \"5\"
run @(  79,  87) w=  16  \"> \"
```

95 + 544 = **639**, one pixel short of the 640-px screen and 69 px past window 0's
own right edge at 570. The clue is cut mid-word at `bef` because 68 characters is
what fits between the cursor and the SCREEN edge. Symptom 1 (\"renders off the
right side of the screen\") is therefore not a render defect at all — hybrid and
raster are both faithfully drawing one paint run the engine made too wide, which
is why neither path gets it right.

Traced: the game itself issues `@window_style(win=0, flags=0b0001, op=2)` —
clear wrapping — before printing. lanthorn honours that; **the real Amiga
interpreter does not read the bit at all.** The whole of that is SQ-1071, which
carries the ZMSD quotations, Infocom's own per-machine behaviour table, and the
order of work. **Fix SQ-1071 first; symptom 1 goes with it.**

## Correction to this quest's first note

It read `attrs=1110` as \"bit 0 clear, very likely the whole of the 'does not
wrap' half\" and said to check what the real machine does before fixing the wrap.
Both halves were right, and the check has now been made: §8.8.3.1.2.2's
commentary table says the Amiga IGNORES attributes 0 and 3 and word-wraps under
`buffer_mode on`, which is the default. So the clue wraps on a real Amiga.

It also said `model: Grid` makes this SQ-1026's shape and links it to SQ-1056 and
SQ-1069. The Grid reading is correct and the raster path does ship no prose here —
but the link is not what it looked like: SQ-1056 and SQ-1069 both keep `win0` a
primary `Buffer` throughout, and **neither reproduces headlessly at all** (see
their notes). This quest is an engine defect; those two are below the model.
