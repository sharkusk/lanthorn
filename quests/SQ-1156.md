## Lane A — reproduced and fixed; it is SQ-1022's shape one layer DOWN (2026-08-30)

Commit `fafa07f4` on branch `worktree-agent-a4031224e1d6e61af`, `Confirm: SQ-1156`.

### Not `reset.rs` — `Machine::restart`

The repro is the game's own `@restart` opcode, which never reaches `reset.rs` at
all (that is the host `/restart`). `reset.rs` was already correct. The same class
of defect lives in `zvm::cpu::exec::Machine::restart`, which destroys two host
declarations and restated neither. SQ-1154's note pointed straight at it: a fresh
`ScreenState` is assigned, so anything living there is silently reset.

### Reproduced

`Arthur - The Quest for Excalibur.adf` (r54/s890606), booted the way `startup.rs`
boots — profile off the medium, `native_font::resolve`, `MachineBoot::resolve` —
hybrid at 80x25, fifteen intro taps and a `look` either side of `restart`/`y`:

    LAUNCH        win0.font_size=0x1408  win0=584x180
      13|      Churchyard                St Anne's Day, Compline
    AFTER         win0.font_size=0x1008  win0=584x192
      13|    ▄▄▄▀▀▀▀▀▀▀▀▀▄▀▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▀▀▀▀▀▄…

The bare `arthur-r74-s890714.z6` does NOT reproduce, and cannot: its declared cell
is the 8x16 the pristine header already carries, so there is nothing to lose. Only
a press whose cell differs — the Amiga floppy's release face (8x20, SQ-1009) or a
Macintosh (7x15, SQ-0917) — can show it.

### Mechanism, measured not inferred

`self.v6_metric` is a field on `Machine` and survives. The two OTHER places
`set_v6_text` writes the cell do not:

* the fresh `ScreenState` seeds every window's `font_size` (property 13) from the
  header, and
* the header itself was just reloaded to the story's pristine image.

So after a restart the machine said 8x20 and the windows said 8x16. Stories read
property 13 for their layout math — `boot_state_and_screen` says so in its own
note — and Arthur laid his score bar out on a 16-row line the host was not drawing
on. Hybrid draws a strip with glyphs only while the game's own runs explain it
(CLAUDE.md, "never rasterise what the game printed as a character"); runs off the
cell boundary do not, so the classifier fell through to the ring.

`restart` now clones `self.v6_metric` and calls `set_v6_text`, which restates all
three.

### A SECOND fact, found by reading and then measured — the Macintosh half

`restart` preserved `$20`/`$21` and called `set_screen_dims`, reconstituting the
v6 screen from the CHARACTER GRID. Exact only while the cell divides the screen,
which is precisely the loss `set_v6_screen_px`'s own doc spells out. Measured at
7x15:

    launch        px($22x$24)=640x400   grid=91x26
    after restart px($22x$24)=637x390   grid=91x26

The v6 screen is now preserved and restored in the pixels it was reported in.
Nobody reported this half — it came out of driving the cell across three presses
after the Amiga symptom was understood, the same way SQ-1154's Macintosh half did.

### Verification, at both layers

* `cpu::exec::tests::v6_restart_redeclares_the_hosts_cell_and_keeps_the_screen_in_pixels`
  — 8x20 and 7x15, asserting the metric, header `$26`/`$27`, property 13 and the
  pixel screen. FALSIFIED two ways: dropping `set_v6_text` gives `0x1008` on both
  cells; disabling the pixel branch gives `(637, 390)`.
* `v6_arthur_amiga_proportional::the_score_bar_comes_back_as_cells_after_an_in_game_restart`
  — the floppy, turn count named, asserting the rebooted frame IS the launch frame,
  with a non-vacuity guard that the declared cell is 8x20 rather than the pristine
  8x16. FALSIFIED: the post-restart frame carries no `Churchyard` cell text at all,
  which is the reported symptom verbatim.

### Worth knowing for the next reader

`docs/zvm-embedding-review.md` §1 already flags that the workspace's two embedders
answer `StepResult::Restart` differently and that `zvm` "never expressed an
opinion". This is the same gap seen from inside: `restart` had no single place
saying which host declarations a reboot must restate, so they were restated one at
a time as each was missed. A `BootConfig`-shaped answer (§3 of that review) would
close the class rather than this instance.
