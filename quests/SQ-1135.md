## The user's framing, which is the whole quest

> "the point of this is not to only show objects that have specific attributes. If
> anything that narrows things too much. Rather any objects/nouns the game 'knows'
> should be available to allow the user to explore as wide as possible."

The assist set exists to make interactive fiction less frustrating for players
without nostalgia for it. A scope walk that under-reports serves correctness and
works against that goal.

## The rule: annotate by vocabulary, offer by scope

Two surfaces, and they want different tests. Conflating them is the defect.

**The reveal — words in text the story ALREADY PRINTED.** The test is *"does the
game know this word?"*, answered by the dictionary. No scope walk, no openness
attribute, no inference. Arthur printed "the crystal imbedded in the torque's
knob" on the player's screen; lighting a word already visible reveals nothing
that has not been told, so there is no spoiler to defend against and no reason
for a conservative test. A description that names a sword sitting in another room
lights it too — confirmed as intended.

**The band's noun column — words the player has NOT necessarily seen.** Here we
are proposing rather than annotating, so a boundary is real: the flat dictionary
is hundreds of words including objects from rooms never entered, useless as a
list and genuinely spoiling.

## The inversion found while scoping this

**The engine with the MOST introspection offers the LEAST vocabulary.**

`command_band`'s `None =>` arm — the fallback for an engine with no live object
tree — reads `state.seen_words`, the words the story has printed. The Z-machine
arm uses the object tree instead, and *only* the object tree. So a Glulx story
offers everything the story printed while Zork I and Arthur get scope-only.

That, not depth and not `infer_open_attr`, is why the Arthur crystal is missing
from the band. Having a real object tree made that path look authoritative enough
to use alone.

## The three tiers, two of which already exist

| tier | source | today |
|---|---|---|
| in the room / in hand | `state.scope_words` | live; SQ-1133 widened it to an opened container in hand |
| printed on screen | `state.seen_words` | **slides**, and non-Z-machine only |
| the flat dictionary | `state.dict_words` | Tab completion only, which is correct |

Tab completion already runs all three (`input.rs`, the `suggest` call site). The
band does not.

## The work

1. **`refresh_seen_words` must accumulate.** It currently does
   `state.seen_words = words` over `recent_transcript_text(state)` — a sliding
   window, so a word scrolls out of the list as the transcript moves on.
2. **The Z-machine band reads scope AND seen**, not scope alone.
3. **The reveal annotates by vocabulary**, dropping its scope test entirely.

## Persistence: nothing new is persisted — this is the recipe/result rule

Decided with the user. `seen_words` must be **derived from the whole restored
transcript**, not stored beside it.

The archive already carries the full transcript, and a restore replaces it
wholesale exactly as `*mapper = ac.mapper` replaces the map. So deriving the word
set from it gives, for free:

* accumulation within a session — the transcript grows;
* **per-save semantics on restore** — the transcript is replaced, so restoring to
  before the crystal was read takes the word away again, which is the correct
  answer and was the user's own observation;
* nothing new in the archive.

Adding a `seen_words` field would store a derived result beside the input it comes
from — the exact hazard `ArchiveContents` warns about two fields below `mapper`,
where `paint_ground` must RESET when absent so "a restore must not leave the
pre-restore surface standing".

Implementation consequence: accumulate incrementally per turn over new lines
(tokenise + dictionary lookup is the cost), and rebuild from scratch at the one
place the transcript is replaced — restore.

## Relationship to SQ-1134

**This demotes SQ-1134 rather than replacing it.** With the reveal annotating by
vocabulary and the band reading `seen_words`, `infer_open_attr` stops being what
blocks the user's reported Arthur crystal. SQ-1134 remains a real correctness
question about the scope WALK — an opened container's contents should be in
`scope_words` — but it is no longer urgent and no longer gates a user-visible
defect.

Also related: [[SQ-1107]], whose persistent-highlight redesign is the surface this
rule applies to, and SQ-1133, which built the single `scope_split` spelling that
tier 1 reads.
