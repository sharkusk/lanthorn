--- note 2026-08-24T22:10:25Z ---

THE COMMENT. `crates/app/src/session.rs:3057-3059`, opening `v6_screen_model`:

    // SQ-0917: the session's own cell, which every native-pixel-to-cell step
    // below divides by. **The engine placed these runs with it, so the model has
    // to recover them with the same number.**

True of the DIVISIONS. Not true of the run EXTENT, which the engine places with the pen.

BOTH SIDES.

  MEASURE — crates/app/src/session.rs:3185, building the retired ("frozen") prose entry's box:
      for t in &win.retired {
          let w = (t.text.chars().count() as u16).saturating_mul(font_w);
          ...
          rx1 = rx1.max(t.x.saturating_sub(1).saturating_add(w));
      }
      ... w_px: rx1 - rx0,
  `chars * cell.w` — which is exactly `V6Cell::run_px` (crates/zvm/src/screen.rs:2587), documented there as "the pixel width the STORY believes `s` occupies ... **uniform on purpose, even for a machine that painted proportionally**".

  DRAW — crates/app/src/render/v6_layout.rs:1627-1628, `build_chrome_canvas`:
      let bound = (tf.proportional() && (it.w_px as i16) >= 0)
          .then(|| (ox + it.w_px as u32).saturating_sub(u32::from(it.right_margin)));
  and the glyph loop below breaks on `pen + tf.advance_styled(ch, t.style) > right`. So the synthesized `w_px` becomes the PEN's clip bound. `fill_explicit_bg_rows(&mut canvas, &px_texts, ox, it.w_px as u32, ...)` at v6_layout.rs:1645 floods to the same short width.

WHY THIS ONE IS DIFFERENT FROM ITS NEIGHBOURS. For an ordinary window `w_px` is the game's own `x_size` — the box the game reserved — and bounding the pen by it is deliberate and correct (the SQ-1009 comment two dozen lines above says so). The RETIRED entry has no game-declared box; session.rs synthesizes one, and its own comment at session.rs:3178 says what it is meant to be: "The entry's BOX is **the frozen prose's own extent**, not the window's". On a proportional face the prose's own extent is the pen's, not `chars * cell.w`. Intent and implementation disagree.

MAGNITUDE. Arthur's Amiga floppy is the proportional press: the release face advances about 10.4 native px against a declared cell of 8, so the synthesized box under-measures the run by roughly a quarter and the tail of every frozen line falls outside the bound. Every fixed-pen machine is byte-identical, since `V6Metric::advance` returns `cell.w` for every style on a fixed pen (crates/zvm/src/screen.rs:2740-2755) — which is why this survived.

THE FIX IS AVAILABLE, WHICH IS WHY IT IS AN OMISSION. `self.machine.v6_metric` is a public field (`crates/zvm/src/cpu/exec.rs:237`) and `V6Metric::run_px(s, style)` (`screen.rs:2759`) is the pen's answer, already in scope at session.rs:3185. Every other extent on this path uses the drawn measure — `tf.run_px_styled(&t.text, t.style).max(font_w)` at v6_layout.rs:763, 1140, 1259, 1303 — so this is the copy the SQ-1054 sweep did not reach.

CONFIDENCE. High on the split; the two expressions are unambiguous and one is documented as deliberately not the other. NOT exhibited on a real frame: reaching it needs a proportional press AND retired prose in the same window (the SQ-0697/SQ-0890 freeze), and I did not establish that Arthur's Amiga floppy produces both together. Settling it: boot `stories/Arthur - The Quest for Excalibur.adf`, reach a frame with frozen prose, and compare the model's `w_px` for the retired entry against `tf.run_px_styled` over the same runs — a mismatch is the defect, no rendering needed.
