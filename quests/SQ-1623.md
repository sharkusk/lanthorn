Follow-up to SQ-1620 (720be81d). Rewritten 2026-09-27: this first asked for the pane-aware raster-fallback reason; the ask is now an opt-in that keeps the Hybrid placement instead.

Today: at an upscaling pane where a story-slot Grid is wider, in its own native columns, than the ring's viewport (Zork Zero Amiga InvisiClues: 58 columns into 41; Shogun r322 / Amiga: 62 into 45), story_slot_grid_wider_than_viewport (crates/app/src/render/screen.rs ~7692) makes hybrid_chrome_layout and hybrid_story_slot_grid answer None and routes the terminal to the raster composite. That is right for a terminal, which cannot draw one window's text in a smaller cell. A host that draws text itself (a browser or native UI) can: it can set that grid's text at whatever size makes the grid's columns fill the viewport, keep the frame Hybrid (crisp text over the ring's art), and show every column. But with None it gets neither the ring nor the grid's placement. It also can't tell why: hybrid_bottom_plan_for (~7371) takes no pane, so its raster_fallback never reports this reason, and hybrid_raster_fallback_reason (~7425) is private.

Ask: an opt-in for such a host (for example a flag on the inputs these functions already take, like V6FrameInputs::extend_flanks_under_story_grid from SQ-1618) under which:
- hybrid_chrome_layout still returns the ring for this frame;
- hybrid_story_slot_grid still returns the viewport and the whole grid (all its columns, not clipped to the viewport), plus a flag or the grid's native column count so the host knows it's wider than the viewport and by how much;
- the frame is not routed to the raster composite for this reason.
Without the opt-in, nothing changes: the terminal keeps its SQ-1620 raster fallback. Clicks: the ring's click map for the grid should map to the grid's own columns so a host that shrinks the text can map a click back (or say how a host should).

Repro: Zork Zero Amiga ADF, hint, y; Hybrid at a 59x51-cell pane with a 20x44 px cell (scale >= 1).
