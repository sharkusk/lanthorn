Follow-up to SQ-1620 (720be81d). story_slot_grid_wider_than_viewport (crates/app/src/render/screen.rs ~7692) and hybrid_raster_fallback_reason (~7425) are private. A host plans a frame with the public hybrid_bottom_plan_for (~7371), whose raster_fallback can't see this reason because it takes no pane or cell size (by design, per the SQ-1620 doc). So on Zork Zero Amiga / Shogun InvisiClues at an upscaling pane narrower than the grid, a host gets None from hybrid_chrome_layout and hybrid_story_slot_grid but no reason to fall back: if it trusts the plan it draws the frame as Hybrid with nothing placing the grid's text (worse than the old clip). The only way to know today is to infer it (both None, story slot is a Grid, plan didn't fall back), which breaks if another None reason is ever added.
Ask: a public, pane-aware answer, for example a hybrid_bottom_plan_for variant that takes the pane and cell size and reports raster_fallback = Some("grid_wider_than_viewport"), or making story_slot_grid_wider_than_viewport public with the same inputs hybrid_story_slot_grid takes. The terminal's own dispatch and the host should get the same reason from the same function.
Repro: Zork Zero Amiga ADF, hint, y; Hybrid at a 59x51-cell pane with a 20x44 px cell (scale >= 1).
