Follow-up to SQ-1694/SQ-1696, for a host that runs hint sessions through host::hints::start (not the TUI's Hints tab):

1. Starting: hints_tab::start_download_in decides "This story already has a hint file" from HintsTab::phase == Running, which only ensure_started_in maintains, and that needs the TUI's split layout and Hints journal tab. A host must set phase by hand. Proposal: host::hints::start_game_download(downloader, story/state, documents, session_running: bool) -> String, or a `running` parameter on start_download_in.
2. Results: hints_tab::poll_download drains the HintDlResults internally, so a host cannot fold an in-game download into its own story list with picker::apply_hint_download as the story browser does. Proposal: return the drained results (or a variant that does).
3. Offer: whether the tab offers "Download hints" (no hint file resolves and hint_download_for(ifid) is Some) is decided in the tab's drawing code; a host repeats it. Proposal: a host-level fn returning the in-game hint status (available / choose / downloadable / none), mirroring picker::hint_status for a running game.
4. Optional: split hints_tab::CHOOSE_INTRO into the prompt ("Several hint files could be this game's — pick one") and the TUI's key help, so a host with click/touch input can reuse the prompt.
