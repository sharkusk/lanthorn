Current code (rev a64394b5):
- crates/app/src/styles.rs:180 `PerGameConfig::write` builds the file from scratch out of its known fields (honor_game_colours … quick) and `std::fs::write`s it, so any other key or table in `<game>.save/config.toml` is silently dropped on every write — including writes from the TUI's own toggles (`edit()`, styles.rs:~238, used by every `write_per_game_*`).
- When no known field is set it deletes the file outright (styles.rs:~223), again losing anything else in it.
- `read` (styles.rs:134) already parses the file as a generic `toml::Value` and ignores keys it doesn't know, so reading is fine; only writing loses data.
- Contrast: the global config's `write_config_at` already keeps unknown keys and comments (read-modify-write).

Why: a non-terminal embedding host has per-story settings of its own that lanthorn has no use for (e.g. a proportional story font or text size). The natural home is the same per-game sidecar, next to the per-game settings the host already shares with the TUI, under a host-owned table. Today the first TUI toggle for that story (or any host write through `PerGameConfig::write`) erases them.

Change:
- `PerGameConfig::write` becomes read-modify-write: known keys are set/removed as now; unrecognised top-level keys and tables (e.g. `[host.<name>]`) are left exactly as they were (a `toml_edit` document, as the global writer does, keeps order/comments too).
- The file is deleted only when nothing at all is left in it — known or unknown.
- Document the rule in the sidecar's doc comment: lanthorn ignores keys it doesn't know and never removes them; a host should namespace its own under a table so they can't collide with future lanthorn keys. Optionally reserve a convention (e.g. `[host.<name>]`).
- Optionally a tiny helper for hosts: read/write one table by name in the sidecar (`read_host_table(game_dir, name) -> Option<toml::Table>`, `write_host_table(game_dir, name, Option<Table>)`), going through the same writer.

Acceptance:
- Test: a sidecar containing `guidance = true` plus `[host.example] font = "Serif"` → a `write_per_game_guidance(dir, Some(false))` keeps the `[host.example]` table byte-for-byte and flips guidance.
- Test: clearing every known key leaves the file (with only the host table) instead of deleting it; clearing everything deletes it as today.
- Test: an unknown top-level key survives too.
- Existing styles/per-game tests pass; TUI behaviour unchanged.
