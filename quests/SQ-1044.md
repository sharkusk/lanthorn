## The cheapest idea in the set

We already retain the whole transcript — `state.transcript` plus four parallel
sidecars (`_styles`, `_runs`, `_para`, `_images`), never truncated except at a
clear-screen anchor or a rewind. So "when did I last see the sceptre?" is a search
over data we are already holding, not a feature that needs new state.

What it buys: the thing a player actually loses in a long session is not the map —
the automap has that — it is the PROSE. Where was the inscription? Which room
mentioned a draught? What did the thief say? Scrolling back through several
thousand lines is exactly what a computer should be doing instead.

## Notes

* **SQ-1033 measured the cost of holding it.** 17.7 MB of transcript at 20,000
  turns on the cell path, growing linearly, and every frame currently re-wraps the
  whole thing. Search should read the LOGICAL transcript, not the wrapped product —
  and if SQ-1034's incremental wrap lands first, be careful not to build a second
  consumer that forces the full wrap on every keystroke.
* **Room attribution is nearly free.** The mapper already knows the location per
  turn, so a hit can say WHERE as well as WHEN, and jump the map there. That is
  the difference between grep and something worth having.
* **`line_starts` already maps logical lines to wrapped rows**, which is what a
  result needs to scroll to.
* Filter by `TranscriptKind` so a search does not return our own status lines
  alongside the story's prose.

No spoiler risk at all: it can only find what the player has already been told.

Related: SQ-1033 (what the transcript costs), SQ-1034 (the wrap that will own it),
SQ-0410 (streaming the transcript to a file, the accessibility sibling).

WHAT EXISTS on `main` at 74e5ac5c:

- `slash::COMMANDS` carries `search-transcript` ("search the transcript; no query
  repeats the last search") and `filter-transcript`, both under `Category::Transcript`.
- `slash_dispatch.rs:456` runs `state.run_search(&query, config.search.start_backward)`,
  reports a match count, holds `search_query`/`search_matches`/`search_idx` for
  repeat-and-step, and scrolls the pane to the current hit via `scroll_for_match`.

**It avoids this quest's own stated trap.** The search reads
`visible_transcript_indices()` — the LOGICAL transcript — not the wrapped product,
so it does not force a full re-wrap per keystroke. That was the note's central
warning after SQ-1034's incremental wrap landed and SQ-1033 measured the transcript
at 17.7 MB by 20,000 turns.

NOT SHIPPED, and recorded here rather than left to be rediscovered: the note's
"room attribution is nearly free" idea — the mapper knows the location per turn, so
a hit could say WHERE as well as WHEN and jump the map to it. The note called that
"the difference between grep and something worth having". The shipped search is the
grep half.

That is deliberately NOT filed as its own quest: it is an enhancement to a working
feature, not an outstanding defect, and filing it would leave an orphan open. If
the user wants it, it is a small quest with the design already written above.
