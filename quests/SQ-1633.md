--- note 2026-09-28T04:39:17Z ---

Several library files can hold the same story release: Zork I r88 on Amiga, Atari ST, Mac and PC disks, plus the bare .z3. They share one save folder (storage::game_dir by story key), which is right: the save is compatible. But archive::Meta (crates/app/src/archive.rs ~279) records ifid, name, turns, saved_at, location, score and trigger, not which copy was played. A host listing a player's games in progress can only show 'some copy of Zork I', so it either lists every copy (five cards for one game) or guesses; it can't badge the copy the player chose or offer 'continue on another version' with that machine's look.
Ask: record the source of the story the session was booted from in each save's Meta (serde default for old saves), e.g. the story file's path relative to the library root (or its file name), the disk-image entry if any, and the machine (blorb::medium::Machine) or none for a bare file, written by every save path (auto, quick, named, exit). Publish a way for a host to read it (read_archive_meta already returns Meta). The terminal could use it too, e.g. to say which version a resume will open.
Tests: boot the same release from two copies (a disk image and the bare file), save from each; each save's Meta names its own source; an old save without it still loads.
