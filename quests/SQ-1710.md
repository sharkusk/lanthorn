--- note 2026-10-03T19:39:19Z ---

After a host restore (host::persist::load_save: Save State/Restore State, and the other restore paths), AppState::current_room_name keeps the pre-restore room until the next turn, because only host::turn sets it (crates/app/src/host/turn.rs ~1121). Any embedding host showing it as the current location shows the wrong room, and so does a save summary made right after the restore (engine_helpers.rs ~119 save_summary) — the TUI too. Seen with Adventureland: status said 'dismal swamp' while the engine/map were at 'damp hollow stump'. Proposal: load_save (and the other restore paths) set current_room_name from Engine::current_location() after restoring.
