--- note 2026-10-01T06:34:01Z ---

Root cause confirmed by reading the code: `reset_game` (crates/app/src/host/reset.rs:38) never receives `arc_file` (the Save State autosave archive, `default.lanthorn`, per the `arc_file = dir.join("default.lanthorn")` pattern in slash_dispatch.rs's own tests) as a parameter at all — confirmed at both call sites, crates/app/src/main.rs:2694 and :2709, neither passes it. When `delete_data` (the "Delete saved progress" checkbox, `state.overlays.reset_delete_data`, state.rs:2512) is true, the only thing actually deleted is `crate::storage::delete_auto_persistent(game_dir)` (storage.rs:67), which by design and by its own test (`delete_auto_persistent_removes_only_defaults`, storage.rs:280) deletes ONLY `default.glkvfs`/`default.aux`/`default.lanthorn`/`default.pcs`... 

CORRECTION while writing this up: `default.lanthorn` IS in `delete_auto_persistent`'s delete list per storage.rs:68 — but the TEST at storage.rs:291 lists `"myslot.lanthorn", "quick.qzl", "_autosave.qzl"` as things that must SURVIVE, which are differently-named files, not `default.lanthorn`. Need to verify precisely which filename `arc_file` actually resolves to for a real game_dir (likely NOT literally "default.lanthorn" — that may be a test fixture name) before concluding whether `delete_auto_persistent`'s list already covers it or not. A fix lane must read `arc_file`'s real construction (probably in startup.rs or wherever `arc_file`/`ifid` get built from game_dir) to settle this precisely — do not assume either way.
