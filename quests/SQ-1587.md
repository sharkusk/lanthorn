--- note 2026-09-25T21:21:40Z ---

Current code (rev d7fd62b7): crates/app/src/state.rs:~5394, `AppState::push_assist`:
`self.push_transcript_internal_styled(&line, …); self.assist_intro_line = Some(self.transcript.len() - 1);`

In inline-prompt mode (`command_bar = false`, lanthorn's default), `push_transcript_internal_styled` **inserts** the line above the trailing game `>` (`insert_above_prompt_at`, SQ-0270), so `len() - 1` is the prompt line, not the intro. The offer lines are then inserted above the prompt too, so the recorded index lands on the first offer line.

Effect for a host that reads `assist_intro_line` (SQ-1557): with Zork I, "illuminate lamp", the intro line arrives unmarked, and the "try instead — light" line is reported as the intro, so its offer structure is lost. With `command_bar = true` (append), it's correct. The TUI doesn't read the field, so nothing shows in the TUI.

Change: record the index where the intro actually landed. That's the `insert_above_prompt_at()` base when inserting, `len() - 1` when appending. Keep `assist_offer`'s line association consistent the same way.

Acceptance: a lib test in both prompt modes. On the first assist, `assist_intro_line` is exactly the intro's index and the following offer line isn't marked as the intro. That holds with Zork I's "illuminate lamp" (a vetted offer), and there's no second intro on the next assist.
