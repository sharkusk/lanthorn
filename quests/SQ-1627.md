--- note 2026-09-28T03:24:57Z ---

Shipped scope, per design discussion before dispatch: item STATE (lit/open/locked etc.) was explicitly excluded — attribute meaning is unrecoverable/unstable per-engine (Z-machine attribute numbers have no fixed meaning; the existing WorldModel inferencer is limited to container/open and disabled for Inform games; Glulx attribute reading is explicitly refused for the same instability reason). Only origin/current-location/vanished (Facet 1) and a "confirmed fixed in place" facet (Facet 3) were built.

Facet 3 (fixed-in-place) is deliberately incomplete, not a bug:
- Only fires when the player actually types a take-style command and the noun unambiguously matches exactly one candidate item's PRINTED NAME (no access to the game's own parser synonyms at that call site) — "take lamp" may not match an item whose printed name doesn't contain "lamp" even if the parser accepts it.
- `fixed_in_place: false` means "never confirmed" — most scenery is never tested this way, so this is not a reliable inventory of what's takeable.
- Ambiguous noun matches (0 or 2+ candidates) are silently skipped, never guessed.
- Real-fixture verification is Z-machine only (Zork I's mailbox). Glulx has no real-fixture test for this facet; Scott Adams items lacking an explicit noun marker are dropped from tracking entirely, so Scott has no coverage either.

Also: display in the TUI is a separate, not-yet-done follow-up — filed as SQ-1628 (covers both this quest's item data and SQ-1625's room descriptions, neither of which is wired into any UI panel yet).
