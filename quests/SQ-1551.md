Citations crates/app/src/ and crates/mapper/src/, as of 09fa95e9. Found building map editing on the session host (SQ-1540's layer_layout + struct_gen).

1. `input::choose_region` (input.rs:4323) and `move_targets` (input.rs:4360) are private. They decide which rooms a "move region" from a selected room takes (portal boundary, single inbound bridge, several bridges -> ask) and which destinations to offer. A host offering "Move to another layer…" must mirror that order using mapper's public functions, which can drift. Make them pub (or move them into mapper / a host module) with the TUI calling the same functions.
2. Accepting a layer suggestion goes through `apply_region_prompt` (input.rs ~4709-4735), which also sets the maze flag for name-triggered suggestions (input.rs:4731). A host that does not use maze flags (and opens such a layer in the matrix view instead) must re-implement the accept. Split the accept into the move itself and the maze-flag step (or take an option), so a host can accept without the flag while the TUI keeps its behaviour. The suggestion text for name triggers ("Separating it also flags the layer as a maze.") should come from a function that knows whether the flag will be set.
3. `MapGraph::mark_tried` doesn't bump `struct_gen`, but tried directions are drawn (the matrix view's tried markers). A host that resends the layout on struct_gen changes misses them. Bump struct_gen when a tried mark actually changes (value-change guarded, like the other mutators), or document why not and expose a separate counter.

Acceptance
- TUI unchanged; existing suites pass.
- Tests: the region/targets functions callable from an integration test and returning the TUI's choice on the existing layer fixtures; accepting a name-triggered suggestion without the flag leaves maze unset while the default path still sets it; mark_tried on a new direction bumps struct_gen, re-marking the same one doesn't.
