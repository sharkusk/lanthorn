Follow-up to SQ-1614. painted_menu_screen_stamps (crates/app/src/render/screen.rs ~6237) builds V6PaintedMenuStamp (~6039) and V6PaintedMenuFill (~6019) from v6_run_style but keeps only fg and bg, dropping the Modifier (REVERSED, BOLD, ITALIC). The terminal's own cell path keeps them, so a host replaying the published layout draws Zork Zero's Mac and Amiga DEFINE (Function Keys) screen without reverse video: the definition fields and the selected key label (UP) aren't reversed (about 430-460 cells differ from render_story_pane's buffer). The PC release resolves its colours explicitly and matches. Ask: carry the style modifiers (or a reversed flag plus bold/italic) on stamps and fills, resolved the same way render_node's cell path resolves them, and extend the v6_amiga_global_colour_pair.rs replay test to compare modifiers as well as colours on Mac and Amiga. Also note: the layout omits the cell path's anchored status band, secondary buffers and side columns; fine for DEFINE, but say so in the doc if they're out of scope.
