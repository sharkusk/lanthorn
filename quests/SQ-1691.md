--- note 2026-10-03T00:56:38Z ---

Measured from an embedding host that indexes a whole library with picker::spawn_library_index (the TUI pays the same cost for Find's index, or when the folder is listed):

- picker::resolve_entries on a crunched .D64 that yields no story takes 7-9 s per file, e.g. QUESTPR3.D64 (9.0 s) and "THE INCREDIBLE HULK - THE ADVENTURE.D64" (6.9 s).
- scan_stories over stories/scott-dialects/c64 takes 13.4 s for 12 rows; that one folder is ~13 s of a ~15 s whole-library walk.
- hints::mounted_stories alone is 2.1-2.7 s per file, because scott_disk_stories (hints.rs ~787ff) emulates blorb::depack::depack_c64_prg for every candidate when the cheap sniff finds nothing.
- resolve_entries then repeats the mount through resolve_entry / load_mounted_story_from, so the depack runs about three times per file.

Proposed:
(a) depack once per file and reuse the result within one resolve;
(b) cache the "no story here" outcome by path + size + mtime, so a later scan or index skips it;
(c) a tighter emulation budget for a candidate that does not look like a crunched program.

Goal: any host listing that folder, or indexing a library containing it, is not held up for seconds per disk.
