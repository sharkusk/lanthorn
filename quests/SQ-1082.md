## The real defect, not the spelling

A negative-only flag is **one-way**. `--no-sound` forces sound off for a run, and
nothing on the command line can force it ON — so a config carrying
`enable_sound = false` can only be overridden by editing the file. `config.rs`
states the limitation plainly at the pin site:

> One-way override: `--no-sound` forces sound off for this run, but its absence
> must not turn on a config that persisted `enable_sound = false`.

That comment is correct GIVEN the flag's shape; the shape is what is wrong. Every
other one-run override in the tree is symmetric. `--game-colours on` is the case
that bites hardest — there is currently no way to ask for it at all.

## Scope: four front-ends, two mechanisms

Changing `app` alone would recreate exactly the drift SQ-1078 existed to remove —
one spelling in the TUI, another at the prompt.

* `app` (clap derive): `--no-accel`, `--no-sound`, `--no-images`,
  `--no-game-colours`
* `zvm-cli` (`cli_host::args` scanner): `--no-aux`, `--no-more`/`--no-page`,
  `--no-sound`, `--no-timed-input`, `--no-game-colours`, `--no-status`
* `gvm-cli` / `scott-cli`: `--no-accel`, `--no-more`/`--no-page`,
  `--no-game-colours`

`config::OnOff` already exists (added for `--v6-pixel-lock`, SQ-1079) and is the
shape to reuse: `Option<OnOff>` rather than `bool`, because "not mentioned" must
stay distinct from "off" or a flag's absence starts turning persisted `true`
values off.

## Decisions taken when this was agreed

* **Require the value** — `--sound on`, never a bare `--sound`. A bare form
  invites "is that on, or a toggle?", which is the ambiguity being removed.
* **No hidden aliases for the old spellings.** Pre-release policy is that
  formats and surfaces may break; an alias is the old spelling surviving
  somewhere nobody maintains it.
* **Two are NOT mechanical conversions.** `--no-status` was already renamed once
  (to `--story-only`, SQ-0613) precisely because it was STRONGER than its name —
  it suppresses the whole upper window, menus included — so `--status on|off` would
  re-tell the same lie. And `--no-more`/`--no-page` has no obvious positive noun;
  `--pager on|off` is a proposal, not a given.

## Cost

Breaking, and to documented surface: v0.2.0 shipped `--no-sound`, and README.md
and the v0.3.0 notes both name `--no-game-colours`. Both need updating with the
change. Deferred out of 0.3 deliberately — that release was already tagged, built
and drafted when this came up, and re-cutting a tag to change CLI surface costs
more than waiting one release.

## Also in scope: `--colour terminal|theme|machine`

Requested 2026-08-26. It fits this quest rather than a separate one, because it is
the same idea — a setting named positively with its values spelled out — and it
lands on the same flags.

**It names a precedence the code already has, and makes it choosable.**
`startup.rs:575` resolves the story pane's default page and ink from exactly three
sources, in this order:

```rust
let mut host_default_colours = if cfg.honor_game_colours {
    cfg.machine_default_colours()                       // 1. the machine's §8.3.3 pair
        .or_else(|| app::colors::host_default_colour_pair(
            cs.theme.get("transcript").style,           // 2. the theme, when concrete
            term_default_colors.fg…, term_default_colors.bg…))  // 3. the OSC 10/11 probe
} else { None };
```

So `machine`, `theme` and `terminal` are not three new concepts — they are the
three arms of that `or_else` chain, which today can only be influenced
indirectly (by whether a medium named a machine, and by whether the theme happens
to set both channels concretely). The flag pins one outright.

**`--system-colours` is subsumed by it.** That flag exists (SQ-0928) to present a
machine's own pair off non-original media — exactly `--colour machine`. It should
go when this lands rather than sit beside it saying the same thing.

## It is a DIFFERENT AXIS from `--game-colours on|off` — keep both

Worth stating because the two are easy to conflate, and the current code conflates
them:

* `--game-colours on|off` — does the interpreter honour what the STORY asks for?
  Off declares the interpreter colourless under ZMSD §8.3.2 and leaves the VM's
  own black-on-white seed alone.
* `--colour terminal|theme|machine` — what does DEFAULT resolve to, for the page
  and ink the story is told about in `$2C`/`$2D`?

Today `honor_game_colours = false` answers both at once: the `if` above returns
`None` for the host defaults as well as declaring the interpreter colourless. That
may well be right, but it is currently a coincidence of one branch rather than a
decision, and splitting the flags is the moment to decide it deliberately —
"ignore what the game asks for, but still present the Amiga's page" is a coherent
request that cannot be expressed at all right now.

## Open questions for whoever takes it

* Spelling: `--colour` or `--colours`? The tree uses `--no-game-colours` and
  `--system-colours` (plural, British), with `--system-colors` accepted as an
  alias. Follow that.
* `--colour machine` on a launch that named no machine cannot conjure one —
  `--system-colours`' own doc says so. Does it error, warn, or fall through to
  theme? An error is probably right for an explicit flag.
* Does it need a config key, or is it launch-only? `system_colours` has one, so
  probably yes — and then it needs a one-run pin like the rest.

## Both old colour flags are DELETED, not aliased

Confirmed 2026-08-26: `--system-colours` (and its `--system-colors` alias) and
`--no-game-colours` are removed outright. The replacements are not synonyms for
them, which is the point:

| gone | replaced by |
|---|---|
| `--system-colours` / `--system-colors` | `--colour machine` |
| `--no-game-colours` | `--game-colours off` |

Nothing is kept as a hidden alias, per this quest's standing decision — an alias
is the old spelling surviving where nobody maintains it, and the pre-release
policy is that surfaces may break.

**This is a documented-surface change and the docs go with it in the same
effort.** `--no-game-colours` is named in README.md, in `docs/features/`
(v6-graphics, customization, interpreter) and in the v0.3.0 release notes;
`--system-colours` is named in README.md and the v0.3.0 notes. The v0.3.0 section
of CHANGELOG.md is history and stays as written — it describes the release that
shipped those flags — but README and `docs/features/` describe the CODE and must
move with it.

Also check the config side: `system_colours` is a config key with a `Cli` field
behind it, so removing the flag means deciding whether the KEY survives
(`colour = "machine"` seems the natural successor) rather than leaving an
orphaned key that nothing can set from the command line.

## Two more consolidations, and the per-flag mapping so far

Added 2026-08-26. This quest is no longer only about polarity — it is about the
whole `app` flag surface reading one way.

### `--no-images` goes; `--image-protocol` gains `disabled`

"Which protocol" and "none at all" are the same axis, so they should be one flag:
`--image-protocol auto|halfblocks|kitty|sixel|iterm2|disabled`.

The config side is the part to think about rather than assume. There are TWO
fields today — `images: bool` (default true) and `image_protocol: ImageProtocol`
(default `Auto`) — and `images` has real consumers that are not the picker:
`picker_ui.rs:778` gates the cover picker on it, and `reset.rs` reads it in four
places so a `@restart` re-resolves artwork the same way the launch did. Folding
`images` into `image_protocol == Disabled` means those call sites ask the protocol
instead, which is a small change but a real one — and `Config::default().images`
is pinned by a test, so the fold is visible in the gate rather than silent.

### `--no-accel` becomes `--glulx-accel on|off`

Two improvements in one: the polarity, and the NAME. `--no-accel` does not say
what it accelerates — it is Glulx accelerated-function interception (13 functions,
Counterfeit Monkey's boot went 23.78M to 3.00M opcodes) and means nothing to a
Z-machine or Scott player, who are most of the audience. `gvm-cli` carries the
same flag and takes the same rename.

### The mapping, as it stands

| gone | replacement |
|---|---|
| `--no-sound` | `--sound on\|off` |
| `--no-accel` | `--glulx-accel on\|off` |
| `--no-images` | `--image-protocol disabled` |
| `--no-game-colours` | `--game-colours on\|off` |
| `--system-colours` / `--system-colors` | `--colour machine` |
| — (new) | `--colour terminal\|theme\|machine` |

Still open, and NOT to be converted mechanically: `--no-status` (already renamed
once to `--story-only` because it was stronger than its name), and
`--no-more`/`--no-page`, whose positive noun is not obvious. `zvm-cli`'s
`--no-aux` and `--no-timed-input` follow the same rule as the rest.
