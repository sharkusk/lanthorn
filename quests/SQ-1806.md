--- note 2026-10-23T15:44:49Z ---

Details. Zork I r52 (Solid Gold v5) splits the upper window to 1 every turn. A .lanthorn save carries the whole upper grid in its screen snapshot (zvm/src/screen_snapshot.rs: grid := cols + rows + cells), and restore_screen (crates/app/src/session.rs:~5594) puts it back as it was, rows included. The grid grows when the game prints below the split or text wraps past the last column (zvm/src/cpu/exec.rs:~6121 grow_rows), and only retire_stranded_upper_rows (exec.rs:~1177) shrinks it, after a split that shrinks. The stranded flag is not saved, so a save taken while the grid was 2 rows (likely an older build during the r52 garbled-status bugs SQ-0679/SQ-0681, or a long status write on a narrow screen) restores a blank second row that stays until a restart; Engine::active_rows (session.rs:~6075, = screen.upper.rows for v4+) then reports 2. Reproduced by the owner with old saves of Zork I and Hitchhiker's on a ~50-column screen; a fresh game is fine. Wanted: after a restore, the upper grid is no taller than the game's split (retire blank rows below it on restore, or save the stranded state), and anything judging 'one-row status line' by rows (zvm-cli quiet_status_line, zvm-cli/src/screen.rs:405-416) counts rows that are actually in the split/painted. A test: restore a snapshot whose upper grid has rows=2 with a split of 1 → active_rows 1. Old saves already in the wild must be cured on restore, not only new ones. The owner is holding the v0.9.8 tag so it can be moved to include this fix.
