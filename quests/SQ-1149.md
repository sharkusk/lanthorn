Fixed in `crates/app/src/render/palette.rs` (lane C of the wave-2 parallel run, branch `worktree-agent-abe02c1d8a6a5e26d`, commit 869d25ef).

## What was implemented

Exactly what was specified: truncation stays while the palette shows a LIST; a filter narrowed to a SINGLE match word-wraps that candidate's whole help and the modal grows downward to hold it. Several matches are untouched — one row each, truncated at the help column, so the name column stays scannable.

Two helpers carry it: `help_col(name)` is the one place the help column is computed (col 26, or one clear cell past a name too long to fit before it), and `sole_match_wrap(cands, modal_w)` returns the wrapped lines or `None`. The wrap is measured BEFORE the chrome is drawn, off the modal's own width, because the dialog has to be sized from it — so the rows the geometry reserves and the rows the draw fills cannot disagree. The row loop became a `while` over rows-consumed so one entry can be several rows tall.

## The three questions the brief asked

**What happens when the description is longer than the height.** It clips at the last row, exactly as a truncated one already did. `modal_h` still takes `.min(area.height - 2)` and the `modal_h < 5` guard still returns `None`, so growth is bounded by the pane and a small pane gets the dialog it got before. Deliberately not a scrollbar: a one-item result has nothing to scroll between, and adding a second scroll model to a dialog whose nav is the candidate list would be a keyboard change for a case that cannot arise (the longest help in the registry is 157 chars against a 44-column field = 4 rows).

**Keyboard model.** Unchanged. Nothing in `input.rs` is touched; routing does not read the geometry. Tab completes, Enter runs, Esc closes, Space stays widget-reserved. With one candidate there is nothing to move between.

**Styleability.** No new UI element, so no new selector — the wrapped rows draw in the existing `palette_desc` / `palette_selected` styles. Said explicitly because the brief asked for one answer or the other.

Also: the selection fill and the click hit-rect both span the whole entry, so a click on a continuation row runs the command instead of falling through.

## Verification

Two new cases in `render::palette::tests` — `sole_match_wraps_its_help_and_grows_the_dialog` (asserts every word of the help is on screen and the hit rect is taller than one row) and `several_matches_keep_one_row_each` (the counterpart). Falsified by disabling the wrap: the new case fails with the originally reported symptom, `help word "silent" missing — description was truncated`.
