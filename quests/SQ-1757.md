  The IFDB search chooser marks a download option '✓ · already downloaded' only when a file of that exact name sits in the download directory (ifdb_search_modal.rs probe_present, private). A library organised in subfolders (e.g. 'Glulx Stories/', 'Infocom/') never gets the mark, even when that very file is already in the library. Wanted, for the TUI and any embedding host: a public lib call that, for each DownloadOption of a resolved game, returns the paths anywhere under the library root (all subfolders, the same walk as the library index; or a pure variant over an index the host already holds, like library_match::matching_entries) holding a file of that name. The chooser marks the row and says where, e.g. '✓ in Glulx Stories/', keeping the top-level 'downloading again makes name (2)' meaning visible where it applies. A hint, never a block. Names only, as today.
