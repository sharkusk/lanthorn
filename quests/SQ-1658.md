  User observation: in inline-prompt mode, if you've scrolled up (prompt not visible) and then type + press Return, the view stays scrolled up instead of auto-scrolling to show the result — unlike most terminal/chat apps, which treat your own submission as an unambiguous "show me what happens now" signal. Confirmed this is a deliberate existing design (pager.rs's own comment: "a reader scrolled into history is never dragged back down, by this or by anything else" — SQ-1595), built to stop the view yanking back when the GAME prints something while the player is reading backlog. The player's own submit is a different signal than passive output arriving and should be carved out as a narrow exception, leaving the existing no-drag-back rule intact for passive output.
