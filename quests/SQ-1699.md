--- note 2026-10-03T05:28:33Z ---

Today the chooser (documents_chooser.rs) lists IFDB's links and a zip's entries with no sign of what was already saved; a repeat download is only caught afterwards, by content ("Already in your documents: …", ifdb_documents.rs ~759). The data to know beforehand exists: since SQ-1687 every download writes its source_url (and, for a zip entry, the zip's URL plus the entry's title/name) into the folder's index, and documents::list returns it on each DocEntry.

Proposed:
1. A host-neutral lib function, e.g. ifdb_documents::saved_status(&[DocEntry], &DocumentOption) -> bool and one for a zip entry (zip option + ZipEntry), or a single fn returning, for a list of options and listed zips, which links / (link, entry index) are already in the folder. Match a whole link by source_url; a zip entry by the zip's URL plus the entry's name (whatever the index records for it). Decide whether a file whose bytes are present under another name counts (probably not needed; source_url is enough).
2. The chooser marks those rows (e.g. "In your documents"), leaves them unticked, and refreshes the marks after a download finishes, so the player sees what they already have before downloading.
Any host showing the same dialog then calls (1) and gets identical answers.
