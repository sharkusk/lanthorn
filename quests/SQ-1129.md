## What happens today

`config_template::auto_seed` writes the fully-commented template **only when the
file does not exist** — pinned by its own test,
`auto_seed_creates_once_and_never_overwrites`. `write_config` then "writes only
non-default values but always updates keys already present in the file", so a key
the file has never contained is never added.

Result: a player who installed at 0.3.0 has a `config.toml` with **none** of this
release's settings — `guidance`, `font_check`, `hide_adult_words`, `adult_words`,
and whatever per-game keys SQ-1123 adds. They cannot discover them by reading
their own config, which is the only place the template's careful documentation
lives.

## Why this is worse than ordinary staleness

**It quietly voids [[SQ-1122]]'s justification.** That quest ships an adult-word
filter on by default, and the argument for its acceptability — made explicitly,
and accepted by the user on the strength of it — was:

> The list ships uncommented and readable in `config_template.rs`. A player must
> be able to see exactly which words are hidden and delete or extend the line. A
> filter nobody can inspect is censorship; a filter written in the player's own
> config file is a default.

**That holds only for new installs.** Every upgrading player gets the filter with
no visible list — an invisible filter, which is the thing the user ruled out
("faithful, we don't censor in this house"). So this is not a nice-to-have; it is
the difference between the shipped behaviour and the behaviour that was agreed.

## The fix

**Append the missing keys, commented, preserving everything the player wrote.**
Commented lines parse as an empty document, so behaviour cannot change — the
template's own doc comment says as much ("writing it changes nothing until the
user edits it"). `toml_edit` is already an `app` dependency and is the
format-preserving editor for exactly this.

Requirements:

- **Never touch a key the file already has**, commented or not, and never reorder
  or reformat what is there. A player's edits and their own comments survive
  untouched.
- **Idempotent**: running twice adds nothing the second time.
- **`adult_words` must arrive uncommented**, like the template ships it —
  otherwise the visibility problem is only half solved.
- Decide and state what happens to a file the player has deliberately emptied,
  and whether there is an opt-out. Re-adding forty commented lines to a config
  someone stripped on purpose is its own annoyance.

There is a related test worth reading first —
`these settings are loaded from config.toml but not documented in the template`
already keeps the template in sync with what `resolve` reads. It governs the
template, not the player's file; this quest closes that second gap.

## A second, smaller staleness found alongside

`commented_template()` states:

> PER-GAME overrides live in a second, separate config.toml inside that game's
> own save directory, and hold only these three keys:
> `honor_game_colours   borderless_windows   show_map`

That list is **already wrong** — `slash.rs` documents `set-v6-pixel-lock` and
`set-game-borders` as "persisted per-game" too — and SQ-1123 is adding
`guidance`, the render mode, the band and the map to it. Fix the sentence, and
consider whether it should enumerate keys at all rather than describing the rule,
since an enumeration in prose is exactly the hand-maintained invariant this repo
keeps getting bitten by.
