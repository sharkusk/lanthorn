## What it was

`stories/Shogun.toast` is a **bare HFS volume** — Master Directory Block signature `BD` at offset 1024, no Toast wrapper, no DiskCopy header, nothing in front of it. So `blorb::hfs::Hfs` mounted it the day it arrived and `InterpreterProfile::resolve_with_source` answered `Macintosh / Medium` off it. Reading was never the problem.

The DIRECTORY SCAN was. `medium::FORMATS`' Macintosh row claimed `["image", "bin", "iso", "dc42"]`, so a file called `.toast` was skipped **on its name, before its bytes were looked at** — which is SQ-0849's defect verbatim, and presents the same way: a disc silently missing from the story list while opening it by name works.

Caught by `disk_set_rows::the_scan_loses_no_game_anywhere`, which is exactly the guard-beats-convention case CLAUDE.md asks for:

```
Game/Story.data (ZCODE-292-890314-69B8) is on ".../stories/Shogun.toast"
and nowhere in the browser
```

## The fix

One spelling added to that row, by the rule its own comment already states four times: *"a spelling is still claimed when a medium wears it"*. The row's test list gains `toast` alongside it, so the claim is pinned rather than assumed.

## What the disc turns out to carry

* **Shogun, release 292 / serial 890314** — a Macintosh press, and a different release from every other Shogun in `stories/` (`shogun-r322-s890706.z6`, and r295/890321 on the Amiga floppy). Per CLAUDE.md, a disk image is a different RELEASE, not the same story on other media, so this is a new specimen rather than a duplicate.
* `FONT 524` (7x15) and `FONT 1033` (7x12), the same pair the Masterpieces volume's Arthur carries.

**It does not solve SQ-1052's machine-dependence, checked rather than assumed.** `FONT 524` is Monaco: every printable-ASCII advance measures exactly 7, so `native_font::fit` answers `Cell` and `TextFace::proportional()` is false. (`DiskFace.proportional` reads `true` for it, but that is `BitmapFont`'s raw flag counting the accented high range — SQ-0916 — not the fit.) A proportional Macintosh face still comes only from a System file, which ships with the machine and with no game.
