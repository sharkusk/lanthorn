--- note 2026-09-26T04:14:02Z ---

An embedding host that draws Hybrid's chrome text in its own fonts (not the game's bitmap faces) needs the same cell layout the terminal Hybrid renderer uses: chrome text that is not on a picture is laid out in text cells at the host's text size, and only pictures scale. Today that layout is private in crates/app/src/render/screen.rs: build_hybrid_frame (~3840), menu_band_rows (~7996, one text row per game row), menu_band_strips (~8017), run_cell (~7388), strip_native_origin (~7339), decompose_chrome_strips (~8638), draw_chrome_text_strip (~9028). Wanted: a public host-side call, e.g. hybrid_chrome_layout(layout, native, pane_cells, cell_px, state), returning for each chrome run its cell (col, row), whether it sits on a text strip or over art, the menu band's rows and the story viewport. Also the click inverse for that layout (a cell -> game pixel successor to V6Frame::menu_band_game_px), so mouse clicks on Journey's menu land where the game expects. Test stories: Journey PC r83 and Amiga, Zork Zero, Arthur, Shogun.
