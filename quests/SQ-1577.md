--- note 2026-09-25T17:52:24Z ---

Observed (rev 7ec7c5e5), Journey r83 on a tall pane through the host compose path (`compose_v6_frame` with `bottom_anchor_menu`, from SQ-1574):
- The left flank below Journey's picture is filled by `fill_menu_flank_extension` (crates/app/src/render/screen.rs l.7513, called at l.3323), which per 8-px block copies "the nearest painted pixel above the gap" downward. Under the picture column that is the picture's bottom row, so the extension becomes tall vertical stripes of the picture's last-row colours, continuing behind the bottom-anchored menu text. The same stripes appear under `Rasterise`, so it's the compose path itself.
- The owner confirms the TUI's hybrid does NOT look like this for Journey: in the TUI the picture is CENTRED (vertically) in the extended flank, and the background around it is FILLED based on the image itself — no smeared stripes. The TUI gets there via its hybrid ring path (`hybrid_bottom_plan` → `BottomPlan::Menu`, `stretch_flanks` at screen.rs ~l.4148, and the flank machinery in render/v6_border.rs — `flank_sections` l.296, `flank_source` l.1200).

Change: make the host Menu compose path produce the same picture as the TUI's hybrid for a Menu plan — place the flank picture where the TUI places it (centred in the extended flank) and fill the surrounding extension with the same image-derived fill the TUI uses, sharing the TUI's flank rule rather than a separate pixel-smear. Divider/rule columns must still run down to the menu (see SQ-1576).

Acceptance:
- Journey r83 and `Journey - The Quest Begins.adf` on a tall pane: the host-composed Menu frame matches what the TUI's hybrid shows for the same pane (picture centred, background filled from the image, no vertical stripes, nothing smeared behind the menu band) — compare against the TUI's rendering of the same frame.
- Frame/Extend titles (Zork Zero, Shogun, Arthur) unchanged.

--- note 2026-09-25T17:52:56Z ---

Owner addition (2026-09-25): Journey releases differ in how they draw their frame and dividers — some use REVERSE-SPACE fill (e.g. PC r83 `journey-r83-s890706.z6`, reverse-space divider runs), others use LINE-DRAWING characters (e.g. Amiga r30 `Journey - The Quest Begins.adf`; also check the Apple II builds `Journey.po` / `Journey.2mg` / `journey_s1..5.dsk`). The fix must handle both, and the acceptance must cover at least one reverse-fill release and one line-drawing release, each on a tall pane with the Menu plan, compared against the TUI's hybrid of the same frame.
