--- note 2026-09-24T04:26:08Z ---

Citations are crates/app/src/ unless stated, as of ca723e44. Goal of this series: an embedding host that is not a terminal (a GUI, a network server, a mobile FFI binding) can boot and play a story through the `app` lib with the same rules the TUI uses, instead of re-implementing them. The TUI must run on the same code, so there is one copy of the rules.

Current state
- `startup` is a bin-only module (main.rs:48-57 declares startup, turn, loop_tick, lifecycle, reset, ingame_io, engine_helpers, slash_dispatch, overlays, picker_ui).
- `startup::boot_story` (startup.rs:903) is ~1,500 lines. It resolves launch config/profile/palette, calls `MachineBoot::resolve` (startup.rs:1554, machine_boot.rs:157), then `GameSession::new_for_machine` (startup.rs:1594, session.rs:1120), `GlulxSession::new_in` (startup.rs:1650, glulx_session.rs:553) or `ScottSession::new_with_options` (startup.rs:1687, scott_session.rs:255); drains the banner with `take_transcript_elems`/`take_transcript` (startup.rs:2025); runs `session.seed_turn()` into `apply_turn` (startup.rs:2129-2131); handles archive resume; and only then enables raw mode and builds the ratatui Terminal (startup.rs:2287, 2357).
- `BootResult` (startup.rs:44) owns the Terminal, so the struct itself is TUI-only. The Mapper is a local owned by the bin (`BootResult.mapper`, startup.rs:46).
- Terminal-only pieces that must stay in the bin: `term_colors::send_and_drain` probe (reached from startup.rs:1139), `stderr_redirect::install`, raw mode, Terminal construction, graphics-protocol probing.

Change
- New lib module (e.g. `app::host`) with a boot entry point taking a plain request (story path, disk entry, launch overrides / OneRunOverrides, data dir, config) and returning a terminal-free result: the engine (whatever `Box<dyn Engine>`/enum the TUI holds), the `Mapper`, `DeathWatch`, the banner transcript already applied to an `AppState` (AppState is in the lib and usable headless; `AppState::default()` opens no audio device, state.rs:3654), the resumed archive state if any, and the seed turn applied.
- `startup::boot_story` becomes: terminal-independent boot via the new entry point, then the terminal setup it does today. No behaviour change for the TUI.
- Terminal-dependent inputs to boot (e.g. the OSC colour probe result, cell size) become optional fields on the request that the TUI fills in and a headless host leaves `None`.

Acceptance
- TUI behaviour unchanged; the existing suites pass (`cargo test --workspace --all-features`, clippy -D warnings).
- New tests boot headlessly through the new entry point with no TTY: a Z-machine story (fixture_path), a Glulx story, and the committed Scott `tiny_cave.dat`; each asserts a non-empty banner and `pending_input() == Line`. Skip vacuously when a gitignored story is absent, as the other real-media tests do.
- A resume test: boot, play two moves, write the resume archive, boot again, and require the same location and transcript tail (CLAUDE.md restore discipline: also make one more move after the restore and compare).

Out of scope: per-turn apply, clocks, autosave (the next two quests in this series).
