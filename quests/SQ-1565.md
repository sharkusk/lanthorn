--- note 2026-09-25T02:32:24Z ---

Current code (rev c68d48cf):
- crates/gvm/src/glk.rs:2634 — "A graphics key child sizes in PIXELS; convert to whole cells": a fixed-size graphics split is rounded up to whole cells for the layout.
- gvm still knows the pixel size the game asked for (`window_pixel_size`, glk.rs:~2762), but the app's window tree drops it: `engine::Split { fixed: u16 }` (crates/app/src/engine.rs:357) carries cells only, and crates/app/src/glk_backend.rs:1171 copies only the cell split.
- The graphics canvas is sized cells × char_px (`canvas_size`, glk_backend.rs:~487), and the game fills all of it, so e.g. Kerkerkruip's 2–3px coloured rules under its panel titles arrive as a solid canvas one full text row high (240×16).

Change: carry the requested pixel size of a fixed graphics split (or the graphics window's `window_pixel_size`) on the WinNode / Split (e.g. `fixed_px: Option<u32>`), and size that window's canvas in pixels when known, so a host with pixel layout can draw the window at its real size. The TUI can keep rounding to cells for its own grid.

Acceptance:
- Test: a Glulx layout with a 2px fixed graphics split → the WinNode reports 2px, and its canvas is 2px high (at least the width in pixels × 2).
- Kerkerkruip's title rules report their pixel height.
- TUI rendering unchanged.
