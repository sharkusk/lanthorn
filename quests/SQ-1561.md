Current code (rev a64394b5):
1. crates/app/src/glk_backend.rs `graphics_draw_image` (~l.1495) and `buffer_draw_image_ext` (~l.1530) know `resnum`, but build `inline_image::InlineImage { pixels, align, scaled, … }` (crates/app/src/inline_image.rs:42) with only the decoded RGBA pixels. A host that ships pictures to a separate renderer (by URL, cached) can't tell which Blorb Pict an inline image came from, so it has to re-encode every inline picture to PNG and content-hash it, instead of serving the story's original PNG/JPEG chunk by number.
2. crates/audio/src/lib.rs ~l.110 `fn gain(master: u8, z_volume: u8) -> f32` (master 0..=100 × Z-scale 1..=8, with 0/255 = full) is private and `cfg`-gated to the playback feature, so a host that plays sounds itself (no rodio) has to copy it and can drift.

Change:
1. Add `pub resource: Option<u32>` to `InlineImage` (the Blorb Pict number when the picture came straight from one resource; `None` for composites/synthesised images), filled in at both draw sites, carried through wherever InlineImage is cloned/persisted (the transcript archive/save format, if it stores inline images — keep old saves loading).
2. Make the mapping public (e.g. `pub fn z_gain(master: u8, z_volume: u8) -> f32`), no feature gate, used by the playback path.

Acceptance:
- Test: a Glulx story drawing a Blorb picture inline yields an InlineImage whose `resource` is that Pict number; a scaled/ext draw keeps it too.
- Test: `z_gain` matches the current values (0/255 → master, 8 → master, 4 → master/2, master clamped at 100).
- Old saves/transcripts still load; TUI output unchanged.
