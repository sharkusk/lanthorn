## What the doc says vs what the code does

`docs/features/customization.md` tells the reader that the gutter marks beside
meta and warning transcript lines come from the `glyph` attribute on the
`transcript_meta` / `transcript_warning` theme rows.

They do not. `render/transcript.rs:2436-2437` reads them from the symbol set:

```rust
TranscriptKind::Meta    => (Some(state.symbols.meta_gutter), meta_marker),
TranscriptKind::Warning => (Some(state.symbols.warning_gutter), warning_marker),
```

`SymbolSet::meta_gutter` defaults to `▏` and `warning_gutter` to `!`, and the
working override keys are `gutter.meta` / `gutter.warning` under
`[symbols.overrides]`. The theme `glyph` on those rows is never consulted for the
gutter, so a user who follows the documentation changes nothing and has no way to
tell why.

Pre-existing — it predates SQ-1045, which found it while adding `gutter.assist`
along the mechanism that actually works.

## Fix

Smallest correct change is to the **doc**, pointing at `[symbols.overrides]` and
the `gutter.*` keys. Do NOT add a second code path that makes the theme `glyph`
attribute work as well: two ways to set one character is how they drift, and the
symbols route is the one every other gutter already uses.

Worth checking while in there whether any other selector's `glyph` is documented
as reaching something it does not reach — this was found by accident, not by a
sweep, and `theme/registry.rs` carries `glyph(...)` on rows whose consumers vary.
