Current code (rev a64394b5):
- crates/app/src/assist.rs:216-218 declares `OfferKind::Intro` ("The once-per-session introduction (see [`preamble`])"), but nothing constructs it: `Assist::offer()` (assist.rs ~305) only yields `Other`/`Caution` for a bare line, and vocab.rs:1882/1997 yield `VocabularyOffer`/`VettedOffer`.
- crates/app/src/state.rs:5362 `push_assist` pushes the intro via `assist::preamble(self.symbols.assist_gutter)` as an ordinary `TranscriptKind::Assist` line with the Help style, then sets `self.assist_offer = Some(assist.offer())` for the assist that follows — the comment at ~5380 says the intro deliberately carries no offer.

Why it matters: a non-terminal embedding host that renders assist lines itself (styling, clickable offered words) has to tell the introduction apart from a help line. With `Intro` never produced, the only way is to compare each Assist-kind line against `assist::preamble(mark)` — a text match that silently breaks if the preamble is ever reworded or the gutter mark changes.

Change: make the introduction identifiable structurally. Any of these is fine — pick what fits the SQ-1552 design:
  (a) record which transcript line the intro was pushed on (e.g. `pub assist_intro_line: Option<usize>` on AppState, set in push_assist), or
  (b) alongside `assist_offer`, expose that this turn printed the intro (e.g. `assist_intro_pushed: bool`, cleared at turn start like `assist_offer`), with `OfferKind::Intro` used for it, or
  (c) a distinct TranscriptKind / line tag for the intro.
If `OfferKind::Intro` stays unused after the change, remove it rather than leaving a variant that is never produced.

Acceptance:
- A lib-level test: with guidance on, the first push_assist in a session produces the intro and the host-visible signal identifies exactly that line (and not the assist line after it); the second push_assist produces no intro and no signal.
- The signal is cleared at turn start by the same rule as `assist_offer`.
- TUI output unchanged.
