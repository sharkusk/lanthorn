## The instance that was found

`crates/verb-synonyms-gen/src/tests.rs`:

```rust
fn scratch(name: &str) -> std::path::PathBuf {
    let d = std::env::temp_dir().join(format!("verbsyn-test-{name}-{}", std::process::id()));
```

Every test calling `wordnet_fixture()` calls `scratch("wn")`, so under **one**
process they all get the **same** directory. `fs::write` truncates, so one thread
read `index.verb` while another rewrote it; `WordNet::load` came back empty,
`build` returned no groups, and a correct fixture failed its assertion.

**Under nextest it cannot happen** — process per test, so the pid already
disambiguates. Under `cargo test` — which is what CI runs — one binary's tests
share a process and run on threads. So the local gate was structurally blind to
it, exactly as CLAUDE.md says of the palette races (SQ-0904): *"a race on one is
structurally invisible to `cargo nextest run` — while `cargo test` gives a
binary's tests one process and many threads and hits it."*

Fixed in place by keying on an `AtomicUsize` as well as the pid.

## Why this needs a sweep rather than a patch

`grep -rn "process::id()" crates/` returns **236** hits. Most are certainly
harmless — real pid uses, or scratch names that already differ per test — but the
dangerous shape is specific and worth finding deliberately:

> a temp directory keyed **only** on the pid, whose name is the **same** for two
> or more tests in one binary.

That is the shape that is correct under nextest, wrong under `cargo test`, and
invisible to every local run.

**Do not mass-rewrite all 236.** Find the ones matching the shape above — a
helper called from a shared fixture is the strongest signal — and fix those.
Report how many of the 236 were genuinely at risk, because that number is the
answer to whether this is a systemic problem or a one-off.

## The durable fix is a guard, not a convention

Per CLAUDE.md, *"where the wrong spelling cannot be made unreachable, add a
source-level case that fails it"* — the way `palette_lock_discipline` does. Two
candidates worth weighing:

1. **One shared scratch helper** that every test crate uses, unique per call by
   construction, so the wrong spelling is not available.
2. **A source-level case** that fails any `temp_dir().join(...)` whose key is a
   bare `process::id()`.

The first is better if it is reachable across crates; the VM crates take no
external dependencies, so a shared helper cannot live in a dev-dependency they
would have to add. Say what you concluded.

## And the wider lesson worth writing down

CI was red for **eight consecutive commits** and the local gate was green every
time. Whatever comes of this sweep, `cargo test --workspace` deserves a mention
in the pre-push routine for changes that add tests writing to disk — not just
for the palette, which is currently the only case CLAUDE.md names.
