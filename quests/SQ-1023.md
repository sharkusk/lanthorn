## Measured from captures already in the tree — three titles agree, and they contradict the source

Discriminator: on a **hires 640** screen a font stroke is ONE pixel wide; on a **lores 320** screen displayed at the same physical size it is TWO. Histogram of bright horizontal ink-run lengths, restricted to text-like rows (8..200 runs, none longer than 24px):

    amiga-arthur.png   320x200 native   1px 77%   2px 10%   3px 9%
    amiga-journey.png  718x484 window   1px 11%   2px 60%   3px 7%
    amiga-shogun.png   720x484 window   1px  2%   2px 65%   3px 6%

Arthur captured natively at 320 shows single-pixel strokes. Journey and Shogun captured in a ~2x window show two-pixel strokes. Both readings say the underlying screen is **320 wide**, from three different titles and two different capture setups.

That is consistent with the existing advance arithmetic (info.txt's 3.75-5.25 px/char against `char.data`'s 2..=8 advances reconciles at 1:1 and not at 2:1) and with info.txt's palette argument that `amiga-arthur.png` was never resampled.

**So the weight of measured evidence is now against `AM_XSIZ 640` describing the shipped build**, not merely unresolved. `Hirez` is an `extern int` declared in `gfx.c:25` and defined nowhere in the archived tree, so a lores path plainly existed and a shipped build may have taken it.

## What would settle it, and it is not another screenshot

**The emulator's own reported display mode while an Amiga v6 game runs.** FS-UAE and WinUAE both surface the current screen mode. `640x200 hires` vindicates the source and means these captures mislead; `320x200 lores` means the archived `yzip.h` is not the shipped build. One glance, and it is direct evidence about the machine rather than an inference from pixels.

## What this does NOT settle

Even granting a 320x200 machine screen, the relationship between that and lanthorn's 640x400 unit space with `art_scale` (2,2) is still not established. Our model is aspect-correct either way; what is unverified is which space the GAME names coordinates in. The source's answer (640x200, art doubled horizontally only) and the captures' answer (320x200, art 1:1) are different coordinate spaces, and our model is a third.

**The standing instruction stands: change nothing here until the mode question is answered.** Every route into this moves every v6 rect on the machine across Arthur, Journey, Shogun and Zork Zero.
