## What they are, verified by running them

`stories/zork1-invclues-r52-s871125.z5` holds five sigil verbs in its grammar
table (dumped with `cargo run -p zvm --example grammar_dump`):

```
229. #unrecor      223. #command      217. #random      159. $verif      138. #record
```

Run against the real game through `zvm-cli`:

```
> $verify
Interpreter 1 Version A
Verifying disk...
The disk is correct.

> #random
What do you want to #random?
```

These are **Infocom's own regression-test rig**, shipped in the retail build:
`#record` / `#unrecord` capture player input to a script, `#command` plays one
back, and `#random` controls the RNG — record a playthrough, replay it
deterministically, compare. `$verify` is the §15 checksum check plus an
interpreter report.

Two sigils, two meanings: **`#` is the test harness, `$` is diagnostic.**

## Why this is a defect

SQ-1111 made the VERB column show the story's real grammar, which is right — but
these are not part of the game. A player browsing for something to try is offered
five internal test commands, at the **top** of an alphabetical column, which is
the worst possible position. It compounds the browsing problem SQ-1111 flagged
(248 rows, four visible).

## The fix is a RULE, not a list

Filter dictionary words whose first character is `#` or `$`. That is structural
and needs no maintained vocabulary — unlike SQ-1122's adult list, which is a
judgement and is therefore shipped visibly in the config for the player to edit.
Do not add these to `adult_words`; they are a different kind of thing and
conflating them would make both harder to reason about.

Check the corpus before fixing the rule in place: `verb_words()` over `stories/`
will say whether other games use other sigils, and whether any *legitimate* verb
starts with either character. The SQ-1110 harvest already does that walk.

## Display only, like SQ-1122

Typing `$verify` must still work — it is a genuinely useful diagnostic, and it is
the easiest way to see which interpreter number lanthorn is reporting to a game
without a debug build. Filter the column, not the parser, and pin that as a test
the way `adult_words.rs` does.

Worth deciding and stating: whether SQ-1041's suggestion path should also skip
them. The risk is negligible either way — a near-miss against `#random` is
improbable — but say what you chose rather than leaving it accidental.

## Related

[[SQ-1111]] built the column; [[SQ-1122]] built the display-only filtering seam
this should reuse (`Config::hidden_display_words` / `VerbTable::hiding`), and its
`every_verb_table_in_src_is_assembled_through_config` guard means there is
exactly one place to add this.
