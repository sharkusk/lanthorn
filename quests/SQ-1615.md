--- note 2026-09-27T05:33:55Z ---

A host that labels a library row with the machine a disk image came from (for example a badge or column: Amiga, Atari ST, Mac, Apple II, C64, PC) today has to derive it from DiskImage::interpreter_number() and implies_ibm_pc() (crates/blorb/src/medium.rs:414, :421). That works for Z-machine machines but is a Z-machine concept: it maps 7 (C128) and 8 (C64) together, 2/9/10 all to Apple II, and gives Atari 8-bit media (DiskImage::AtariDos2 at medium.rs:943, DiskImage::AtariXex at :1029) neither a number nor the PC, so a host can't name the machine at all. These disks are real library rows: the Scott Adams SAGA .atr sides and The Hulk.xex under stories/scott-dialects/atari/ load and list today.

Ask: publish the machine a medium belongs to as its own answer, independent of interpreter numbers. For example DiskImage::machine() -> Machine (enum: Amiga, AtariSt, Atari8Bit, Mac, AppleII, Commodore64 (or C64/C128 as the lib prefers), IbmPc, ...) with a display label, or None for media that name no machine (plain ISO the lib can't place). The existing label field names the filesystem; this is the computer. Keep interpreter_number as is. A host would then call machine() instead of re-deriving it.
