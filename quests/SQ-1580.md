Current code (rev d7fd62b7):
- `post_restore_fixups` (crates/zvm/src/cpu/exec.rs ~l.6627-6631, from SQ-1572) re-applies `set_v6_screen_px(w, h)`.
- `set_v6_screen_px` (~l.1305-1310) sets `windows[0]` AND `windows[1]` `x_size`/`y_size` to the whole screen.
- A game that had sized window 1 itself (FMV Poker: the blue title banner) keeps working on the restored memory but now has a full-width window 1, so its next `erase_window 1` paints to x=640.

Evidence: `fmvpoker.z6` + `fmvpoker.blb`, seed pinned.
- Without a restore, 5 hands leave pixel (600,20) frame blue `68,102,136`.
- After an in-game SAVE then RESTORE, every later hand shows banner blue `0,107,181` there. The only difference from the no-restore composite is the box (461,6)–(640,40).
- Likely affects any v6 game that sizes window 0 or 1 itself and is restored.

Change: after a restore, re-declare the screen size (header $22/$24, the text metric) without resetting the window table. The windows come back from the restored game state, or are left as the game had them. Keep SQ-1572's guarantee: the screen stays 640×400 on Mac Zork Zero.

Acceptance:
- FMV Poker: save, restore, then play a hand. The composite equals the no-restore composite (pixel (600,20) stays frame blue).
- SQ-1572's Mac Zork Zero restore test still passes.
- Zork Zero r393, Arthur and Shogun save/restore tests are unchanged.
