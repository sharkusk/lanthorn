Citations crates/app/src/, as of 5560bc25.

Observed: when a timed interrupt routine returns true and the @read is terminated, `run_timed_interrupt` calls `abort_timed_input("")` (session.rs:1767), so the text buffer the game reads back is empty even when the player had typed part of a line. The TUI and a headless host through `host::clock::fire_due` behave identically.

Question: what should the text buffer hold when a timed interrupt terminates input? Check ZMSD §15 (@read / @aread, timed input) and §10 input rules, and compare Frotz's behaviour (and one other interpreter, e.g. Bocfel), with a real timed-input story (Border Zone, or a tiny assembled v5 test with a timed aread).

Change (if the standard or reference interpreters keep the partial text): pass the partial line through to the terminated read, and keep the host's own input draft consistent with what the game now holds.

Acceptance: a test with a tiny assembled v5 story (timed aread whose routine returns true after the player has typed "hel") asserting the buffer content matches the verified rule; the TUI's timed-input suites still pass. If the current behaviour turns out to be correct, close with a note citing the spec text, so nobody re-opens it.
