  On Windows, HOME is normally unset (a GUI app started from the Start menu or a shortcut has USERPROFILE, not HOME). Several path helpers fall back to '.' (the process's working directory) when HOME is missing: crates/app/src/colors.rs:866 expand_path (expanding ~ in config paths), crates/app/src/system_fonts.rs:337 and :482 user_media_dir (where system disks are kept), and crates/app/src/config.rs:1001 default_user_dir (configs built without resolve, e.g. tests). An embedding host on Windows then reads/writes user files relative to its install or working folder instead of the user's profile. Ask: one shared 'home directory' helper that uses HOME, then USERPROFILE (and HOMEDRIVE+HOMEPATH) on Windows (or the dirs/home crate), used by all of these; tests for each with HOME unset and USERPROFILE set.
