## The report

The VERB column jumps straight from `lock` to `lose`. `look` is excluded because
it is in `DEFAULT_QUICK`, enforced by
`command_band.rs::tests::verb_column_excludes_quick_words`:

```rust
assert!(!items.contains(&"look".to_string()), "`look` is in the default quick row");
```

The rule is dynamic, not hardcoded — removing `look` from `quick` puts it back,
and adding `take` to `quick` removes it — so the mechanism is fine and only the
**criterion** is wrong.

## The right rule (user, 2026-08-28)

> look needs to stay because it can be used in compound statements. the others
> cannot.

**Exclude a quick word only if it cannot start a longer sentence.** `n`, `s`,
`inventory`, `wait`, `again` are complete in themselves: a one-click button does
the whole job and a column row adds nothing. `look` is not — `look at`, `look
under`, `look behind`, `look in` — so the button fires only the bare form and the
column is the sole way to compose the rest.

## The wrinkle that makes this non-trivial

**The band cannot currently see that `look` composes.** SQ-1111 reports it as
`max_nouns() == 0`, because `VerbLine::from_syntax` refuses any line whose
literal precedes the first noun:

```rust
// A literal before the first object, or after the second, is a word
// the band has nowhere to put.
if nouns != 1 { return None; }
```

So `look at noun` is discarded and `look` arrives looking like a bare verb. A
naive "keep quick words that take objects" test, written against `VerbLine`,
would therefore **still drop it**.

**Consult the raw `grammar_model::SyntaxLine`** — does this verb have any line
containing a noun slot — rather than the converted `VerbLine`. That is the
difference between "the story lets this verb take an object" and "the band knows
how to compose it", and only the first is the question being asked.

## Check the whole quick row, not just `look`

`DEFAULT_QUICK` is `n s e w ne nw se sw up down in out look inventory wait
again`. Several are ambiguous and the corpus should decide rather than intuition:
`in`/`out` and `up`/`down` are directions here but real object-taking verbs in
some stories (`in` as `enter`), and `look` is not the only quick word that might
compose. Run the rule over the corpus and report which quick words return to the
column and on which stories.

## Why this matters more than one missing row

The user went looking for `look`, found a silent gap, and concluded the feature
was broken. That is the exact failure the exclusion was meant to prevent — the
word was optimised for and became unfindable.

It also got worse with SQ-1111: at 23 generic rows you could see the whole column
and notice `look` sitting on the quick row instead; at **248 rows with four
visible**, a gap reads as an omission. A column that claims to be the story's
real vocabulary must not have silent holes, or nothing in it can be trusted once
one is found.

## Related

[[SQ-1111]] built the column and deferred a leading-preposition column
(`look at …` cannot be composed at all, only typed) as "a UI feature, not a fix".
This report is evidence that deferral has a cost, and the two should be weighed
together. [[SQ-1126]] is a different filter on the same column.
