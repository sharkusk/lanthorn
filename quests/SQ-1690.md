Added scope from the SQ-1685 review (2026-10-02):
(1) hints::NO_HINT_MESSAGE tells the player to use `/hints <path>`, but no such command exists (parse("hints") is an error). This is pre-existing. Replace it with honest advice: put the hint file in the game's documents folder (and/or Shift-H download), and name the folder.
(2) There is no AskUser chooser. host::hints::open returns Ok(None) for both AskUser and None, so an ambiguous match (e.g. two identity-tied hint files, per SQ-1689) shows "no hint file". Add a real choice in the Hints tab: list the candidates and pick one, remembered in hints/index.toml as today's per-IFID association. Expose it through host::hints, for example an available() variant that returns the candidates.
