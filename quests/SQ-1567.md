--- note 2026-09-25T05:00:19Z ---


**Why.** A host that draws the frame's text with its own renderer
(`V6TextMode::RecordOnly`) needs to know where the prose box is, what colour the
canvas was flattened onto, where the input caret sits, and which kind of text
each run is. The composite computes all of these and throws them away:
- the story's clear box and its cell grid (`screen.rs:2970` `story_clear`;
  `cols`/`rows` at `screen.rs:3246-3248`);
- the flatten page (`finish_v6_raster_canvas`, `screen.rs:3342`);
- the caret, which is **painted into the canvas even under `RecordOnly`**
  (`render/v6_layout.rs:2943-2971`; the secondary-panel caret at `v6_layout.rs:2079`),
  so the art changes on every read and keystroke;
- `V6TextRun` (`v6_layout.rs:1676`), which cannot say whether a run is a
  grid cell, chrome, secondary prose, story prose, story-canvas text or the pager
  prompt.

**Change.**
- `V6Frame` (`screen.rs:2861`) gains:
  - `story: Option<V6StoryBox { x: u32, y: u32, w: u32, h: u32, cols: u16, rows: u16 }>`
    (canvas-native px, extension included; the box the prose callback was
    asked to fill);
  - `page: image::Rgba<u8>`;
  - `caret: Option<V6Caret { x: u32, y: u32, h: u32, panel: bool }>`.
- Under `RecordOnly` the caret is reported and **not painted**. `Rasterise` is
  unchanged.
- `V6TextRun` gains `source: V6RunSource { Chrome, GridCell, Panel, StoryProse, StoryCanvas, Pager }`,
  threaded through `GlyphSink::blit` from each call site (`build_chrome_canvas_into`,
  `draw_secondary_prose_into`, `draw_story_canvas_runs_into`,
  `draw_story_text_into`, the pager block at `screen.rs:3288`).

**Acceptance.** In `v6_headless_compose`:
- `story.cols/rows` equal the arguments the prose callback received (captured in
  the closure), and `story` lies inside the canvas.
- `page` equals the canvas pixel inside `story` under a prose callback that
  returns no lines.
- With `awaiting: true`, the `RecordOnly` canvas is identical to the one with
  `awaiting: false`, and `caret` is `Some`, after the last prose glyph. Under
  `Rasterise` the caret pixels are still drawn.
- Every run has a source. Zork Zero r393's status runs are `GridCell` or
  `Chrome` and the host's prose runs are `StoryProse`. Journey r83's menu runs
  are not `StoryProse`.
- The existing pixel-for-pixel cases stay green.
