--- note 2026-10-02T17:01:33Z ---

SQ-1676 layers config shared -> player -> per-game, but only through config::resolve(cli), which picks the player via data_roots::select_player_from_env (LANTHORN_PLAYER, process-global). resolve_config_layers is private, and the host-facing config::resolve_at(user_dir) (config.rs ~2781) takes no player. That is fine for one process per player (the TUI, ttyd), but a host that serves several players from ONE process (one thread per session) cannot set an environment variable per player, so it cannot get a named player's merged Config, nor the inherited baseline that makes write_config_at store only the player's overrides.

Ask: a public, environment-free entry point, e.g. pub fn resolve_at_for(user_dir: &Path, player: Option<&str>) -> Config (or make resolve_config_layers public with a stable signature), returning the same merged Config: config_file = the player's file, player/player_dir set, and inherited = the shared config, so write_config_at behaves exactly as for the TUI. Validate the name with validate_player_name and return a Result (or document that the caller must). The style side already takes a Config (load_style_for, style_write_path_for), so it should work once the Config is player-aware; please confirm with a test that a host-built player Config reads and writes the player's style.toml as overrides only.
Also worth a test: two players resolved in the same process do not affect each other (no shared global state).
