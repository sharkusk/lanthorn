--- note 2026-09-24T04:26:09Z ---

Citations are crates/app/src/ unless stated, as of ca723e44. Goal of this series: an embedding host that is not a terminal (a GUI, a network server, a mobile FFI binding) can boot and play a story through the `app` lib with the same rules the TUI uses, instead of re-implementing them. The TUI must run on the same code, so there is one copy of the rules.

Current state
- Clocks: `main::dispatch_due_game_clocks` (main.rs:1722); deadline arming in loop_tick.rs:578-611; `loop_tick::refresh_engine_input` (loop_tick.rs:520) sets char/event mode, line seeds and timer deadlines. Engine side is already lib: Z-machine `pending_timeout`/`run_timed_interrupt`/`abort_timed_input` (session.rs:1755/1764/1784); Glulx `timer_interval`/`deliver_timer`/`deliver_mouse`/`deliver_hyperlink`/`resize` (glulx_session.rs:2081/2090/2176/2216); v6 mouse `set_mouse` (engine.rs:999) then `submit_char(254)` (main.rs:3932).
- Screen dims: `loop_tick::poll_glulx_resize` (loop_tick.rs:73) and `poll_zvm_screen_dims` (loop_tick.rs:261) read PaneRects.
- Autosave per turn via `state.archive_worker` (turn.rs:~543); `lifecycle::exit_auto_save` (lifecycle.rs:28); `reset::reset_game` (reset.rs:16); `engine_helpers::restore_from_file` / `apply_archive_state` (engine_helpers.rs:217/318); `ingame_io::*` for game-initiated file prompts (`TurnResult.pending_io`, `pending_filename()` -> `resume_save`/`resume_restore`/`resume_filename`, engine.rs:918-935). `archive::SessionRecord::of(&AppState)` (archive.rs:544).

Change
- Lib host API, roughly: next deadline / fire what is due at `now`; current input kind and timeout; set screen dims in cells (the host decides them, no PaneRects); autosave now / exit save; reset with the existing options (clear map, delete auto data); answer a pending file prompt with a name or cancel; restore from a save file or archive. The TUI's event loop calls these instead of its private copies.

Acceptance
- TUI unchanged; existing suites pass.
- Headless tests: a Z-machine timed-input story and a Glulx timer story (skip when absent) fire their timers through the host API; exit-save then boot (part 1) resumes the same state; reset clears as the TUI's reset does; a game-initiated SAVE answered with a name writes a file a later RESTORE reads.
