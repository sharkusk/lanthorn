--- note 2026-09-26T02:40:03Z ---

Repro (rev fe4fc638): `Journey - The Quest Begins.adf`: Start, Proceed ×3, then Left (combat opens). The party column shows **"Tager"** in the lib's own Rasterise composite; hosts drawing runs see the same.

Run data: the lib's run list still holds `'er     '` at native (160,336), the tail of the earlier `'Esher     '`. The later `'Tag       '` run (x 136–216, same row) doesn't remove it.

Cause: `V6Windows::paint_run` (crates/zvm/src/screen.rs:1238). The erase predicate (~l.1260) is `bg_opaque || clearing || chars[i] != ' '`. Only a run that is **entirely** spaces clears letters (SQ-0498's Zork Zero case). A space **inside** a mixed run only erases blank cells (~l.1251, SQ-1054), deliberately, so Shogun's status padding doesn't eat a neighbouring label. Journey's menu writes each slot as one mixed run, "word + padding", over the old word, so the old tail survives.

Change: find the rule that clears Journey's overwritten slot without regressing Shogun. For example, trailing spaces of a mixed run erase the cells they cover up to the run's own end, as the game's own erase semantics do. Or a space erases when it overwrites ink from an earlier, *longer* run that started at or before this run's start (an overwrite of the same slot), not a neighbour's label. Base it on how the Z-machine screen model works (the game printed those spaces precisely to blank the old word).

Acceptance:
- Amiga Journey combat shows "Tag" with no trailing "er".
- The PC r83 menu is unchanged.
- Shogun's status padding still doesn't erase its labels (SQ-1054).
- Zork Zero's "Great Hall" (SQ-0498) is still clean.
- The existing pixel-for-pixel cases stay green.
