--- note 2026-10-03T02:57:08Z ---

SQ-1690's Hints tab start-up lives in hints_tab.rs (~155-200: ensure_started_in, show_program, the Choose phase), which depends on the TUI's layout state (AppState::hints_tab_visible, state.rs ~4147). A non-terminal host that shows hints in its own panel can call host::hints::{available, open, remember, no_hint_message} but must re-create the rules that glue them: a tie shows the chooser; a pick is remembered then opened; opening a hint program that is already running is a no-op; nothing found gives no_hint_message(documents).

Proposed: a host-level call independent of AppState layout, e.g.
  host::hints::start(story_path, HintStory, index, picked: Option<&Path>, user_dir, running: Option<&Path>, dict_words, cfg)
    -> Started(HintSession) | AlreadyRunning | Choose(Vec<PathBuf>) | NoHint(String) | Failed(HintOpenError)
and have hints_tab.rs use it too, so every host runs exactly the same rules. The chooser's intro line ("Several hint files could be this game's — pick one", draw_choose) could be a pub const alongside.
