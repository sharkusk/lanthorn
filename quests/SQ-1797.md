--- note 2026-10-18T16:06:19Z ---

crates/app/src/bug_report.rs: build() takes BugReportFacts, which mixes host-neutral facts (version, os, arch, game, map, commands typed, home scrub, timestamp, report_file/save_error, map JSON) with terminal-only ones (TERM*, tmux, ssh, GraphicsFacts, /dump-terminal, /dump-windows) and always prints the terminal/graphics/settings lines and a 'lanthorn <version>' header. Ask: (1) split the facts into a shared part and a host part: the host gives its product name for the header, its own labelled summary lines (label, value) and its own full-report sections (heading, lines); the TUI's terminal, graphics and settings lines become its host part, output unchanged. (2) The privacy rules apply to host-supplied lines too: home scrubbed to ~ everywhere, games named by file name only. (3) Gathering GameFacts and MapFacts (and the session's typed commands) from a running session is a public library function any host can call, not code inside the terminal's /report-bug handler in slash_dispatch.rs. (4) Keep the map-JSON and commands sections in the shared part. Tests: the existing bug_report tests still pass with the TUI's text unchanged; a new test builds a report with a non-terminal host part (no TERM lines, its own header and lines) and asserts the scrubbing applies to them.
