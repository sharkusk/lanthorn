--- note 2026-09-16T21:25:01Z ---

Closed 2026-09-16, no work needed. This was filed as prep before a future MS-DOS family-E `.PAK` picture decoder existed, warning against the naive per-entry `read_zip_entry` (reopens the archive + reparses the central directory each call) being used in a loop over ~60 pictures.

That decoder was since built (SQ-1477, `hints::saga_picture_files`'s zip branch). Verified directly in code: it goes through `for_each_zip_entry` (hints.rs), which opens the zip ONCE (`ZipArchive::new`) and streams every entry in a single pass — exactly the batching this quest asked for, just built as a single-pass visitor rather than a "read N named entries" function. Confirmed via call-site grep that `read_zip_entry` (the reopen-per-call function) is only used for genuine one-off lookups elsewhere (main.rs, story_url.rs), never in the picture-collection path. Nothing to implement.
