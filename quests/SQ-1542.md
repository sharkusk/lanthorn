--- note 2026-09-24T04:26:10Z ---

Citations are crates/app/src/ unless stated, as of ca723e44. Goal of this series: an embedding host that is not a terminal (a GUI, a network server, a mobile FFI binding) can boot and play a story through the `app` lib with the same rules the TUI uses, instead of re-implementing them. The TUI must run on the same code, so there is one copy of the rules.

Current state
- `cover::load_cover(path, game_dir) -> Option<DynamicImage>` (cover.rs:50): the Blorb `Fspc` frontispiece wins over `<game_dir>/cover.png`. `frontispiece_cover` (cover.rs:34) returns raw bytes but is private. `app::cover::decode` (cover.rs:26). The rest of cover.rs (CoverState, TileEncoder) is ratatui-image code. SQ-0985 notes no shelf story has an Fspc, so that branch lacks a real-media test.

Change
- A pub fn returning the cover's original encoded bytes and format (PNG/JPEG), with the same precedence as `load_cover`; `load_cover` built on it.

Acceptance
- Test with a cached cover.png (bytes returned unchanged) and with a synthetic Blorb carrying an Fspc chunk (the Fspc Pict's bytes returned, and they win over cover.png).
