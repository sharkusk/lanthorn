Current code (rev 5a31a353):
- crates/zvm/src/cpu/exec.rs:6596-6609 `Machine::post_restore_fixups((rows, cols))` (called at ~l.6547 and ~l.6653) re-applies the screen with `self.set_screen_dims(rows, cols)` for every version, v6 included. For v6 that rebuilds the pixel screen from the cell grid.
- With the Mac profile's 7×15 cell and a 91×26 grid, that gives 637×390 instead of the 640×400 the host declared with `set_v6_screen_px`, so after a restore the frame is 637×390 and the story window has 20 rows instead of 21 — not the screen the game was saved on or laid out for. Other profiles can shift similarly wherever the cell doesn't divide the screen exactly (SQ-1436).
- SQ-1156 fixed exactly this for `@restart` (exec.rs:~1000-1086: keep `v6_screen_px()`, re-declare the text metric, call `set_v6_screen_px`), but the restore path never got it. The TUI goes through the same lib path.

Change: in `post_restore_fixups`, for version 6, keep the pre-restore `v6_screen_px()` (and text metric) and re-apply them with `set_v6_screen_px(w, h)` — sharing the helper the restart path uses, so both stay one rule — instead of `set_screen_dims(rows, cols)`. Non-v6 behaviour unchanged.

Acceptance:
- Test: Mac Zork Zero (`Zork Zero Disk.image`, 7×15 cell, 640×400) — save, restore, then make a move and assert (CLAUDE.md's restore-must-perturb rule): screen stays 640×400 in header $22/$24, the story window keeps 21 rows, and the composed frame is 640×400.
- The same on Zork Zero r393 (8×16, exact) stays unchanged.
- The existing SQ-1156 restart tests still pass.
