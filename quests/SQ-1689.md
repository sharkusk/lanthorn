--- note 2026-10-03T00:22:22Z ---

Two different rules match a story to its hint file:
- The story list (picker.rs ~1982, SQ-0767) matches sidecars by identity first: hints::hint_matches_identity(name, ifid) || hint_matches_story(name, stem) || hint_matches_story(name, title). So the story info panel shows the right hint file for a story mounted from a disk image.
- In game, host::hints::available and host::hints::open go through hints::resolve_hint_source (hints.rs ~544), whose step 3 ranks sibling sidecars only by the story's file stem (pick_hint_candidate). A disk image is named for the box, so its stem names no game; with several hint sidecars in the folder the result is AskUser, and available() says None.

Specimen: stories/Zork I - The Great Underground Empire.adf (Zork I r88, IFID ZCODE-88-840726) with zork1izm.z5, bzorkizm.z5, zork3inv.z5 and others in the same folder. The info panel lists zork1izm.z5; in-game hints report no hint file (an embedding host's Hints tab, and presumably the TUI's hints panel).

Ask: give resolve_hint_source the same identity tier as the picker (hint_matches_identity with the story's IFID first, then the stem/title rules), so available/open, the story list and every host agree; keep AskUser for a genuinely ambiguous set. Consider sharing one matcher between picker.rs and resolve_hint_source so they cannot drift again. Test: the Zork I ADF specimen (skip when absent) resolves zork1izm.z5 in game; a folder with two Zork hint files and a .z5 named zork1.z5 still picks by stem.
