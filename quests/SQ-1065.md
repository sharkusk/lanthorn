Each of these was verified on BOTH sides. None of them mis-renders anything today; every one of them is a duplicate whose comment tells the next reader a guard exists where none does. Filed as one quest because no single item is worth its own, and because the pattern is the point. SQ-1059 (the third copy of "is there art here?") and SQ-1060 (the raster/cell over-art split) were filed separately because they are load-bearing.

1. **`display_name` — "The dock header and the exit card both call this."** They do not.
   `crates/app/src/render/room_info.rs:96` is the claim. `display_name` (`:97-105`) has exactly ONE caller in the tree: `crates/app/src/render/room_dock.rs:96`. The exit card names rooms through `dest_name` (`room_info.rs:33-42`), a second independent implementation of the same three-step rule (own-layer -> `labels.row_of(id)` -> `room.label()` -> `#id`), differing only by a `graph.layer_of(id) == layer` gate that is trivially true in `display_name`'s case. A third spelling of the fallback is inline in `card_detail`'s cross-layer branch (`room_info.rs:60-65`). They agree for every input today, and `the_exit_card_names_a_same_named_destination_by_its_matrix_number` (`room_info.rs:490`) pins the numbered case.

2. **`bitfont`'s header states the world SQ-0917 ended.**
   `crates/app/src/render/bitfont.rs:9-11` — "The cell is 8x16 at every production call site (`v6_layout`'s `FONT_W`/`FONT_H`)" — and again at `:189`. Contradicted 200 lines later by its own body, `bitfont.rs:397-404`: "The floor was `ch >= 16` and that was a latent assumption, not a rule (SQ-0917). It read '16 is the only cell any production call site asks for', which was true while every v6 machine shared one cell and stopped being true the moment the Macintosh declared its own 7x15." `v6_layout::FONT_W`/`FONT_H` (`v6_layout.rs:188,190`) are still bare `8`/`16`, documented THERE as a test convenience. The code is correct and fully cell-parametric; the header is how `py + 16` gets written next, which is SQ-1020's exact defect.

3. **`router.rs` cites a value the other file inverted seven hours later.**
   `crates/mapper/src/router.rs:76-77` — "This also settles a standing inconsistency: `oneway_entry_side` already routes NE arrivals to Right." It routes them to LEFT: `crates/mapper/src/route/mod.rs:546-549` is `if is_diagonal(dir) { return side_for(opposite(dir)) }`, its own doc at `:540` spells out "NE->Left, NW->Right, SE->Right, SW->Left", and `route/mod.rs:1673` asserts it. Settled by history, not argument: at `353211bd` (2026-07-15 00:47), when the router comment was written, `oneway_entry_side` had a literal `Direction::NE => Side::Right` arm and the sentence was true; `b1a9144c` (07:21 the same morning) replaced the function and did not touch the comment. The two functions are geometrically consistent (leave the origin's right, arrive on the destination's left) so nothing draws wrong — the cost is the next reader "restoring consistency" against an inverted citation.

4. **`zvm`: "Same spelling as `ZWindow::prose_new_line`, one file away" (SQ-1030) is not the same spelling.**
   `crates/zvm/src/cpu/exec.rs:4375-4377` is `w.y_cursor = w.y_cursor.saturating_add(fh);` — unbounded saturating accumulation. `crates/zvm/src/screen.rs:608-627` is a bounded `self.y_cursor += cell.h` inside `if self.y_cursor as u32 + 2 * fh - 1 <= self.y_size as u32`, with an `else` that scrolls the shadow. Different operator, different guard, different failure mode. No defect (the guard makes overflow unreachable on the prose side); the sentence invites someone to make one match the other.

5. **`bitfont::source_col`'s doc describes a branch the code does not take.**
   `crates/app/src/render/bitfont.rs:336-338` — "at `cw > 8` it spreads the master over the wider cell the same way" — against the body at `:340-346`, where the endpoint map is gated `(2..8).contains(&cw)` and `cw > 8` takes `dx * 8 / cw` instead. The outcome coincides (for any `cw > 8`, `(cw-1)*8/cw` floors to 7, so the rightmost column survives and the tiling guarantee holds), so nothing is visibly wrong.

6. **`gvm`: a doc comment split in half by an inserted test.**
   `crates/gvm/src/exec.rs:8118-8119` carries the first half of a sentence belonging to a different test, breaking off mid-clause ("...but leaves the") into an unrelated SQ-0595 paragraph. The continuation sits at `crates/gvm/src/exec.rs:8220-8223`, correctly attached to `restore_quetzal_reverts_vm_state_but_preserves_live_glk_and_iosys` (`:8225`). Both halves currently read as claims about the wrong test.
