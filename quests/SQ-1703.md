  Glulx graphical stories designed for a fixed Windows Glk window size never line up when the Glk screen is measured in host text cells

--- note 2026-10-03T06:32:40Z ---

Some Glulx graphical stories ship a Windows Glk per-game config (<story>.cfg, Key=value lines; documented in Windows Glulxe's help, config.htm). Examples: Narcolepsy (narco.cfg: WindowWidth=800, WindowHeight=600, WindowMask=3) and Photopia 2.01 (photo201.cfg: 640x480, WindowMask=39). Keys: WindowWidth/WindowHeight (client size in pixels of a single full-size Glk window), WindowBorders, WindowFrame, WindowMask (a Blorb Pict used as a window-shape mask, white = transparent), FontName, FixedFontName, FontSize, FullScreen.

These stories lay out their Glk windows for exactly that pixel size:
- Photopia: fixed graphics splits Above 58px, Below 79px, Left 14px, Right 14px around a 612x343 text area at (14,58); each chapter draws a 612x343 card into a 100% graphics split Above the text area, then opens a new text buffer at 100% Above (the old one left at 0px).
- Narcolepsy: root text buffer (left half), a text buffer Right 50% with graphics margins Left 20% / Right 25% / Above 10% / Below 30% around it, leaving the story text in 240x378 at (480,60) inside the mask's bubble; a fixed 80px graphics window Above the root holds a 400x80 title.

Today the Glk screen is the host's pane in cells: fixed graphics splits round up to whole cells (79px becomes 4 rows of a 22.9px cell, i.e. ~92px), proportional splits round down to cells, canvases are cells x char_px, and the window tree reports cells (gvm glk.rs relayout / layout_window ~2556ff, window_pixel_size ~2782; glulx_session AppGlk). A 100% split leaves a leftover cell instead of 0px. So the frame art never lines up, at any size.

Asks, for any embedding host (terminal or not):
1. Discover and parse the .cfg beside the story, as garglk_ini.rs does for garglk.ini (decide whether a `.cfg.txt` spelling is accepted). Expose the design size, the borders flag (folded into the per-game borderless preference) and the mask Pict id on the booted story / AppState.
2. A host-selectable pixel-exact Glk screen: the host states the screen in pixels (the design size) and a fractional text cell in those pixels; splits divide in pixels exactly as a GUI Glk library does (no cell rounding; a 100% split leaves 0px); text windows report floor(window pixels / cell) characters; graphics canvases are their exact pixel size; screen_model / WinTree carry each window's pixel rectangle; changing the cell relayouts and redraws (as set_char_px does).
3. Decide the TUI's own behaviour with a design size (e.g. letterbox to its aspect in cells) so other hosts follow it.

Tests: photo201 and narco stories, skipped when absent. At 640x480 Photopia's text area is exactly 612x343 and its frame windows 640x58, 640x79, 14x343, 14x343; at 800x600 Narcolepsy's story text window is 240x378 at (480,60).
