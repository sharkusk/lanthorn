Titles: Zork Zero r366 Amiga, Shogun r322, Shogun r295 Amiga; type hint, then y. The topic menu is a Grid in the story slot, so hybrid_chrome_layout returns Some and the plan is the ring.
- What the terminal Hybrid does: build_hybrid_frame_with tiles the flanks down the whole pane via tiled_flanks / flank_tiled_source (crates/app/src/render/screen.rs ~5149-5164), whatever the story slot's node type. At a 99x50 pane with a 20x44 px cell the band log shows 'band 14x50@(0,0) [Art, tiled] · source 91x711 native px' for Zork Zero, 11x50 from 71x711 for Shogun.
- What a host gets: compose_v6_frame given want = RasterFrame { canvas_h: 704, .. } declines to extend: compose_v6_frame_into's 'ext block has 'if !matches!(&story.node, WinNode::Buffer(_)) { break 'ext None; }' (just after the story_window_is_a_canvas check, ~line 3400, comment mentions scopa and Amiga Shogun's InvisiClues). So the art stays the game's 400 rows.
- V6HybridChromeLayout publishes no tiled flanks (only flank_borders and divider_exts), so a host can't draw them itself.
Needs either (a) a V6FrameInputs opt-in, or a Hybrid-plan condition, letting the composite run extend_raster_flanks under a story-slot Grid as the ring does; or (b) the ring's tiled flank bands published on V6HybridChromeLayout (dest rect in cells plus the native source rect).
Repro: on either title, hint, y, compose Hybrid at 99x50 with a 20x44 px cell: V6Frame.frame.canvas_h == 400 while the terminal's flank band is 50 rows.
Optional: V6HybridChromeLayout::text_rows() (screen.rs ~5934) could include a story-slot Grid's rows; a host that draws that Grid in cells otherwise has to add them to hybrid_text_rows itself, or fill_reverse_row_gaps (v6_layout.rs ~1307) floods a selected reverse row with explicit colours across the flanks (Zork Zero Amiga's selection).
